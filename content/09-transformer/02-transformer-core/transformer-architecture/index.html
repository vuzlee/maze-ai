Transformer architecture

Attention is just one layer. This lesson assembles the rest: tokenization, embedding, position at the input;

Residual, LayerNorm, FFN inside each block; and how a hidden state becomes text at the output —

With a lab to count parameters and memory yourself.

01

Mental model

A Transformer is the same block repeated N times, sandwiched between one end that turns text into vectors and one end that turns vectors back into text.

Attention is just one layer. What turns it into a model is everything wrapped around it: tokenization, embedding, position, residual, FFN, and the output.

  • Attention is a weighted sum over a set — on its own it knows no order, no text, and cannot produce a single token.
  • Most of a Transformer's parameters live in the FFN, not in attention. Most of the long-context cost is the other way round.

02

Tokenization

A model does not read text, it reads numbers. The tokenizer cuts text into pieces that exist in its vocabulary (usually with the BPE algorithm) and looks up their ids.

from transformers import AutoTokenizer
tok = AutoTokenizer.from_pretrained("gpt2")

tok.encode("unbelievable")      # [403, 6667, 12472]  → "un" + "bel" + "ievable"
tok.encode("the")               # [1169]              → 1 token
tok.encode(" the")              # [262]  DIFFERENT id: the space is part of the token
tok.encode("Con mèo ngồi")  # 8 tokens — Vietnamese costs far more

Practical consequences

  • Cost is per token, not per word. Accented Vietnamese often costs 2–3× as many tokens as English for the same content, because accented combinations are rare in the tokenizer's training data.
  • Spaces belong to tokens. "the" and " the" are two different ids. A classic source of bugs when stitching prompts together by hand.
  • The model never sees letters. So it miscounts characters, botches anagrams, and is poor at multi-digit arithmetic — numbers get cut into pieces that do not follow place value.

A common question

Why can't an LLM count the r's in "strawberry"? Because its input is three tokens, not ten characters. It has never seen the individual letters.
03

Embedding

A lookup table: each id maps to a d-dimensional vector, learned during training.

W_emb: (V, d) = (50257, 768)          # GPT-2 small
ids:   [1044, 8712, 3390]             # (T,)
X = W_emb[ids]                        # (T, d) = (3, 768)

There is no matrix multiplication here — just picking rows by index. This table takes a very large share of a small model's parameters:

W_emb — a single lookup table38.6 M
all 12 blocks combined85 M

Weight tying

Many models reuse W_emb itself (transposed) as the projection to logits. It saves V × d parameters, and there is an intuitive reason: the same meaning space serves both reading in and writing out.
04

Positional encoding

Attention is a weighted sum over a set —

It has no notion of order. Without anything added, "cat chases mouse" and "mouse chases cat" give identical hidden states, just with rows permuted.

# proof in your head: attention(X) with X's rows permuted
# = attention(X) with the output rows permuted  → permutation equivariant

Ways to add position

Sinusoidal — original Transformeradds a multi-frequency sin/cos vector to the embedding · no parameters, but weak in practice
Learned absolute — GPT-2, BERTa learned (T_max, d) table · simple, but the maximum length is fixed; exceed it and it breaks
RoPE — LLaMA, Qwen, most new modelsrotates each pair of Q and K dimensions by an angle proportional to position · encodes relative distance, easier to extend context

Why RoPE wins: when both Q at position m and K at position n are rotated, their dot product depends only on the difference m − n.

The model learns "3 words apart" rather than "this word is in slot 412", so it breaks less on longer sentences.

05

Residual and LayerNorm

Residual — a shortcut for the gradient

Every sub-block is written as x = x + f(x).

So the derivative always has a component equal to 1 flowing straight back, instead of being multiplied through dozens of layers.

This is a prerequisite for training models 32, 80 or 100 layers deep.

Another view, very handy in interviews: the residual stream is a tape of information running the length of the model.

Each block reads from that tape, computes something, then adds it back onto the tape.

No block overwrites the information of the blocks before it.

LayerNorm — keeping magnitudes stable

y = (x - mean(x)) / sqrt(var(x) + eps) * gamma + beta
# mean and var over the feature dimension, ONE token at a time
BatchNorm

Normalizes over the whole batch, one feature at a time.

Small batches give noisy statistics; sequences of different lengths get messy because of padding.

Train and inference are two different modes — you must keep running-average statistics.

LayerNorm

Normalizes per token, across all features.

Independent of batch size, indifferent to sequence length.

Train and inference are identical — the most important reason when deploying.

Pre-LN and Post-LN

The original paper put LayerNorm after the sub-block: x = LN(x + f(x)). Models today almost all put it before: x = x + f(LN(x)). Pre-LN keeps the residual path completely clean, so training is more stable and does not need an overly cautious learning-rate warmup.
06

FFN — where most parameters live

FFN(x) = W_2 @ activation(W_1 @ x + b_1) + b_2

W_1: (d, 4d) = (768, 3072)     # expands 4×
W_2: (4d, d) = (3072, 768)     # compresses back

Applied independently to each position — tokens do not look at each other here. All information exchange between tokens is already done in the attention layer.

A quick count for one GPT-2 small block:

Attention — W_q, W_k, W_v, W_o2.36 M · 33%
FFN — W_1, W_24.72 M · 67%

Two thirds of the parameters sit in the FFN. Interpretability research suggests this is where factual knowledge is stored —

It acts much like a key–value memory, while attention handles routing information.

Why expand 4×

There is no theorem — it is an empirical constant from the original paper, kept because it works well. Newer models using SwiGLU usually take about 8/3 · d to keep the total parameter count equivalent, since SwiGLU needs three matrices instead of two.
07

A complete block

class Block(nn.Module):
    def forward(self, x):
        x = x + self.attn(self.ln1(x))    # mix across tokens
        x = x + self.ffn(self.ln2(x))     # process each token
        return x

All of GPT is just this layer repeated: 12 times in GPT-2 small, 32 in LLaMA-7B, 80 in 70B models.

The shape going in and coming out is always identical — that is why they can be stacked at will.

08

From hidden state to text

H        (T, d)      = (3, 768)      # after the last block
H        = final_ln(H)
logits   = H @ W_out                 # (3, 50257)
logits   = logits[-1]                # only the last position matters when generating
probs    = softmax(logits / T)       # T = temperature

Generation knobs

temperature — divides logits before softmax<1 sharpens the distribution, >1 flattens it · at 0.1 it repeats itself, at 1.8 it drifts off-topic and invents names
top-k — keeps the k most likely tokensa fixed k does not suit every context: too many where the model is sure, too few where it is unsure
top-p — keeps the smallest set whose total probability exceeds pthe set size adapts to confidence, so it is usually better than top-k

Order of application

temperature first, then top-k / top-p filtering, then sampling. Changing the order gives very different results — a high temperature applied after filtering can no longer widen the candidate set.

Why only the last row: in training we use all T rows of logits to compute the loss at every position.

During generation, the first T−1 rows predict tokens we already know, so they are dropped.

10

Encoder, Decoder, or both

Encoder-only — BERTbidirectional attention, no mask · learns by guessing masked tokens · suits classification, extraction, text embedding
Decoder-only — GPT, LLaMAone-directional attention with a causal mask · learns by predicting the next token · suits text generation, chat, any task that can be cast as generation
Encoder–Decoder — T5, machine translation modelsbidirectional encoder, causal decoder, plus cross-attention · suits translation and summarization, where source and target are distinct

How cross-attention differs from self-attention: Q comes from the decoder, while K and V come from the encoder's output.

That is, "the sentence being written" asks questions of "the source sentence". The formula does not change by a single symbol —

Only the source of the three inputs changes.

Why decoder-only won

One architecture, one training objective, works on any raw text, and every task can be cast as text generation. Simpler means easier to scale — and at large scale, simple usually wins.
11

Common mistakes when coding it yourself

These architectural bugs are hard to spot because the model still converges, just worse than it should.

Forgetting positional encoding

The model still reaches a decent loss because word frequencies alone let it guess a lot. Symptom: shuffle the word order and the output barely changes.

Placing LayerNorm after the residual block

Post-LN needs careful warmup to avoid diverging in deep networks. Pre-LN is much more stable and is today's default.

Not tying embedding and output weights

Misses a large block of reusable parameters, and often makes perplexity worse in small models.
