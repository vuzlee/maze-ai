Self-attention

A weighted sum, but the weights are decided by the data itself —

That is the whole idea. This lesson goes from Q/K/V to scaled dot-product, explains why you must divide by √d_k, separates the two kinds of mask.

And shows how the KV cache trades memory for speed.

01

Mental model

Each token asks every other token one question, then brings back the content of the tokens whose answers match best.

A GPT model does exactly one thing: take a sequence of tokens and return a probability distribution over the next token. Everything below is detail of that one job.

"The cat sat" → [1044, 8712, 3390]tokenization — text into a list of numbers, (T,)
X — (3, 768)embedding lookup, plus position information
× 12 blocks: x = x + attn(ln1(x)) then x = x + ffn(ln2(x))shape unchanged through every block — still (3, 768)
logits — (3, 50257)final LayerNorm, then multiply by W_out
p(next token) — (50257,)take the last row, softmax

Remember one sentence

Attention mixes information across tokens. The FFN processes each token on its own. The whole model is just those two jobs repeated N times, plus the residual shortcut so gradients can flow.
02

Why attention is needed

Before the Transformer, sequences were handled by RNNs/LSTMs: read tokens in order, compress the entire past into one state vector. Three problems:

  • Bottleneck. An entire long sentence has to fit into one fixed-size vector.
  • Long gradient path. Getting from token 1 to token 500 takes 500 matrix multiplications, and the gradient shrinks along the way.
  • No parallelism during training. Step t must finish before step t+1 can be computed.

Attention fixes all three with one idea: every token connects directly to every other token.

The path between any two tokens is always exactly one step long, and every position can be computed at once.

The cost

Connecting everything to everything means cost scales with T² instead of T. An RNN handles long sentences far more cheaply — that is why long context is still expensive today. Details in section 09.
03

What Q, K, V are

From the same token vector x, we project through three learned matrices to get three different roles:

RoleLiteral meaningExample
Q queryWhat information I needThe token "it" asks: which earlier noun could be my referent?
K keyWhich kind of question I can answerThe token "cat" reports: I am a singular noun
V valueThe content I carry if chosenThe semantic information of "cat" to mix into "it"
x:   (T, d)      = (3, 768)
W_q: (d, d_k)    = (768, 64)      # for one head
W_k: (d, d_k)    = (768, 64)
W_v: (d, d_v)    = (768, 64)

Q = x @ W_q      # (3, 64)
K = x @ W_k      # (3, 64)
V = x @ W_v      # (3, 64)

Why split into three instead of using x directly

With the product x·xᵀ, every token is always most similar to itself, and the relation is always symmetric: A attends to B exactly as much as B attends to A. But language is not symmetric — a pronoun needs its noun more than the noun needs the pronoun. Separating W_q and W_k lets the attention matrix be asymmetric. Adding a separate W_v makes the "search criterion" and the "content carried" two independent things.
04

Scaled dot-product attention

The whole formula fits in four lines:

scores = Q · KT / √dk(T, T) — how well every pair matches + maskhides the future, see section 07
weights = softmax(scores)row-wise — each row sums to 1
out = weights · V(T, d_v) — weighted sum of V

Each step in words

  1. Q @ K.T — for each token i, take the dot product of its query with the key of every token j. A large product means "what I need" matches "what you have".
  2. Divide by sqrt(d_k) — keeps the magnitude of the scores stable. The full reason is in the next section.
  3. softmax along each row — turns scores into attention shares that sum to 1. This is where the axis most often gets mixed up when you code it yourself.
  4. weights @ V — token i receives a weighted average of the tokens' values. Paying 70% attention to token 2 means taking 70% of its content.
import torch, torch.nn.functional as F

def attention(Q, K, V, mask=None):
    d_k = Q.size(-1)
    scores = Q @ K.transpose(-2, -1) / d_k ** 0.5   # (T, T)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float("-inf"))
    w = F.softmax(scores, dim=-1)
    return w @ V, w
05

Why divide by √d_k

This is a classic interview question, and the answer "to normalize" is taken as not really understanding it.

Assume the components of q and k are independent, with mean 0 and variance 1. The dot product of two d_k-dimensional vectors is a sum of d_k independent terms:

q·k = Σ qi · kii = 1..dk
E[q·k] = 0
Var[q·k] = dkvariances add up
std[q·k] = √dkwith dk = 64, scores swing around ±8

The larger the scores, the sharper the softmax. When one value clearly dominates, the distribution approaches one-hot, and the softmax derivative goes to 0 —

The gradient cannot flow back, and the model stops learning from the very start.

Dividing by sqrt(d_k) brings the variance back to 1, whatever d_k you choose. That way you can increase the dimension without re-tuning the initialization.

In one sentence

The dot product has variance proportional to d_k. Without dividing, a large d_k saturates softmax into one-hot and the gradient vanishes. Dividing by sqrt(d_k) keeps the variance at 1, so softmax stays in the region with good gradients.

The lab in the next section lets you toggle this division yourself and watch the distribution collapse into one-hot.

07

Masking — two kinds, do not confuse them

Causal mask (hides the future)

During training, we feed the whole sentence at once and make the model predict the next token at every position in parallel.

If token 3 could see token 4, it would simply copy the answer.

Masking the upper triangle with -inf prevents that.

Use -inf, not 0, because softmax(-inf) = 0 exactly. Set them to 0 and exp(0) = 1, so masked cells still get real weight.

Why the mask is what makes parallel training possible

Without a mask you would need T passes, one per position. With the mask, a single pass yields T predictions, each based only on its own past. That is why a Transformer trains many times faster than an RNN, even though generation is still sequential.

Padding mask (hides padding)

Packing sentences of different lengths into one batch means padding them to equal length. Padding cells carry no meaning and must be masked, or the model learns garbage statistics from them.

Trap

The two masks must be combined, not substituted for each other. Forgetting the padding mask usually causes no runtime error — quality just drops for no obvious reason, and the bug is very hard to trace.
08

Multi-head attention

One head can only learn one kind of relation. With h heads, we run h independent attentions on smaller subspaces, then concatenate them.

x — (T, 768)d = 768, h = 12 → each head gets d_k = 768 / 12 = 64 dimensions
Q, K, V — (12, T, 64)project through W_q, W_k, W_v (768, 768) then split into 12 groups of 64 — 12 heads run in parallel
concat — (T, 768)attention per head, then concatenate along the last dimension
out — (T, 768)multiply by W_o (768, 768) to mix information across heads

Total cost is unchanged. Split 768 dimensions over 12 heads, 64 each — they still add up to 768. Multi-head is nearly free compared with one big head.

What each head learns

Analysis of trained models shows that heads specialize:

A head that tracks the previous token, a head that links a pronoun to its noun, a head that matches opening and closing brackets, a head that follows the main verb.

Nobody programmed this — it emerges from the data.

Why W_o is needed

After concat, the heads only sit side by side; they have not talked to each other yet. W_o is the mixing layer that lets the model combine the conclusions of many heads into one unified representation. Drop W_o and multi-head is just several disconnected parallel channels.
09

Complexity — why long context is expensive

StepTimeMemory
Project to Q, K, VO(T · d²)O(T · d)
Q @ K.TO(T² · d)O(T²) ← attention matrix
weights @ VO(T² · d)O(T · d)
FFNO(T · d²)O(T · d)

Total: O(T²·d + T·d²). Which term is larger depends on how T compares with d:

  • T = 512, d = 768 — the FFN and projections take most of the time. Attention is not yet the bottleneck.
  • T = 32000, d = 768 — the T² term dominates. Double the context and attention cost quadruples.

A common misstatement

Many people say "attention is always the bottleneck". Not true at short context. The correct answer: cost has two terms, T²d and Td², and which dominates depends on the ratio of T to d.

What FlashAttention solves

It does not reduce the computational complexity — it is still O(T²·d).

What it removes is writing the T×T matrix out to main memory:

It computes block by block right inside the GPU's fast on-chip memory, so memory drops from O(T²) to O(T) and speed rises several times because less data moves.

This question separates those who read carefully from those who only know the name.

10

KV cache — what sets serving cost

Generation is sequential: emit one token at a time, append it to the input, and run again.

Recomputing from scratch at every step would make 1000 tokens cost about a thousand times more work than needed.

The key observation: with a causal mask, the K and V of earlier tokens never change. So store them.

No cache

Each step recomputes Q, K, V for all t tokens: O(t · d²) per step, O(N² · d²) for the whole sequence.

With cache

Compute only for the new token: O(d²) per step, plus O(t · d) for it to look at the t stored keys.

Two phases with completely different behavior

PrefillDecode
What it doesProcesses the whole prompt in one passGenerates one token at a time
BottleneckCompute — the GPU runs at full capacityMemory bandwidth — all weights must be re-read for every token
Metric to watchTime to first tokenTime between tokens
How to speed upChunking, parallel processingBatch many requests, quantization, fewer KV heads

Why decode is memory-bound rather than compute-bound

Generating one token requires reading all model weights from VRAM, but performs only a tiny amount of computation on them. The GPU sits idle waiting for data. That is exactly why batching is so effective: once you have paid to read the weights, serving 32 requests at once costs almost nothing extra.

11

MHA, MQA, GQA

All three differ in only one way: how many heads share one K/V set. The number of query heads always stays the same.

TypeK/V headsKV cacheQuality
MHASame as query heads (32)Baseline, 100%Highest
MQAExactly 1, shared by all heads1/32 — 32× smallerClear drop on hard tasks
GQAA group, e.g. 81/4Close to MHA

GQA is the balance point, so almost every open model today uses it.

Queries still have 32 separate views, but every four adjacent heads share the same set of keys and values.

Tying back to the previous section

This is exactly the n_kv_heads variable in the cache formula. Going from 32 down to 8 cuts the cache fourfold, so the same GPU can serve four times as many concurrent requests. That is the whole motivation for GQA — not to make the model smarter.
12

Common mistakes when coding it yourself

All five of these bugs leave the model still running with loss still falling — so they survive for a long time.

Softmax on the wrong axis

softmax(scores, dim=0) instead of dim=-1. The model still runs and the loss still creeps down, but it never gets good. Check that w.sum(-1) gives all ones.

Masking with 0 instead of -inf

exp(0)=1, so masked cells still get weight. The model peeks at the future, loss is artificially low in training, then it generates nonsense in real use.

Forgetting to divide by sqrt(d_k)

With a small d_k it still learns, so this bug survives for a long time. With a large d_k the loss is flat from the very first step.

Wrong reshape order when splitting heads

It must be view(T, h, d_k).transpose(1,2). Do it the other way and dimensions get mixed across heads — no shape error, just a model that cannot learn.

KV cache not trimmed by length

The cache keeps growing across conversation turns until VRAM runs out. This only shows up in long chat sessions, so it often slips through testing.
