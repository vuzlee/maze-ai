PEFT — LoRA & QLoRA

Fully fine-tuning a 7B model needs 60–80 GB of VRAM; LoRA brings that down to a single consumer GPU.

This lesson explains why learning a low-rank matrix is enough, and how to choose r and alpha.

Then how QLoRA compresses the base weights to 4-bit and still trains.

01

Why not fine-tune all the weights

Fully fine-tuning a 7B model needs about 60–80 GB of VRAM just for weights, gradients and optimizer state.

full fine-tune 7B~80 GB
weights alone14 GB

Every parameter keeps four copies: weight, gradient, and Adam's two moments — this is where memory goes, not the forward pass.On top of that, each task produces a full copy of the model: ten tasks means ten times 14 GB to store and load.

02

LoRA — Low-Rank Adaptation

The update to a weight matrix usually has low rank, so it can be written as the product of two thin matrices.

h = W_0·xoriginal path, unchanged + (α/r) · B·A·xadded LoRA branch

α/r is a scaling factor that lets you change r without re-tuning the learning rate.

After training you can merge B·A straight into W_0 — inference then costs nothing extra over the base model.

Why B is initialized to zero and A randomly

Because ΔW = B·A = 0 at the start, the model begins identical to the base model — no shock at the first step. If both were random, ΔW would be random noise added to well-trained weights, wrecking quality immediately. If both were zero, both gradients would stay zero forever — nothing would be learned. One zero, one random is the only correct choice.

An under-mentioned benefit: the base weights never change.

So you can train many adapters for many tasks, then swap them on the same base model sitting in VRAM.

One GPU serves ten customers with ten separate adapters — something full fine-tuning cannot do.

03

Lab: parameters and memory

The number that matters most is the memory column: fully fine-tuning a 7B model needs about 100+ GB, so it takes several GPUs.

QLoRA brings it down to a single 24GB GPU — that is exactly why it changed the game.

QLoRA

The base model is compressed to 4-bit and frozen; only the LoRA adapter stays in bf16 and is trained.

The real trade-off of QLoRA

It trades time for memory: every forward pass must dequantize the 4-bit weights to bf16 to compute, so it is about 30% slower than LoRA. Worth it when VRAM is your limit — which is the situation of almost everyone without a GPU cluster. If you have enough VRAM, LoRA is usually the better choice.

06

Common mistakes

LoRA is easy to run, but these four points decide whether it learns anything.

LoRA applied only to q and v

That follows the original paper, but later experiments show applying it to all linear layers is clearly better.

Setting r too small for a hard task

r = 4 is enough to change writing style, not enough to learn a new domain. If the loss plateaus early, raise r before adding epochs.

Changing r but forgetting alpha

The effective strength is alpha / r. Raising r while keeping alpha fixed silently weakens the adapter.

Merging the adapter, then quantizing

With QLoRA the base weights are already 4-bit. Merging and then compressing again loses most of what was just learned.
