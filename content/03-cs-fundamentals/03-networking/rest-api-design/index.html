REST API design

An HTTP API is a contract between two programs.

  • the URL names a resource, the method says what to do
  • the status code says what happened: 2xx ok, 4xx client error, 5xx server error
  • big lists come back in pages
01

Mental model

One resource, four methods — read, create, replace, delete.

02

Resources and methods

Nouns go in the URL; the verb is the HTTP method.

2.1URLs

Plural nouns, nested for belongs-to.

2.2Methods

Five methods cover almost every action.

  • Only idempotent calls are safe to retry blindly — see TCP & HTTP.
03

Status codes

The first digit says who is responsible.

3.12xx success

It worked.

3.23xx redirect

Look somewhere else, or use your cache.

3.34xx client error

The request is wrong — fix it before retrying.

  • 401 = who are you? · 403 = I know you, but no.

3.45xx server error

The server failed — retrying later may work.

  • Never return 200 with an error in the body — clients and proxies will think it worked.
04

Pagination

Return a big list one page at a time.

4.1Offset

Skip N rows, take the next page.

4.2Cursor

Continue after the last item seen.

  • Use cursor for large or fast-changing lists (feeds, logs).
05

Versioning

Keep old clients working while the API changes.
