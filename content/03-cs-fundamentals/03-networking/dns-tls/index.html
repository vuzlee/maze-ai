DNS & TLS

Find the server, then make the line private.

  • DNS turns example.com into an IP address
  • answers are cached for a time called the TTL
  • TLS checks the certificate, agrees a key, then encrypts
01

Mental model

DNS finds where; TLS makes the line private.

02

DNS

A phone book for the internet: name in, IP address out.

2.1Cache

Ask the nearest cache first — usually it already knows.

2.2Full lookup

No cache: root → TLD → authoritative.

  • DNS runs over UDP port 53 — one small packet each way.

2.3Records

A name can point to an address, another name, or a mail server.

2.4TTL

Each answer is cached for TTL seconds.

  • Changing a DNS record takes effect only when old TTLs run out.
  • Low TTL = faster changes, more lookups.
03

TLS

Prove the server's identity, agree a key, encrypt everything.

3.1TLS 1.2 handshake

Two round trips before any data.

3.2TLS 1.3 handshake

One round trip — the key share goes in the first message.

  • Reconnecting to a known server can send data at once (0-RTT).

3.3Certificate

Proves the server owns the name.

3.4Encryption

Agree a shared key once, then encrypt every message with it.

  • Asymmetric crypto only for the key agreement; symmetric (AES) for the data — much faster.
  • HTTPS = HTTP inside TLS.
