CS fundamentals · operating system

Virtual memory & paging

Each process thinks it has the whole memory to itself.

  • the MMU turns virtual addresses into physical ones
  • memory is split into pages (usually 4 KB)
  • RAM is given only when a page is first touched
01

Mental model

Programs use virtual addresses; the MMU maps them to real RAM.

  • Two processes can both use address 0x2010 — each has its own map.
  • A process cannot reach memory that is not in its map: isolation.
02

Page table

One row per page: page number → frame number.

  • Page size is usually 4 KB, so the last 3 hex digits are the offset.
  • Each process has its own page table.
03

TLB

A tiny cache of recent page-table rows inside the CPU.

3.1TLB hit

The page is in the TLB — no table walk.

3.2TLB miss

Walk the page table, then remember the answer.

  • Most accesses hit, so translation is almost free.
04

Page fault

The page has no frame in RAM yet — the kernel steps in.

4.1Minor fault

First touch: the kernel hands out a free frame. Fast.

  • That is why malloc of a big buffer costs nothing until you use it (lazy allocation).

4.2Major fault

The page was moved to disk (swap) and must be read back. Slow.

  • Constant major faults = thrashing: the machine crawls while the CPU sits idle.
05

Locality

Same work, different order — very different speed.

5.1Row order

Read cells next to each other: one miss loads several.

  • Measured on a 1500 × 1500 matrix: row order 43 ms.

5.2Column order

Jump through memory: every read misses.

  • Same matrix, column order: 108 ms — 2.5× slower.
  • Why NumPy is fast: data sits in one block — see Profiling & performance.
