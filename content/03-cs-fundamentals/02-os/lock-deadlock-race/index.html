CS fundamentals · operating system

Lock, deadlock & race condition

Threads share memory, so they must take turns.

  • x = x + 1 is three steps, and a thread can be paused between them
  • a lock lets one thread in at a time
  • deadlock: each thread waits for a lock the other holds
01

Race condition

x = x + 1 is read, add, write — another thread can slip in between.

  • The code that must not be interleaved is the critical section.
  • The result depends on timing, so the bug appears only sometimes.
02

Locks

Let only a limited number of threads into the critical section.

2.1Mutex

One thread at a time; the others wait.

with lock: x = x + 1

  • Keep the locked part small — waiting threads do nothing.

2.2Semaphore

Up to n threads at once.

pool = Semaphore(2)

  • Use it to cap a resource: database connections, parallel requests.
03

Deadlock

Two threads each hold a lock the other one needs.

3.1How it happens

Opposite lock order makes a circle of waits.

  • Four conditions together: mutual exclusion, hold and wait, no preemption, circular wait.
  • Break any one and deadlock cannot happen.

3.2Lock ordering

Everyone takes locks in the same order.

  • Another fix: acquire(timeout=…), then release and retry.
