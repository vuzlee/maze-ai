Operating system overview

One machine, many programs.

  • the kernel stands between programs and hardware
  • it shares CPU time and memory
  • shared data needs synchronisation
01

Mental model

Programs never touch hardware directly — they ask the kernel.

open() · read() · write() · fork() — all system calls

  • User mode: programs run with limited rights.
  • Kernel mode: only the kernel talks to CPU, memory and devices.
02

What the OS shares

Three resources many programs want at once.

2.1CPU time

A scheduler gives each process a short turn.

  • Switching turns costs time: a context switch saves and loads registers.
  • See Process, thread & GIL.

2.2Memory

Each process sees its own addresses.

  • A process cannot read another one's memory — that is isolation.
  • See Virtual memory & paging.

2.3Synchronisation

Threads that share data must take turns on it.

  • See Lock, deadlock & race condition.
