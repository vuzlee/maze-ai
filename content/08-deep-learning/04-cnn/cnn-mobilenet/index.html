MobileNet

From the convolution operation to architectures that run on microcontrollers.

This lesson pins down the shape and cost formulas, shows with numbers why depthwise separable convolution is 8–9× cheaper, why MobileNetV2 is called an inverted residual,.

And why the last layer of the block has no ReLU.

01

Mental model

Instead of connecting every pixel to every neuron, a CNN slides a small kernel over the whole image — the same set of weights reused at every position.

This whole line of architectures is a sequence of cutting multiplications while keeping representational power.

Fully connectedevery neuron sees the whole image → far too many parameters
Convolutionweight sharing + local connectivity · a small filter slides over the image → few parameters, catches edges
Deep CNNstack many layers · receptive field grows → edges → shapes → concepts
Depthwise separablesplit the operation in two · per-channel filtering + channel mixing → 8–9× cheaper
MobileNetV2invert the residual block · expand → filter → compress, skip at the narrow ends → saves memory

Remember one sentence

Every advance in this group is a form of cutting multiplications while keeping representational power. Understand what each step trades off and you understand the whole line of architectures — and that is exactly what you get asked when you say you work on models for edge devices.
02

Why not use fully connected for images

fully connected · 1000 neurons224 × 224 × 3 × 1000 = 150,528,000 params
convolution 3×3 · 3 → 64 channels3 × 3 × 3 × 64 = 1,728 params

same 224×224×3 image87,000× fewer

Convolution achieves this through two assumptions about image structure:

  • Local connectivity. A pixel relates to its neighbors, not directly to a pixel in the opposite corner. So each neuron only needs to look at a small region.
  • Weight sharing. A vertical edge detector that is useful in the top-left corner is just as useful in the bottom-right. So use the same filter at every position instead of learning one per position.

The second consequence of weight sharing

It gives the model translation invariance: a cat in the left or right corner is detected by the same filter. Fully connected has to relearn from scratch for each position, so it needs far more data to reach the same level of generalization. This is the clearest example of building knowledge of the problem into the architecture instead of leaving the model to learn it.

Why it is almost always 3×3

Two stacked 3×3 layers have a 5×5 receptive field, but cost only 2 × 9 = 18 weights per channel versus 25 for one 5×5 layer. Three 3×3 layers give a 7×7 receptive field with 27 weights versus 49. Cheaper, and you also get two extra nonlinearities in between, so the representation is stronger. This was VGG's main contribution, and it is why 5×5 and 7×7 almost disappeared from later architectures except in the first layer.

Receptive field

Why receptive field matters in practice

If the object to recognize is larger than the last layer's receptive field, the model cannot see it whole — it only sees pieces. That is why object detection architectures combine multiple resolution levels (feature pyramid), and it is the answer to "why does my model recognize small objects well but large ones poorly".

07

Convolution 1×1 — small but important

A 1×1 filter sees only one pixel — sounds pointless, but it sees all the channels of that pixel.

UseHow
Change the channel countCompress 256 channels to 64 before an expensive 3×3 conv — this is the ResNet bottleneck idea
Mix information across channelsThe second half of depthwise separable convolution
Cheap extra nonlinearityAdd a ReLU after it, costs very little compute

The cost of 1×1 relative to 3×3 on the same channel count is 1/9.

That is why the ResNet bottleneck block — 1×1 compress, 3×3 process, 1×1 expand —

Is much cheaper than two 3×3 layers on the full channel count, despite having three layers instead of two.

08

Residual connection

y = xshortcut + f(x)residual to learn
∂y/∂x = 1gradient flows straight back, multiplied by nothing + ∂f/∂x

As explained in the Backpropagation step by step lesson: the 1 term creates a path through which the gradient flows without being multiplied by anything.

So even if ∂f/∂x shrinks to 0, the gradient still reaches the first layers.

That is what makes it possible to train networks hundreds of layers deep.

A second view, useful in interviews: a residual block only has to learn the residual —

Instead of learning the target function H(x), it learns H(x) − x.

If the optimal mapping is close to the identity, learning the residual is much easier, since the weights only need to be pushed toward 0.

In other words, adding layers never makes the model worse —

In the worst case it learns the zero function and the block becomes a straight pass-through.

The shape condition

The sum x + f(x) requires both sides to have the same shape. When the block downsamples or changes the channel count, you must insert a projection on the shortcut — usually a 1×1 conv with the same stride. This implementation detail is often missed when writing a ResNet by hand.
09

Depthwise separable convolution

The idea: a standard convolution does two jobs at once — spatial filtering and channel mixing. Separating them is far cheaper.

Standard convolution — one op

k×k×Cin×Cout does both jobs at once. Params: k² · Cin · Cout

Depthwise separable — two steps

1 · depthwise one k×k filter per channel, no channel mixing — k² · Cin
2 · pointwise 1×1 conv mixes channels — Cin · Cout
Total: k² · Cin + Cin · Cout

savings ratiostandard / separable = 1 / ( 1/Cout + 1/k² )simplified from the two formulas above

With k = 3, Cout = 128: 1 / (0.0078 + 0.1111) = 8.4×. When Cout is large, the 1/Cout term vanishes, so the ratio approaches k² = 9.

The number to remember

With a 3×3 kernel, depthwise separable is about 8–9× cheaper in both parameters and compute, in exchange for about 1 percentage point of accuracy. The trade is so good that MobileNet, EfficientNet and nearly every mobile architecture use it. Stating the number and how to derive it is the complete answer.

But cheap in FLOPs does not mean fast

Depthwise convolution has a very low ratio of compute per byte read from memory — it reads a lot of data and does little work. On a GPU, where memory bandwidth is the bottleneck, a depthwise layer may be no faster than a standard conv despite 9× fewer FLOPs. It wins clearly on mobile CPUs and dedicated accelerators. This detail separates people who have actually measured from people who have only read the paper.
10

MobileNetV2 — inverted residual and linear bottleneck

Why it is called "inverted": the ResNet block compresses in the middle and skips between the wide ends. MobileNetV2 does the opposite — expands in the middle and skips between the narrow ends.

Why inverting helps

  • Memory savings. The tensor kept for the residual add is the one at the narrow end, much smaller. On a device with only a few hundred KB of SRAM, this is the difference between running and not running.
  • Depthwise needs many channels to be effective. It does not mix channels, so with few channels its representational power is very limited. Expanding before filtering gives it room to work.

Linear bottleneck — why the last layer drops ReLU

ReLU sets every negative value to 0 — so it destroys information, and how much damage that does depends on the dimensionality.

High-dimensional space

Losing some is not too bad — the information survives in other dimensions.

Low-dimensional space · the narrow part of the bottleneck

Losing half the dimensions loses most of the information, with nowhere to make it up.

so the 1×1 compress layer at the end of the block is linear, no ReLUthis is the "linear bottleneck" in the paper's title

Four MobileNet questions you should be able to answer

Why is it suited to edge devices? Depthwise separable cuts compute 8–9×; inverted residual keeps intermediate tensors small, saving peak memory.

What is depthwise separable? Splitting spatial filtering and channel mixing into two steps, cutting cost to about 1/k².

What is an inverted residual? Expand the channels so depthwise has room to work, then compress back, and skip between the narrow ends instead of the wide ends.

Why does the last layer have no ReLU? Because ReLU destroys information, and in a low-dimensional space that damage cannot be recovered.

Quantization for edge devices

Quantizing float32 → int8: 4× smaller, and integer math is much faster on mobile CPUs and accelerators.

real valueoriginal float32 ≈ scalequantization step × ( integer − zero_point )int8 stored in the model
MethodMechanismQuality loss
Post-training, dynamicQuantize weights; activation scale computed at runtimeSmall; no data needed
Post-training, staticUse a calibration dataset to fix activation scalesSmaller; faster than dynamic
QAT — training with simulated quantizationSimulates rounding during training so the model adaptsSmallest; but requires retraining

A detail worth mentioning: per-channel scale

With one scale for the whole weight tensor, channels with small amplitude get rounded to near 0 and lose all their information. A separate scale for each output channel fixes that at almost zero cost, and it is the default in every tool today. This is a good answer to "why did my model's score drop sharply after quantization".

MobileNet has one specific caveat: depthwise convolution is very sensitive to quantization.

Each channel has only k² weights, so amplitudes vary a lot between channels.

This is a case where QAT or per-channel scale is practically mandatory.

12

On-device inference optimization

Folding BatchNorm into convolution

At inference, BatchNorm is a linear operation with fixed parameters — so it can be folded straight into the conv right before it.

y = γ · (x − μ) / √(σ² + ε) + βBatchNorm at inference
W′new conv weights = γ · W / √(σ² + ε)
b′new conv bias = β − γ · μ / √(σ² + ε)

Drops a whole layer, fewer memory reads. The result is identical, nothing lost.

This is the first optimization every deployment tool performs, and it is free.

Mentioning it when asked about inference optimization is a clear plus.

TechniqueEffectCost
Fold BatchNormDrops a layer, fewer memory accessesNone
int8 quantization4× smaller, 2–3× fasterAbout 1 point of accuracy lost
Weight pruningRemove small weightsOnly faster with structured (block) pruning; scattered pruning cannot be exploited by hardware
Knowledge distillationA small model learns from a large oneRequires retraining and an existing large model
Lower input resolutionCost drops quadraticallyLoses the ability to recognize small details

Measure, do not guess

On edge devices, the bottleneck is usually memory bandwidth, not compute. So a model with fewer FLOPs can be slower if it reads more data. Always measure real latency on the actual target device, and say so when discussing optimization — it shows you have worked with real hardware.

14

Common mistakes

Looking only at FLOPs when optimizing speed

Depthwise has few FLOPs but is heavy on memory bandwidth. Measure real latency on the target device.

Forgetting the projection on the shortcut

When the block changes channel count or size, the residual add fails on shape. You need a 1×1 conv on the shortcut.

Adding ReLU to the final compress layer

Breaks the linear bottleneck. Information lost in low-dimensional space cannot be recovered.

Using one scale for the whole tensor when quantizing

Small-amplitude channels get rounded to 0. Use per-channel scale.

Keeping bias in a conv right before BatchNorm

Redundant — BatchNorm already has β. Set bias=False.

Poor on large objects without checking receptive field

If the object is larger than the receptive field, the model cannot see it whole.
