Normalization — BatchNorm & LayerNorm

A norm layer re-centres a group of activations to mean 0 and spread 1, then lets two learned numbers set the scale back — BatchNorm and LayerNorm differ only in which group.

01

Mental model

Measure a group's mean and spread, shift and squeeze it to 0 and 1, then rescale with γ, β.

x̂normalised = x − μ√(σ2 + ε)μ, σ² of the group , y = γ x̂ + βlearned scale and shift
  • Deep stacks drift: each layer's activations shrink or blow up (section 06). The norm re-pins them every layer.
  • γ starts at 1, β at 0, so the network can undo the norm if that helps; ε only guards against dividing by 0.
02

BatchNorm vs LayerNorm

Same formula, same tensor: the only difference is the axis the statistics run along.

2.1BatchNorm

One μ, σ per feature, computed down the column, across the samples of the batch.

  • Each sample's output depends on the other samples in the batch — the root of section 03.
  • The default in CNNs: statistics per channel, over batch × height × width. A bias right before it is redundant (bias=False).

2.2LayerNorm

One μ, σ per token, computed along the row, across its own features.

  • No other row is used, so training and inference compute exactly the same thing.
  • RMSNorm drops the mean: y = γ x / √(mean(x2) + ε); slightly cheaper, same quality — used in LLaMA and most new LLMs.
03

BatchNorm and its batch

BatchNorm's statistics are estimates from one batch: they need a stand-in at test time and enough samples to be trusted.

3.1Train vs inference

Training uses the batch's own stats and updates a running average; eval() freezes it.

μrunrunning mean ← (1 − m) μrunold estimate + m μBthis batch · m = 0.1
  • Forgetting model.eval() keeps using batch stats: one sample's prediction then depends on its neighbours.
  • The running variance is updated the same way; both are buffers, not learned parameters.

3.2Batch size

A batch of 2 gives a noisy μ and σ; the noise goes straight into every normalised value.

  • A little noise regularises; below about 8 samples per GPU it hurts. Fixes: GroupNorm, SyncBatchNorm, or LayerNorm.
04

Why Transformers use LayerNorm

Sentences have different lengths and generation runs one token at a time: only a per-token norm survives both.

  • BatchNorm would average padding into the statistics and break at batch 1; LayerNorm never looks outside the token.
05

Where to put the norm

In a residual block the norm either sits on the residual line or inside the branch — the gradient feels the difference.

5.1Post-LN

Add first, then normalise: every block's LN cuts the residual line.

xl+1block output = LN(xl + f(xl))norm on the sum
  • The original Transformer and BERT. Deep stacks need a careful learning-rate warmup or they diverge.

5.2Pre-LN

Normalise the branch input, then add: the residual line stays bare from loss to input.

xl+1block output = xluntouched + f(LN(xl))norm inside the branch
  • GPT-2 onwards, LLaMA, almost every modern LLM; one extra LN after the last block. Why a bare path helps is the residual argument in Backpropagation.
06

Diagnosing with statistics

Print the std of the activations per layer: shrinking to 0 or growing without bound is the symptom a norm fixes.

  • Log it with forward hooks on a few batches; a healthy net keeps a similar order of magnitude in every layer.
  • Setting the right magnitude at step 0 is Weight initialization; the norm keeps it right during training.
