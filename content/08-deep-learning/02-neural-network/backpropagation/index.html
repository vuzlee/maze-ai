Backpropagation

Not magic — just the chain rule applied in a clever order.

This lesson walks through a 2–2–1 network with real numbers.

Then it explains why the gradient of softmax plus cross-entropy collapses to p − y, and why gradients shrink across many layers.

And why the initialization formula contains √(1/n).

01

Mental model

The forward pass records the path taken; one reverse multiplication on the way back yields the gradient of every parameter.

Forward — x → z₁ → a₁ → z₂ → a₂ → Lcompute and store every intermediate value
Backward — L → ∂L/∂a₂ → ∂L/∂z₂ → ∂L/∂W₂ → … → ∂L/∂W₁go backwards, each step multiplies in one local derivative
Update — W ← W − η · ∂L/∂Wsubtract a small step along the gradient

Remember one sentence

Every node in the network needs to know only two things: its own local derivative, and the gradient received from behind. Multiply the two and pass the result upstream. No node needs to know anything about the whole network — that is why backprop works for every architecture.

Why not compute gradients numerically

∂L/∂wi ≈ [ L(w + ε·ei) − L(w) ] / εfinite difference — a separate forward pass per parameter

To get the gradient of all parameters, the backward pass costs only about 2 forward passes.That is the whole value of backprop: the cost does not grow with the parameter count.

That is the whole value of backprop: the cost does not grow with the parameter count.

It achieves this by reusing intermediate results instead of recomputing them.

Numerical gradients are still useful in one place

To verify hand-written backprop code. Compute the gradient both ways on a few random parameters and compare — the relative difference should be below about 1e-7. This is gradient checking, and naming it is a good answer to "how do you know your backprop code is correct".
03

Chain rule

One path — multiply

If L = f(g(h(x))) then ∂L/∂x = ∂L/∂f · ∂f/∂g · ∂g/∂h · ∂h/∂x.

Many paths — add

If a variable is used in several places, ∂L/∂x is the sum of the gradients along each path.

The sum rule for a variable used several times is important and often overlooked:

∂L/∂a₁ = contribution via neuron 1a₁ is used here + contribution via neuron 2and also here
∂L/∂a₁ = W₂T · ∂L/∂z₂the matrix form packs that sum into one multiplication

This is the number-one source of bugs when implementing backprop

Forgetting to sum gradients when a tensor is used several times — for example with a residual connection, or weights shared across layers. The gradient ends up partial; the model still learns, but slowly and never well. In PyTorch this is exactly why loss.backward() accumulates into .grad, and why you must call optimizer.zero_grad() every step.
04

Computation graph

Practical consequence for memory

Inference needs only the weights. Training needs the weights, the activations of every layer, the gradients, and the optimizer state — with Adam that is two more copies the size of the weights. That is why a large batch size runs out of VRAM, and why gradient checkpointing exists: drop some stored activations and recompute them when needed, trading time for memory.

Two things worth noticing in the table

Sigmoid and tanh reuse their own output to compute the gradient; z is not needed.

That is why frameworks store a rather than z for these layers —

It saves memory.

ReLU is an on/off valve. It does not shrink the gradient like sigmoid; it either lets it through or blocks it entirely.

This is the main reason ReLU solves the vanishing-gradient problem.

07

Softmax + cross-entropy: why the gradient is p − y

pi = e^zi / Σ e^zjsoftmax · L = −Σ yi log picross-entropy
∂pi/∂zj = pi(δij − pj)computed alone: a messy Jacobian matrix
∂L/∂zi = pi − yicombine the two steps and everything cancels

The same result as the sigmoid + log loss pair in binary classification, and the identity + MSE pair in regression.

This is no coincidence — it is a property of canonical link functions in the exponential family.

TaskOutput functionLoss functionGradient w.r.t. z
RegressionnoneMSEŷ − y
Binary classificationsigmoidlog lossp − y
Multi-class classificationsoftmaxcross-entropyp − y

Two practical consequences

1. Frameworks always fuse the two steps. PyTorch's CrossEntropyLoss takes logits, not probabilities, and applies softmax internally.

Because fused, no Jacobian is needed, and overflow is avoided when computing e^z for large z.

2. Applying softmax yourself and feeding it into CrossEntropyLoss is a bug. Softmax gets applied twice, gradients are wrong and the model learns very poorly — an extremely common silent bug.

08

Matrix form and shapes

forwardX : (N, D)batch of N samples, D input dims
forwardW : (D, H)H output dims
forwardZ = X @ W + b(N, H)
backwarddW = X.T @ dZ(D, H) — matches W's shape
backwarddX = dZ @ W.T(N, D) — matches X's shape
backwarddb = dZ.sum(0)(H,) — summed over the batch axis

A trick that works everywhere

No need to memorize formulas. The gradient of a tensor always has the same shape as that tensor. Given that constraint, there is exactly one way to arrange the matrix multiplication to get the right shape — so you can derive the formula on the spot. Stating this trick in an interview when asked to write a layer's backward is the safest approach.
Why must db be summed over the batch axis?

The same b is used for all N samples, so it takes part in N different computation paths. By the sum rule in section 03, the gradient is the sum of contributions from every path. For the same reason, the gradient of weights shared across time steps in an RNN must also be accumulated over every step.

09

Vanishing and exploding gradients

The gradient through L layers is a product of L factors — the last layer's derivative times the previous one's, all the way back to the first layer:

each factor ≈ 0.9 · over 50 layers0.005 — vanishes
each factor ≈ 1.01.0 — preserved
each factor ≈ 1.1 · over 50 layers117 — explodes

The problem is the product itself: deviate from 1 just slightly and, over many layers, the deviation grows exponentially.

CauseFix
Sigmoid and tanh saturate — sigmoid's derivative peaks at only 0.25Use ReLU: derivative is 0 or 1, no shrinking
Weights initialized too small or too largeXavier or He — see section 10
Network too deep, gradient path too longResidual connection: x + f(x) gives the gradient a path with derivative 1
Activation magnitude drifts across layersBatchNorm / LayerNorm
Sudden gradient explosionGradient clipping: clip the norm to a threshold — almost mandatory for RNNs and Transformers

Why residual connections work so well

With y = x + f(x), ∂y/∂x = 1 + ∂f/∂x. That 1 term creates a path for the gradient to flow back without being multiplied by anything. So even if ∂f/∂x vanishes to 0, the gradient still passes through intact. That is why such a simple idea makes it possible to train networks hundreds of layers deep.
10

Weight initialization — why √(1/n)

Var(z) = n · Var(w) · Var(x)one neuron with n inputs, w and x independent, zero mean
Var(z) = Var(x)want signal magnitude unchanged across layers ⇒ std(w) = √(1/n)
MethodVarianceUse with
Xavier / Glorot2 / (n_in + n_out)tanh, sigmoid — balances both forward and backward passes
He / Kaiming2 / n_inReLU — the factor 2 compensates for what ReLU cuts off
All zeros—Never — every neuron in a layer stays identical forever

Why zero initialization makes the network useless

If all weights in a layer are equal, every neuron in that layer computes the same value, receives the same gradient, and is updated identically. They stay identical forever — the whole layer acts as a single neuron. Random initialization exists to break that symmetry. Biases, however, are perfectly fine at 0, because the weights already break the symmetry.

Why He has a factor of 2: ReLU sets half the inputs to 0, so the output variance is only about half.

Multiplying the initialization variance by 2 compensates for exactly that loss, keeping the signal magnitude from shrinking across layers.

How normalization helps gradients

y = γlearned scale · (x − μ) / √(σ2 + ε)normalize to mean 0, variance 1 + βlearned shift
BatchNorm
μ, σ computed along the BATCH axis, per feature
LayerNorm
μ, σ computed along the FEATURE axis, per sample
EffectMechanism
Keeps activation magnitude stableStops it drifting across layers, so gradients neither vanish nor explode
Allows a larger learning rateThe loss surface becomes smoother, so large steps stay safe
Less dependence on initializationA wrong scale at initialization is renormalized right at the first layer
Mild regularization effectBatchNorm only — noise from per-batch statistics acts like random noise

Why Transformers use LayerNorm

Three reasons, ordered by importance in deployment: LayerNorm does not depend on batch size, so serving single requests is still correct; it is unaffected by padding tokens when sequences in a batch have different lengths; and it behaves identically in training and inference, whereas BatchNorm must keep running-average statistics and so has two different modes.
12

Model not learning — an ordered checklist

1 · Memorize 8 samplesturn off regularization, train until loss is near 0. If it will not go down, it is a code bug, not the data or learning rate
2 · Initial loss ≈ ln(C)with 10 classes it should be about 2.30. Far off: wrong label format, or double softmax
3 · Sweep the learning ratelog scale from 1e-5 to 1e-1. NaN means too large, flat means too small
4 · Gradient normnear 0 is vanishing, huge is exploding, exactly 0 means the computation graph is broken
5 · zero_grad()without it, gradients accumulate across steps
6 · Normalize inputsunnormalized inputs are a very common reason a network fails to converge
7 · Labelsoff by one, shuffled relative to inputs, or a class missing entirely
8 · model.eval()forget it and dropout and BatchNorm misbehave at evaluation

do firstin this order, each step rules out a whole class of causesdo later

Step 1 matters more than the other seven

If the model cannot memorize 8 samples, then tuning the learning rate, switching optimizers or adding data is all pointless — there is a bug somewhere in the code. This test takes two minutes and rules out a whole class of causes. Bringing it up when asked "your model does not converge, how do you debug it" is the answer of someone who has done the real work.
13

Formula summary

Two-layer network, binary classification:

FORWARD
    z₁ = W₁x + b₁
    a₁ = σ(z₁)          or    relu(z₁)
    z₂ = W₂a₁ + b₂
    a₂ = σ(z₂)
    L  = -[y log a₂ + (1-y) log(1-a₂)]

BACKWARD
    dz₂ = a₂ - y                        ← neat thanks to sigmoid + log loss
    dW₂ = dz₂ · a₁ᵀ
    db₂ = dz₂
    da₁ = W₂ᵀ · dz₂
    dz₁ = da₁ ⊙ a₁(1-a₁)                ← ⊙ is element-wise multiply
                                          or da₁ ⊙ (z₁ > 0) with ReLU
    dW₁ = dz₁ · xᵀ
    db₁ = dz₁

UPDATE
    W ← W - η · dW

Being able to rewrite this table from scratch without looking it up is enough preparation for a whiteboard question on backprop.

14

Common mistakes

Forgetting zero_grad()

Gradients accumulate across steps. The loss fluctuates erratically and does not converge.

Applying softmax before CrossEntropyLoss

Double softmax. The model still runs, learns very poorly, and no error is raised.

Initializing weights to 0

Every neuron in the layer stays identical forever. The whole layer becomes one neuron.

Not summing gradients for a tensor used several times

The gradient is partial. Happens when hand-implementing residuals or shared weights.

Not normalizing inputs

The loss surface becomes a narrow valley; every learning rate is wrong.

Forgetting model.eval()

Dropout stays on and BatchNorm uses batch statistics during evaluation.
