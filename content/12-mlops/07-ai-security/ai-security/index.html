AI security

Ordered by lifecycle: runtime first, then training, then access.

Skeleton lesson — outline settled, content not yet written.

01

The problem

The model cannot separate "instructions" from "data" — both go into the same token sequence.

02

Prompt injection

Injecting fake instructions into data the model reads: documents, web pages, tool results.

03

Jailbreak

Steering the model into breaking its own system prompt — differs from injection in what it targets.

04

Data poisoning

Injecting poisoned data during training or fine-tuning, and backdoors that fire only on a trigger.

05

Model extraction

Probing a model through its API to reconstruct its behavior or weights — probing cost vs training cost.

06

Access control

Who may call the model, who may see logs with sensitive data, and rate limits as a layer of defense.

07

Defense

Clearly separate input from instructions, guardrails, output checks — there is no absolute block.
