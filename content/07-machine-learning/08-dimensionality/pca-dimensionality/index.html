PCA & dimensionality reduction

A hundred columns, most of them saying the same thing over and over. PCA rotates the axes toward the direction the data spreads most and then drops the directions with almost nothing in them — keeping 95% of the information in 12 new columns.

01

Mental model

The lesson is the five parts below. Every later section redraws this map and highlights the box being studied.

02

The problem it solves

High dimensionality is not just slow. It breaks exactly the models that rely on distance, and makes every model easier to overfit.

Distance loses meaningthe nearest and farthest points draw close together → KNN, k-means, kernel SVM all get worse
Data gets sparsethe volume of the space grows exponentially, the number of samples does not — each region is left with only a few points
More parametersmore degrees of freedom on the same amount of data → high variance, easy to overfit
Columns repeat informationmulticollinearity makes regression coefficients swing wildly and lose their interpretability
Cannot be plottedif you cannot see the data, you cannot spot its structure or the errors in it

What makes compression possible: real data is almost always low-rank.

Columns are tangled up with each other, so the real information lives in a subspace far smaller than the number of columns.

  • Height and weight are two columns but almost one axis — knowing one lets you guess the other.
  • PCA finds exactly those axes: the first is the direction the data spreads most, the next is perpendicular to it and spreads second most.
  • It is not the only way: feature selection, autoencoders, t-SNE, UMAP. PCA is the cheapest and easiest to understand, so start here.
03

Mechanism

The whole algorithm is: compute the covariance matrix, take its eigenvectors, sort by eigenvalue.

Why the direction of largest variance?

A direction along which the data barely changes does not help tell points apart — dropping it loses the least information.

The math background is in Linear algebra.

  • The components are perpendicular to each other, so the new columns are uncorrelated — the most thorough cure for multicollinearity.
  • Libraries do not compute the eigen of the covariance matrix; they run SVD directly on the mean-centered data.
  • The transform is linear and invertible, so PCA is also used for compression and denoising.
04

Loss function

PCA minimizes reconstruction error — and that number is exactly equal to the variance it throws away.

  • "Keep the most variance" and "reconstruct with the least error" are the same thing. Compress to k dimensions and expand back, and the squared error equals exactly the sum of the eigenvalues from k + 1 onward. Measured on 600 samples: at k = 3, reconstruction error 0.302 and variance dropped 0.302 — matching to three digits. Because the loss function is quadratic like that, PCA solves in one shot via eigenvalues, without iterating like k-means.
  • Where the eigenvalues break is the true dimensionality. In the same table: 10.181 → 4.690 → 1.254 then straight down to 0.071. The data was generated from exactly 3 directions, the rest is measurement noise — and the table says so without knowing in advance.
  • The price: variance depends on the unit of measurement. Take the same data, multiply the most useless column by 100, and PC1 jumps from 62.0% to 97.5% with a weight of 1.000 on that column — it takes over the first component and pushes all the real information down. Not standardizing first ruins the result silently, with no warning at all.
05

Choosing the number of components

There is no right number. There are three ways to choose, and each answers a different question.

scree plot: variance of each componentwhere the line drops sharply then flattens is a candidate

Variance threshold — PCA(n_components=0.95)keep enough components to reach 90–95% cumulative variance · the default to use
Scree plot — cut where the line breaks and flattenswhen you want to understand the data's structure, not just compress
Measure with the downstream modelput n_components into cross-validation along with the other hyperparameters · most reliable
2 or 3 — just enough to draw on screenonly for looking; here t-SNE or UMAP usually give an easier-to-read picture
  • You must standardize the scales first. PCA looks for the direction of largest variance, and variance depends on the unit of measurement.
  • A salary column in VND has billions of times more variance than an age column, so the first component nearly coincides with salary — because the unit is big, not because it matters.
  • Use StandardScaler first, unless every column already shares the same unit (images, signal spectra).
06

PCA is not feature selection

It does not drop any column. It creates new columns, each a combination of all the old ones — and that is where the real loss is.

Feature selection

Keep a subset of the original columns: age, number of purchases, order value.

Kept columns keep their names and meaning.

When collecting new data you only need to measure those columns.

PCA

Creates new columns: PC1 = 0.3·age − 0.7·salary + 0.2·orders + …

No column has a nameable meaning anymore.

You still have to measure every original column to compute the PCs — no savings at collection time.

  • So PCA destroys interpretability. A task that must answer "which variable matters" cannot pay that price.
  • It does not look at labels: the direction of largest variance does not necessarily separate the classes. If you need labels, use LDA.
  • It only captures linear relationships. Data lying on a curved surface is the territory of kernel PCA, autoencoders, UMAP.
  • PCA learns the mean, the standard deviation and the principal directions from the data, so it is a training step.
  • Calling fit on the full data before the train/test split is data leakage: information from the test set has leaked into the principal directions.
  • Put it inside a Pipeline and that cannot happen — see Train, validation & test.
07

Pros and cons

Every strength of PCA comes from keeping only a few directions of largest variance. Every weakness comes from exactly the same place.

AspectProsCons
DimensionalityDrops most columns while keeping nearly all the variance—
ComputeOne decomposition, no loop with parameters to tuneCost grows with the square of the original dimension
New featuresAxes are perpendicular, so multicollinearity is goneNo column has a nameable meaning anymore
Data collection—You still have to measure every original column to compute the components
Relationships—Only captures linear relationships
LabelsNeeds no labels — works even on unlabeled dataSo the direction of largest variance is not necessarily the one that separates classes
Preparation—Standardizing the scales is mandatory
  • Choose PCA when you need to reduce dimensions before another model, remove multicollinearity, or plot high-dimensional data on two axes to look at it.
  • If you must keep column names to explain decisions, this is the wrong choice — feature selection is the right tool.
  • PCA cannot unfold non-linear relationships; then use t-SNE or UMAP to look, but only to look.
08

Common mistakes

PCA always runs and always returns a result — even when it is the wrong step.

Not standardizing the scales

The first component only reflects the column with the biggest unit. The most common and the most silent mistake.

Fitting before the train/test split

Data leakage. Test scores look falsely good, then collapse in production.

Using it on tabular data and feeding a tree model

Tree ensembles need no dimensionality reduction and handle useless columns very well. PCA only costs interpretability and gains nothing.

Expecting it to raise accuracy

PCA throws away information. It helps when what is dropped is mostly noise — nothing guarantees that.

Feeding one-hot variables in directly

The variance of a binary column is not the same kind as that of a continuous one. Consider MCA, or apply PCA only to the numeric part.

Interpreting PC1 as a concept

Calling PC1 "wealth" and believing it. It is just a linear combination, with no guarantee of matching any concept.
