Machine learning · Tree models

Random forest

In goes a data table, out comes a forest of voting trees. Three things to remember:

  • each tree learns its own sample
  • each split looks at only a few columns
  • the whole forest votes for one answer
01

Mental model

Random forest is many different decision trees voting to produce one prediction. It exists because a single tree tends to memorize the data.

  • See also Decision tree and Gradient boosting.
02

Bootstrap

Draw rows from the original table at random, with replacement. One sample per tree.

  • Rows not drawn are called out-of-bag. About 37% of the rows when n is large.
03

Random features

At each split, a tree may only consider a few columns.

  • The number of columns considered is max_features: √p for classification, p3 for regression.
  • Drop this step and you have bagging. Only with both steps is it a random forest.
04

Aggregating

The customer goes through each tree. The most votes wins.

  • Regression takes the mean instead of votes.
  • Bagging = bootstrap + aggregating. Compared with boosting: Tree models overview.
05

Loss function

Random forest has no loss function of its own. Each tree still grows by Gini or variance. The forest just averages.

variance of the forest = ρσ2does not fall with more trees + (1 − ρ)σ2Bfalls with more trees
B
number of trees
σ2
variance of a single tree
ρ
how alike the trees are
  • Averaging can only lower variance, not bias (see Bias–variance). So trees in a forest are left to grow fully.
  • The forest has no shared objective like XGBoost.
06

OOB score

Each row is scored only by the trees that never saw it. No separate test set needed.

OOB score = rows predicted righttotal rowscounting only out-of-bag votes
  • Close to cross-validation, at no extra training cost.
07

Feature importance

The forest scores each column. MDI sums the impurity drop over every split. Permutation shuffles a column and measures the score drop.

  • Columns with many distinct values have many thresholds to try, so MDI easily scores them high.
  • Quick check: add a column of random numbers. Any column ranked below it is noise.
08

Pros and cons

It trades interpretability for stability. One tree can be read by eye. Five hundred trees cannot.

AspectGainLose
OverfittingAveraging many trees lowers varianceEach tree's bias stays the same
Number of treesAdding trees does not overfitOnce at the floor ρσ2, more trees are useless
Input dataNo scaling needed, few hyperparametersNo extrapolation: outside the trained range it returns a constant
Reading the modelOOB score and importance built inCannot be read like a single tree. MDI is biased, and columns with duplicated information split their score
OOB scoreNo separate test set neededWrong when rows are not independent, like time series
SpeedTrees are independent, so they train in parallelPrediction must query every tree
AccuracyStable, needs little tuningOn tabular data it usually loses to boosting
  • Choose random forest when you need a strong baseline, little tuning, medium-sized tabular data.
  • Choose boosting when you need the highest accuracy and are willing to tune a lot.
  • Choose a single tree when you need to read every rule.
  • The hyperparameter most worth searching is max_features, scored by OOB score.
  • Full comparison: Tree models overview.
