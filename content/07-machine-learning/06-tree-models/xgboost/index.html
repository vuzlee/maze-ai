Machine learning · Tree models

XGBoost

Many small trees in sequence, each learning the residual of the trees before it. Three things to remember:

  • each later tree learns the residual of the one before
  • split where Gain is largest, scored by one formula
  • the final prediction adds up the trees, it does not average
01

Mental model

XGBoost is many small trees in sequence: each tree learns the residual the earlier trees still get wrong, then everything is added up.

  • There is one formula for scoring a tree. Regression and classification just fill different numbers into it.
  • Running example throughout: 6 customers A–F, y is the extra spending (in thousands). Classification uses the buy-or-not label.
  • How adding up works in general: Gradient boosting. The faster version: LightGBM.
02

General formula

Obj = loss + two penalties. The loss is the error of each row. Obj adds up the loss over the whole tree plus the penalties, and is what the tree must minimize.

Obj ≈ Σj [ Gjwj + ½ Hjw2j ]block 1: loss of the whole tree, approximated + γTblock 2: penalty on leaf count + ½ λ Σj w2jblock 3: penalty on leaf size

Solving the formula for each leaf gives three things:

w* = − GH + λOutput value: the leaf value
Similarity Score = G2H + λscore of one leaf
Gain = Sim(left) + Sim(right) − Sim(root)how many points the two new leaves beat the old one by
  • g and h are the only place the loss enters. Change the loss and you change these two numbers; the rest stays the same.
  • Obj drops the part of the loss that does not change between trees, so it is only used to compare two trees with each other.
  • γ is the price of keeping a branch: if Gain − γ is below 0, cut it.
  • Why the formula takes this form: section 06.
03

Regression and classification

Plug the loss's g and h into the formula from section 02. The rest stays the same.

Lossghas StatQuest calls it
Regression: ½(y − ŷ)²ŷ − y1residual = y − ŷ = −g, Cover = n
Classification: log lossp − yp(1 − p)residual = y − p = −g, Cover = Σ p(1 − p)

Rename g to −residual and H to Cover, and the formula from section 02 takes its familiar form:

Similarity Score = (Σ residual)2Cover + λscore of the leaf
Output value = Σ residualCover + λvalue the leaf returns
  • The Output value in classification is a log-odds. New prediction = old log-odds + η × output, then mapped to p by logistic.
  • If Cover is below min_child_weight (default 1), the leaf is dropped. Regression needs only 1 row.
  • Classification at p = 0.5 needs at least 4 rows. This 6-row example must set min_child_weight = 0.
04

From table to one tree

The tree learns the residual. It tries every column and every threshold, and picks the split with the largest Gain.

  • This example is regression: g = −residual, h = 1, so Similarity Score = (Σ residual)²n + λ.
  • Each tree has leaves like a random forest, but a leaf holds an Output value: a correction number, not a label or a mean of y.
  • The Similarity Score is high when the residuals in a leaf share a sign. With opposite signs they cancel out.
  • The figure stops at one level for brevity. A real tree keeps splitting within each leaf down to max_depth, default 6.
05

Adding up many trees

Each later tree learns what the previous one still gets wrong. The final prediction adds up the trees, rather than averaging or voting.

What each tree learnsa bootstrap sample of ythe residual of earlier trees

Trainsong songsequential
  • Each tree only adds η × Output value. A small η needs more trees. Here η = 0.3.
  • Stop when n_estimators is reached, or with early stopping: when the validation score stops improving.
  • Each later tree needs the residual of the previous one, so trees cannot be trained in parallel.
06

Why the formula takes that form

Each leaf is a parabola in the leaf value. Its bottom is the Output value, its depth is the Similarity Score.

w* = − GH + λbottom of the parabola , Obj* = − ½ Σ Similarity Scoredepth of the bottom + γTpenalty on leaf count
  • Approximate the loss around the current point with a parabola: g is the slope, h is the curvature. The loss must be twice differentiable.
  • λ makes the Similarity Score and Gain smaller, so γ cuts more branches.
  • The library drops the ½ factor when computing Gain, so Gain is compared with γ directly.
07

Pros and cons

It trades tuning effort for accuracy. The defaults are rarely the best configuration.

AspectGainLose
AccuracyTop of the class on tabular data, stable across runsMany hyperparameters to tune
Overfittingγ, λ live in the objective, early stopping availableAdding trees forever still overfits gradually
Input dataNo scaling needed, takes missing values directlyCategorical variables usually have to be encoded first
Changing the lossOnly changes how g and h are computedThe loss must be twice differentiable
SpeedThreshold search runs in parallelTrees are sequential, so slower than LightGBM on very large data
Reading the modelHas feature importanceMany trees in sequence, rules cannot be read one by one
  • Choose XGBoost for medium-sized tabular data when you need high accuracy and are willing to tune hyperparameters.
  • Choose LightGBM when the data is very large or must be retrained frequently.
  • Choose random forest when you need a quick baseline with little tuning. See Random forest.
  • The number of trees is chosen by early stopping on a validation set. Full comparison: Tree models overview.
