Machine learning · Tree models

Decision tree

A decision tree cuts the table in two on one column, then cuts each mixed half again — a chain of yes/no questions that ends in an answer.

01

Mental model

Cut the rows on one column at one threshold; repeat on every half that is still mixed.

  • The same six customers as KNN: age, income, bought before, and whether they buy.
  • A half where every row has the same label is pure: it stops and becomes a leaf.
02

Reading a tree

Every cut becomes a question node; a prediction walks one path from the root to a leaf.

  • Root is the first question, internal nodes ask the next ones, leaves give the answer; the longest path is the depth.
  • Each path is an if-else rule (export_text prints them), so the model can be read line by line.
03

Classification

The label is a class: score how mixed a node is, pick the cut that unmixes it most, read the leaves.

3.1Impurity

One number for how mixed a node is: 0 when pure, highest at fifty-fifty.

Ginichance two random rows differ = 1 − Σk pk2pk = share of class k
Hentropy = − Σk pk log2 pkbits of surprise
  • The drop in entropy after a cut is called information gain — section 3.2.
  • criterion="gini" (default, CART) or "entropy" (ID3, C4.5): they almost always pick the same cut.

3.2Finding a split

Try every column × every threshold, keep the cut with the largest gain.

gainwhat the cut removes = I(S)impurity before − nLn I(SL)left half, by size − nRn I(SR)right half, by size
  • I is Gini or entropy; with entropy the gain is the information gain. Thresholds sit halfway between neighbouring values.
  • Greedy: the best cut now, never a worse cut that would pay off later.
  • Only comparisons inside one column, so no scaling is needed; a yes/no column is the threshold 0.5.

3.3Leaf & boundary

A leaf answers with its majority class; on the plane, every leaf is a rectangle.

  • predict returns the majority class, predict_proba the class shares inside the leaf.
  • Every cut is parallel to an axis, so a diagonal boundary needs a staircase of many small boxes.
04

Regression

The label is a number: same algorithm, only the impurity and what a leaf returns change.

4.1Impurity

A node is "mixed" when its values are spread out: impurity is their variance.

Var(S)impurity of a node = 1n Σi (yi − ȳ)2ȳ = mean of the node
  • Plug it into the same gain formula as 3.2; a leaf then answers with ȳ.
  • criterion="squared_error" is the default; "absolute_error" uses distance to the median and is less pulled by outliers.

4.2Finding a split

The same scan as 3.2: every column × every threshold, keep the biggest drop in variance.

  • Same cut as the classification tree here, age 31.5 — but only by coincidence: the label column decides the cuts.

4.3Leaf & staircase

A leaf answers with the mean of its rows, so the prediction is a staircase.

  • Only as many distinct predictions as leaves: the curve is flat between cuts.
  • No extrapolation: beyond the training range the tree repeats the last step.
05

Reining it in

Left alone, a tree splits until every leaf is pure: it memorises the training rows.

5.1Overfitting

Every extra level lowers training error; past some depth, test error climbs.

  • max_depth defaults to unlimited: an unconstrained tree always reaches 0 training error, which proves nothing.

5.2Instability

A tiny change — a tie, one row — changes a cut, and everything under it.

  • Drop row C and the root itself ties between age and income; small data changes, a different tree.
  • This high variance is what Random forest averages away by growing many trees.

5.3Pre-pruning

Stop growing early: forbid a split that is too deep or leaves too few rows.

  • max_depth, min_samples_leaf, min_impurity_decrease — cheap, but a stopped branch is never looked at again.

5.4Post-pruning

Grow fully, then cut back the branches that cost more leaves than they earn.

Rα(T)cost of tree T = R(T)impurity of the leaves on train + α · |T|price per leaf
  • Set with ccp_alpha; cost_complexity_pruning_path lists every useful α. Choose it by cross-validation.
06

Feature importance

A column is important when its cuts removed a lot of impurity for many rows.

imp(j)importance of column j ∝ Σt ∈ jnodes that split on j ntnshare of rows reaching it · gaintimpurity it removed
  • Normalised to sum to 1; read it from feature_importances_.
  • It describes this tree, not the world: a column that loses a tie, or is correlated with a winner, scores low.
