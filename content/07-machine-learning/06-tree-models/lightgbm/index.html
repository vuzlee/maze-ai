Machine learning · Tree models

LightGBM

Still gradient boosting, only the way the tree grows and the way data is scanned change. Three things to remember:

  • each round splits exactly one leaf
  • raw numbers are binned before scanning
  • faster, but memorizes more easily
01

Mental model

Each round, LightGBM scores every current leaf and then splits exactly one leaf — the one promising the largest drop in loss.

  • The tree's budget is a number of leaves, not a number of levels — so it grows lopsided rather than evenly.
  • The original idea is in Gradient boosting, the gain formula is in XGBoost.
02

Leaf-wise growth

Level-wise growth forces the tree to split even nearly useless spots, just because they are on the same level as the spots worth splitting.

  • With the same 16 leaves, measured test RMSE is 5.09 leaf-wise versus 5.26 level-wise.
  • So the main parameter is num_leaves, not max_depth as in XGBoost.
03

Histogram binning

Before growing trees, each numeric column is grouped into a few dozen bins. From then on the tree never looks at the raw numbers again.

  • Measured with the same 40 trees: the exact scan takes 14.1 seconds, the 32-bin scan takes 1.2 seconds and the test RMSE is even slightly better.
  • Binning is a kind of light blurring, so it is both faster and fights overfitting — unless there are too few bins: with 8 bins RMSE drops to 7.58.
04

Loss function

The loss is still the gradient boosting loss. What changes is that it is summed per bin, so finding a split takes just one scan.

gain = G2LHL + λ + G2RHR + λ − G2H + λneeds only the sum of g and the sum of h on each side
GL, HL
sum of g and sum of h over the bins left of the cut
λ
the number that restrains leaf values, exactly as in XGBoost
  • Each bin keeps only two numbers, so one left-to-right cumulative pass gives the gain of every cut.
  • The sibling leaf is cheaper still: take the parent's histogram minus the other child's, no rescan needed.
05

GOSS

Samples the model already predicts nearly right have small gradients, and small-gradient samples barely change where the split goes — so drop some of them.

  • Measured: scanning 30% of the samples gives a test RMSE of 4.77, better even than scanning everything (5.34) — because dropping easy samples is also a kind of blurring.
  • The randomly drawn part must have its weights scaled up to compensate, or the sum of g skews heavily toward the hard group.
06

EFB

One-hot data has hundreds of columns where each row has only a few non-zero cells. Columns that are never non-zero together can be packed into one place.

  • Measured: 60 columns at 5% density merge into 11 bundles, cutting scans 5.5 times without losing any information.
  • Moderately sparse columns can still be merged, in exchange for a little conflict — which is why max_conflict_rate exists.
07

Reining the tree in

Leaf-wise growth has no level ceiling to hold it back, so on data with few rows it heads straight into memorizing.

  • Three checks in order: shrink num_leaves, raise min_child_samples, and only then learning_rate and early stopping.
  • Rule of thumb: num_leaves should be below 2max_depth, otherwise setting max_depth has no effect at all.
08

Pros and cons

Every strength comes from cutting down what has to be scanned. Every weakness comes from exactly the same place.

AspectGainLose
SpeedFastest in the group: bin scanning, dropping easy samples, bundling sparse columns—
MemoryBins are stored as one byte, so large data still fits in RAM—
GrowthWith the same leaf count it lowers loss more than level-wise growthOn data with few rows it balloons and memorizes very fast
BinningA light blur, so it also fights overfittingToo few bins lose the right cut altogether — 8 bins give RMSE 7.58
TuningDefaults run right away on large dataYou must remember that num_leaves, not max_depth, is the main parameter
CategoricalTakes categorical columns directly, no one-hot neededCategoricals with many rare values easily split on noise
Reading the modelHas feature importance and SHAP like XGBoostA lopsided tree a dozen levels deep is even harder to read than a balanced one
  • Choose LightGBM when the data has many rows and many columns and training time is the biggest worry.
  • Choose XGBoost when the data is moderate and you want safer defaults.
  • Choose Random forest when you suspect dirty labels or do not want to tune parameters.
