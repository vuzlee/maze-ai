LightGBM

LightGBM is gradient boosting that grows each tree one best leaf at a time and searches splits over a few bins instead of every value — much faster, but the leaf count is now yours to rein in.

01

Mental model

Every leaf bids the gain of its best split; each round, only the top bid is split, until the tree has num_leaves leaves.

  • The same six customers and residuals (spend − 25) as XGBoost; a bid is XGBoost's Gain with λ = 0, LightGBM's default.
  • The budget is a number of leaves (default 31), not a depth, so the tree grows lopsided toward where the error is.
02

Growing a tree

Same 8-leaf budget, same gain formula: only which node is split next changes.

2.1Level-wise

Split every node of a level, useful or not, then move one level down.

  • The rule of XGBoost by default: a balanced tree, depth set by max_depth.

2.2Leaf-wise

Split the one leaf with the largest gain, wherever it sits.

  • Same 8 leaves, less error left: 941 → 763, because no split is spent on a node with gain 6.
  • Nothing stops one branch from going very deep — section 06.
03

Histogram binning

Bucket every column into bins once; from then on a split search works on per-bin sums, not on rows.

3.1Bins

Candidates drop from every gap between values to every bin edge.

  • Each bin stores the sum of gradients and of hessians; one left-to-right pass gives the gain of every edge.
  • max_bin defaults to 255. Boosting 100 trees here: exact test RMSE 1.79, 10 bins 1.70, 5 bins 2.16 — coarse bins also smooth, too coarse loses the cut.

3.2Histogram subtraction

After a split, build the histogram of the smaller child only; the sibling is a subtraction.

  • Works because a parent's bins are exactly its two children's bins added up — for counts and gradient sums alike.
04

GOSS

Rows the model already fits have small gradients; keep the big ones, sample the rest and weight them up.

  • Gradient-based One-Side Sampling: top_rate 0.2 and other_rate 0.1 here; the weight is (1 − 0.2) / 0.1 = 8.
  • Without the weight the big gradients dominate the sums and the gain is overstated.
05

Sparse and categorical columns

Fewer columns to scan, and categories split without one-hot.

5.1EFB

Sparse columns that are never non-zero in the same row can share one column, shifted so their values do not mix.

  • Exclusive Feature Bundling: fewer columns means fewer histograms to build; each city still gets its own splits from its own bins.
  • One-hot columns are the typical case. A few rows where two columns clash are tolerated, up to max_conflict_rate.

5.2Native categorical split

Sort the categories by mean gradient, then try only the cuts in that order — one node sends a whole group of categories left.

  • Declare the column with categorical_feature (or pandas category dtype); k categories give k − 1 cuts, not 2k−1 subsets.
  • Missing values need no imputing: at each split the rows with no value are tried on both sides and sent where the gain is larger, and that direction is stored in the node.
06

Reining it in

Leaf-wise growth has no level to stop at: with few rows, a tree chases noise unless you limit it.

6.1num_leaves

The main knob: leaves per tree, the budget of section 01.

  • Default 31. On 300 noisy rows the best here is 4; large data supports many more.

6.2min_data_in_leaf

Forbid a split that would leave too few rows in a child.

  • Default 20 (min_child_samples in the scikit-learn API): with 64 leaves allowed, it alone brings test RMSE from 1.86 to 1.70.

6.3max_depth

A depth limit caps a tree at 2d leaves — it only acts when that is below num_leaves.

  • Default none. Keep num_leaves < 2max_depth, or setting max_depth changes nothing.
  • The usual tuning set: num_leaves and min_data_in_leaf for tree size, learning_rate (default 0.1) traded against the number of rounds, and feature_fraction / bagging_fraction (with bagging_freq) to sample columns and rows per tree.
