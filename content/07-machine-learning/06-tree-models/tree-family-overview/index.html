Tree models overview

Read this before learning Decision Tree, Random Forest or XGBoost. It answers exactly one question: what problem are people trying to solve, and where those dozens of names sit in that picture.

01

Mental model

The branch is the five parts below. Each lesson in the group opens up one box.

02

The problem

There is a data table. You need to predict one column from the others. That is all.

ageincomebought beforecity→ will buy?
2412knoParisno
4135kyesRomeyes
3318kyesParisyes
579knoBerlinno
  • This table is hard for a math formula: "city" has no order, "income" and "age" are on completely different scales.
  • The relationship is not linear: over 60 is a different story — a straight line cannot express that threshold.
  • The columns affect each other: young with high income is different from young with low income.
  • Tables are the kind of data you meet most in real work: bank transactions, medical records, user logs, orders.
03

The first idea people came up with

No formula. Just ask one yes/no question at a time — exactly how a doctor diagnoses an illness.

  • The questions are yes/no on one column, so scale does not matter — age and income can sit side by side.
  • Asking further inside the branch just split is exactly how it catches columns affecting each other.
  • The result can be explained to someone who knows no math — few models can do that.
04

But one tree is weak

A tree memorizes the old data: 100% right there, often wrong on new data.

one tree · on data it learned100% right
one tree · on new data64.8% — a sharp drop
parallel combining · Random Forest70.5%
sequential combining · shallow-tree boosting73.8%

measured: 400 training rows, 4,000 test rows, binary label — the same dataset for all four rows

  • Change a few rows and you get a completely different tree: randomly drop 10% of the rows and regrow, and the two trees disagree on 30.1% of the test rows. The same operation on a forest gives only 17.0% — combining trees makes the model depend less on individual rows.
  • But that very weakness is useful: many trees err in different ways, and combined they cancel out.
  • The next 30 years of research revolved around one question: how to combine many trees.
  • Combining many weak models into one strong model is called an ensemble. It suits trees best, because trees are cheap to train and each one is different.
05

40 years of research in one picture

Each name (XGBoost, LightGBM…) is one answer to the question in the previous section.

  • From 1996 on, every name is a way to combine trees, not a new kind of tree.
  • XGBoost and LightGBM are not new algorithms — they are gradient boosting rewritten to be fast, with added regularization.
  • Deep learning took off in 2012 but has not replaced this branch on tabular data.
06

Ways to combine trees

There are only two ways to combine, for two different problems. Every algorithm sits on one of the two branches.

Bagging — when each tree is too complex

Each tree is too complex, and each one errs in its own way.

Averaging makes the errors cancel each other out.

Like asking 100 independent people and taking the majority.

Boosting — when each tree is too weak

Each tree is too weak, guessing only slightly better than a coin flip.

Each later tree focuses only on where the earlier ones are still wrong.

Like redoing an exercise, each time fixing exactly where you just went wrong.

  • The table under the figure reads as one sentence: the base tree must make up for exactly what the combining step does not handle.
  • So a deep tree in boosting adds the noise in too, and later trees cannot take it back out.
  • Two things not in the figure: Random Forest is not very sensitive to hyperparameters — the defaults are already near-best, while boosting needs tuning to reach its higher score.
Choose Random Forest when

you need a quick baseline that works well right away with defaults

the data has label noise

there is no time for tuning

you want an OOB score in place of a validation set

Choose boosting when

you need the highest score possible

you have a good validation set for early stopping

you have time to search hyperparameters

labels are clean — later trees will try to learn wrong labels too

  • Random Forest combines deep trees trained in parallel, to reduce variance.
  • Boosting adds up shallow trees trained in sequence, to reduce bias.
  • In practice: adding trees to Random Forest is safe, adding trees to boosting requires early stopping.
07

Choosing XGBoost or LightGBM

Both are gradient boosting with the same objective function. Choose by data scale and working rhythm, not by "which one is stronger".

XGBoostLightGBM
Main contributionSecond-order Taylor approximation → leaf values computed directly; regularization lives in the objective functionKeeps that same objective function, optimizes how split points are searched
Tree growthLevel-wise — balanced trees, more stableLeaf-wise — faster and more accurate, overfits easily on small data
Main limiting parametermax_depth, lambda, gammanum_leaves together with min_data_in_leaf
Categorical variablesMust be encoded firstAccepted directly
Choose whenUnder a few tens of thousands of rows, stability firstMillions of rows, or frequent retraining
  • After careful tuning, the accuracy gap between the two libraries is much smaller than the gap in run time.
  • So the deciding factor is almost always data scale and retraining rhythm.
  • The shared mechanism of both is in Gradient boosting.
  • And CatBoost: worth trying when the table is full of high-cardinality categorical columns — product codes, region codes, user IDs. It encodes each row using only the rows before it, so labels do not leak.
08

What order to learn in

Five lessons; in this order, each lesson adds only one new idea over the previous one.

1 · Decision TreeHow one tree learns: how it picks questions, when it stops, why it memorizes easily. The foundation of the whole branch — the four lessons after it all assume you have this one.
2 · Random forestThe only new idea: grow many trees on randomly drawn data, with each split allowed to see only a few columns. Why that "randomness" makes the model better.
3 · AdaBoostNew idea: instead of growing in parallel, grow one after another, and raise the weight of samples currently predicted wrong. The easiest lesson for grasping the spirit of boosting.
4 · Gradient boostingNew idea: instead of raising weights, have each new tree learn the remaining error directly. This is the general version XGBoost and LightGBM both build on.
5 · XGBoost & LightGBMNo new mathematical idea — just gradient boosting that runs faster and overfits less. This lesson leans toward using it correctly.
  • The first three lessons are what universities teach and interviews ask about most. The last two are what real work uses.
  • Do not jump straight into XGBoost — it sits on top of the four ideas below it. Skip them and you only learn how to call a function.
  • SVM, KNN, Naive Bayes belong to another branch. The tree branch alone is enough for most tabular-data problems.
09

Pocket dictionary

These seven words will appear constantly in the next four lessons. One line each, come back to look them up when needed.

TermMeaning in one sentence
EnsembleCombining many weak models into one strong model.
BaggingCombining by growing many trees in parallel and averaging.
BoostingCombining by growing trees one after another, each fixing the previous one's errors.
BootstrapRandomly drawing n rows with replacement from the n original rows — so some rows are drawn twice and some not at all.
Weak learnerA weak model, only slightly better than guessing. Boosting uses this kind on purpose.
OverfitMemorizing even the noise of the old data → right on old data, wrong on new data.
Variance / BiasHigh variance = the model is too sensitive, a little data change changes it entirely. High bias = the model is too simple, wrong in a systematic way.
  • Bagging cures variance, boosting cures bias — remember this pair and you will mix them up less later.
  • "Weak learner" sounds negative but is a deliberate choice: only weak trees can be added up under control.

What you can do after this branch

Not "knowing algorithm names", but four concrete skills.

Read a tree

Look at the tree the model prints and explain why it predicts what it does for a specific customer.

Choose the right model

Know when to use Random Forest, when to use LightGBM, and when trees are completely the wrong choice.

Tune the right hyperparameter

When the model overfits, know what to tune first, and why that and not something else.

Understand it properly

Explain the bagging/boosting difference by mechanism, not by a memorized sentence.
