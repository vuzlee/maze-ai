Logistic regression

Take linear regression's straight line and change two things. Three things to remember:

  • sigmoid squashes the score into the range 0 to 1
  • log loss replaces MSE
  • the model returns a probability, not a label
01

Mental model

A sample goes through three stages: x → z → p, and only then a label. The model stops at p.

  • Running example: 6 customers A–F, x is age, the label is buy or not.
  • The line and the gradient are already in Linear regression. Sigmoid and log loss are the new parts.
  • Going from p to a label is a threshold the user chooses, see section 06.
02

General formula

The score z is the linear part. Sigmoid turns z into a probability. Log loss measures confidence placed in the wrong spot.

L = − 1n Σ [ yi log pi + (1 − yi) log (1 − pi) ]log loss: only one of the two terms survives

  • The gradient has the form (p − y)·x, exactly like linear regression with MSE.
  • Not a coincidence: it is a shared property of the exponential family when using the canonical link function.
03

From table to probability

Each row goes through three columns: z, then p, then log loss. The loss is the mean of the last column.

  • The decision boundary is still a flat plane, so the model cannot separate customer E.
  • For a curved boundary you have to add higher-order or interaction features yourself.
04

Why sigmoid and log loss

A straight line does not stop at 0 and 1. And MSE paired with sigmoid kills the learning signal exactly on the worst mistakes.

  • MSE is not wrong in principle; it just kills the learning signal where learning is needed most.
  • MSE with sigmoid also gives a loss surface with many minima, so where you stop depends on where you start.
05

Odds ratio: reading coefficients

The linear part is exactly the log-odds. So one more unit of x multiplies the odds, rather than adding to them.

log p1 − plog-odds = w·x + bexactly the linear part , ew = odds ratiohow many times the odds multiply when x rises by 1
odds
cases where it happens divided by cases where it doesn't
log-odds
the log of the odds, exactly the linear part
odds ratio
how many times the odds multiply when x rises by one unit

Example with coefficient w = 0.7 on the variable "has bought before". This customer has never bought; the probability of buying is p = 0.30. Now we learn the customer has bought before:

  • Add on the log-odds scale, multiply on the odds scale, and on the probability scale there is no tidy operation at all.
  • The odds double, but the probability only rises to 0.46.
  • For a non-specialist audience skip the first two scales and just say "from 30% to 46%".
06

Decision threshold

The model stops at a probability. The threshold is a business decision, not a model parameter.

  • Lower the threshold to 0.3: catches all 3/3 buyers but raises 1 false alarm.
  • Raise it to 0.7: flags only when very sure, missing 2/3 buyers.
  • The 0.5 default is nothing special. Choose by the cost of the two kinds of error.
  • How to measure precision and recall: Classification metrics.
07

Pros and cons

Every strength comes from a straight line squeezed through a sigmoid. Every weakness comes from exactly the same place.

AspectGainCost
OutputMeaningful probabilities, well calibrated out of the boxYou must choose the threshold
InterpretabilityEach coefficient is an odds ratioMust be read on the odds scale, not the probability scale
BoundaryStable, rarely overfitsAlways a flat plane; curved relationships need hand-made features
TrainingConvex loss, so a single minimumNo closed form, must be solved iteratively
DataWorks with few samplesNeeds scaling, and heavily imbalanced classes need special handling
  • Choose logistic regression when you need trustworthy probabilities, readable coefficients, or a baseline.
  • Choose gradient boosting when you only need the highest accuracy on tabular data.
  • L1 and L2 regularization keep the same mechanism as in Ridge, Lasso; only the base loss changes.
  • In scikit-learn, C is the inverse of λ: raising C means less regularization.
