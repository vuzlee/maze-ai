Metric &
confusion matrix

Picking the wrong metric is the fastest way to fool yourself that a model is good. This lesson goes from the four cells of the confusion matrix out to every metric, explains with concrete numbers why 99% accuracy can be meaningless, and why the 0.5 threshold is almost always wrong.

01

Mental model

No metric is the universal "right metric" — choosing a metric is choosing which question you are asking.

  • The four cells on the left are the confusion matrix, the root of every metric in this lesson; section 02 takes each cell apart and names it.
  • This lesson stays on the middle branch on the right. The top branch has its own lesson: ROC-AUC & PR curve; the bottom one: Probability calibration.
  • This lesson stops at offline metrics — the things that measure the model. The table of which metric to use when, and the story of AUC going up while revenue does not budge, live in Model evaluation overview.
  • The more imbalanced the data, the more useless accuracy becomes — with 1% positives, blindly guessing "negative" already scores 99%, so that number says nothing.

03

Precision, recall, F1 — which one

The answer always lies in the cost of the two kinds of error, not in the model.

TaskWhich error costs morePrioritize
Cancer screeningMissing a sick case (FN)Recall — better a false alarm and one more test
Blocking suspected fraud transactionsWrongly blocking a real customer (FP)Precision — wrong blocks lose customers
Spam filteringSending an important email to spam (FP)Precision
Machine fault detectionMissing a fault that causes an accident (FN)Recall
Product recommendationBalanced, and computed over top-kPrecision@k, NDCG

F1 and its variants

Fβ = (1 + β2) P Rβ2 P + R
β = 1
is exactly F1 — treats precision and recall as equally important
β = 2
treats recall as twice as important as precision
β = 0.5
treats precision as twice as important

This is a harmonic mean, not an ordinary mean: with P = 1.0 and R = 0.0 the ordinary mean is 0.50 but F1 is 0.00. The smaller value always pulls the result down.

  • F1 implicitly assumes the two kinds of error cost the same. That assumption is almost always wrong.
  • Missing one fraud case loses 10M, wrongly blocking one customer loses 100k — a 100:1 ratio, and F1 reflects none of it.
  • Pick β by the cost ratio, or compute directly in money as in section 05.

Same model, same ranking ability — but the real-world usefulness is entirely different.
That is the whole reason to use PR-AUC when the positive class is rare.

05

Choose the threshold by cost, not by F1

Ask the business side for the price of the two kinds of error, then sweep every threshold and pick the cheapest point.

cost = #FP × 200kreal customer wrongly blocked + #FN × 5Mfraud case missed

A 25 : 1 ratio — misses cost far more, so the best threshold will be lower than 0.5 to catch more.

threshold 0.50costs 41M
threshold 0.3024M
threshold 0.1518M ← cheapest
threshold 0.0529M — too many wrong blocks

sweep the threshold, measure in money0.5 is the library default, almost never the cheapest point

  • It uses exactly what the business side already has and F1 throws away: the real price of each kind of error.
  • The result is a number in money, something you can say to non-technical people.
  • When prices change you only re-pick the threshold — no retraining.
  • The threshold is not a model parameter. The model gives a score; the threshold is a business decision applied on top of that score.
  • Deploy the model so it returns probabilities, and keep the threshold in config — changing the threshold then needs no redeploy.
06

Multiclass

Multiple classes means multiple numbers — how you combine them is a choice, not a technical detail.

macrocompute per class then take a plain average → rare classes get as much say as large ones
weightedaverage weighted by sample count → large classes dominate
micropool TP, FP, FN of every class then compute once → for single-label tasks, micro-F1 equals accuracy
ChooseWhen
macroEvery class matters equally, rare ones included — usually the right default for imbalanced data
weightedYou want to reflect performance on the real-world distribution
microMulti-label tasks, or when each prediction matters equally rather than each class
  • Since micro-F1 is accuracy, it inherits the same flaw from section 02 — do not use it on imbalanced data.
07

Regression metrics

MetricFormulaProperties
MAEmean(|ŷ − y|)Same unit as y, easy to explain, robust to outliers. Estimates the median
RMSE√mean((ŷ − y)²)Same unit, punishes large errors heavily. Estimates the mean
R²1 − SSESSTUnitless, but depends on the variance of the test set
MAPEmean(|ŷ − y||y|)In %, but has three serious problems
Breaks when y is near 0It divides by the true value, so one sample with y = 0.01 blows MAPE up to thousands of percent.
AsymmetricUnder-predictions are capped at 100%, over-predictions are unbounded. So a model optimizing MAPE tends to under-predict systematically.
Not comparable across seriesTwo series at different value levels give MAPE numbers that do not mean the same thing.
Replace withWAPE, sMAPE, or MASE for time-series forecasting.

The biggest difference between MAE and RMSE shows up when one sample is off by a lot:

MAE — 100 samples each off by 22.0
RMSE — same data2.0
MAE — add 1 sample off by 1002.98
RMSE — add 1 sample off by 10011.0 ← jumps 5×

one outlier barely moves MAEbut makes RMSE explode — because it squares before averaging

About R², two things are easy to misread.

  • It can be negative — meaning the model is worse than predicting the constant mean.
  • The denominator is the variance of the test set, so the same model gives different R² on two different test sets — do not use R² to compare two datasets.
08

Common mistakes

Reporting accuracy on imbalanced data

99% with recall 0. Always ask the class ratio first.

Using ROC-AUC when positives are very rare

The number looks falsely good because FPR divides by a huge negative count. Use PR-AUC.

Keeping the 0.5 threshold

The threshold is a business decision. Choose it by expected cost.

Optimizing F1 by default

F1 assumes both errors cost the same — almost always wrong.

Using MAPE when y is near 0

The metric explodes and favors under-prediction.

Comparing R² across two different datasets

The denominator is the test-set variance, so they cannot be compared.
