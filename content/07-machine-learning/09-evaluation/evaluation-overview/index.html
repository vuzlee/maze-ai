Model evaluation — lookup table

One model, three different questions, three groups of metrics that cannot stand in for each other. This lesson covers how to read the table and pick a measure; how each measure works lives in the next three lessons.

01

Mental model

Asking "is this model good" is an incomplete question. There are at least three questions, and a model can ace one and fail another. Rewrite the scores with an increasing function and F1 changes 5.5× while ROC-AUC does not move by a thousandth.

  • The three axes break in three different ways, so one number is never enough: the √p row catches all 148 positives (recall 1.000) but brings 2,588 false alarms — F1 shows it, ROC-AUC does not.
  • Not every task needs all three: if you only take the top-k, axis one is enough; only probabilities that get multiplied by money need axis three.
  • Reading order: Metric & confusion matrix → ROC-AUC & PR curve → Probability calibration.
02

Choosing a metric

Two questions settle most of the table: what share of the data is positive, and where will this number go after it is reported.

SituationMain metricOwner lesson
Balanced classificationAccuracy or ROC-AUCROC-AUC & PR curve
Rare positive class, positives matterPR-AUC + precision/recall at the chosen thresholdROC-AUC & PR curve
Real cost of FP and FN is knownExpected cost — always the best when you have this informationMetric & confusion matrix
Probabilities feed further computationLog loss or Brier score, plus a reliability diagramProbability calibration
Ranking, recommender systemsPrecision@k, Recall@k, NDCG, MRRMetric & confusion matrix
Multiclass, with rare classesMacro-F1Metric & confusion matrix
RegressionMAE if you care about the typical error · RMSE if large errors are very badMetric & confusion matrix
  • The middle column is the main metric, not the only one. One number plus a confusion matrix is the safest way to report.
  • The most common mistake is row two: ROC-AUC still looks good when positives are rare because FPR divides by a very large denominator.
  • Every number only means something when measured on data the model has not seen — leakage traps are in Train, validation & test.
03

From offline metrics to real impact

Every measure in this group is an offline metric — it measures the model, not the product.

Metric offline

AUC, F1, Brier — computed on the test set

does it carry over?→
Product metric

click rate, revenue, fraud cases blocked

measure the gap→
A/B test

is the gap real or just noise

  • The two ends do not match automatically: AUC goes up while the product does not budge — that is common.
  • What to do early: check whether the offline metric correlates with the product metric, before using it to pick models for months.
  • Proving a gap is real takes a completely different tool — see A/B testing.
