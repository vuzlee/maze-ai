Probability calibration

The third axis of evaluation, after the confusion matrix and the curves: a model that ranks correctly can still say 0.9 when reality is 0.6.

01

Mental model

The lesson is the five parts below. Every later section redraws this map and highlights the box being studied.

02

The problem it solves

Accuracy asks "is the decision right", AUC asks "is the ranking right". Calibration asks a third question: does that 0.9 mean anything.

Two models can have exactly the same AUC while one says 0.9 when reality is 0.9, and the other says 0.9 when reality is only 0.6.

AUC cannot tell them apart, because it only looks at order.

Distort every score with a monotonic function and AUC does not change at all, even though the probability values are now plainly wrong.

Ranking only

Take the top 1,000 customers most likely to churn and call them.

The probability values do not matter — only the order has to be right.

AUC is enough.

Need the real value

Send a $5 voucher if the expected value exceeds the cost.

When computing in money, 0.9 and 0.6 lead to two different decisions.

Must calibrate.

  • Calibration is the precondition for a probability to feed the next computation: expected value in money, threshold set by cost.
  • It is orthogonal to ranking ability: calibration is a monotonic transform, so it does not change AUC.
  • Don't pick one: report both AUC and a calibration measure when probabilities are used for computing, not just for ordering.
03

Measuring with a reliability diagram

Split predictions into groups by probability, then ask in each group: how much did the model say, how much was real.

A well-calibrated model: of all the cases it calls "70%", about 70% are actually positive.

  • Merging the gaps of all bins into one number gives ECE — Expected Calibration Error: the weighted average of each bin's gap.
  • Brier score — the squared gap between the probability and the 0/1 label — combines calibration and discrimination.
  • The number of bins is a trade-off: more bins give more detail but more noise. With little data, split by quantiles.
04

Which models are skewed by design

The skew is not random but predictable from how the model learns.

ModelDefault calibration
Logistic regressionGood — log loss is exactly the loss function that optimizes probability
Gradient boostingFair, but often slightly off at both ends
Random ForestPoor at both ends — an average of many trees rarely gives 0 or 1
SVMPoor — the output is a distance to the hyperplane, not a probability
Deep neural networksOften overconfident — tends to output 0.99 when reality is only 0.8
  • Models that optimize log loss directly come calibrated. SVM and Random Forest give scores dressed up as probabilities.
  • Random Forest is the easiest to picture: the probability is the share of trees voting positive, so getting 1.0 means all hundred trees must agree.
  • Neural networks skew the other way: long training pushes probabilities toward 0 and 1 — confidence grows faster than accuracy.
05

Fixing with Platt scaling & isotonic

Both learn a monotonic function mapping old scores to new probabilities. Because it is monotonic the order is unchanged, so AUC is unchanged.

Platt scalingIsotonic regression
Function shapeSigmoid — two parametersMonotonic steps — very many steps
Data neededLittle, a few hundred samples workA lot — under ~1,000 samples it overfits
Kind of skew it can fixOnly sigmoid-shaped, which fits SVM and neural networksAny monotonic shape
RiskCannot fix unusual skew shapesSteps fit noise when data is scarce
  • Fit the calibrator on the training set itself and it relearns exactly the model's overconfidence. The diagram looks falsely good, and data leaks into the measure.
  • Use a separate set, or use cross-validation to produce out-of-fold scores and fit on those.
  • In sklearn, CalibratedClassifierCV does both kinds out of the box.
06

When it is actually needed

Not every task needs calibration. The only question: where does the probability go after the model returns it.

Ranking onlytake the top-k, sort the display order — not needed, AUC is enough
Fixed threshold cutthreshold tuned on the validation set — not needed, because the threshold absorbs the skew
Feeds a computationexpected value in money, credit risk, threshold set by cost — needed
Merging several modelsadding or averaging probabilities from several sources — needed, otherwise the most confident model dominates
  • Calibration is needed when probabilities are used in further computation: expected value in money, credit risk, merging predictions from several models.
  • If you only need ranking to take the top-k, AUC is enough and calibration does not matter.
07

Common mistakes

Bad calibration is more dangerous than none, because the numbers look much more trustworthy.

Fitting the calibrator on the training set

It relearns the exact same skew. The diagram looks good on paper, the skew is fully intact in production.

Using isotonic with a few hundred samples

The steps fit noise. With little data, Platt scaling is much safer.

Thinking calibration makes the model more accurate

It does not change order, so it does not change AUC and catches no extra cases. It only fixes the values.

Treating an SVM's decision_function output as a probability

That is an unnormalized distance to the hyperplane. It must go through Platt scaling to become a probability.

Looking only at ECE

One number hides where the skew is. A skew in the 0.9 bin is far more dangerous than one in the 0.1 bin — look at the diagram.

Calibrating once and never measuring again

When the data distribution drifts, the skew comes back. Measure calibration periodically like any other metric.
