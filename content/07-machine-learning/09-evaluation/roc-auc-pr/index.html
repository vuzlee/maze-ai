ROC-AUC & PR curve

Continuing from Metric & confusion matrix: when the threshold is not fixed yet, what do you evaluate a model with — and why two curves drawn from the same model tell opposite stories.

01

Mental model

The lesson is the four parts below. Every later section redraws this map and highlights the box being studied.

02

From confusion matrix to curve

A confusion matrix needs a threshold to be computed. But the threshold is a business decision, made later — so we need an evaluation that does not depend on it.

The model does not return labels but scores, usually probabilities.

  • Set the threshold at 0.5 and you get one confusion matrix, set it at 0.3 and you get another — lowering the threshold makes recall rise and precision fall.
  • Each threshold is one point; sweep every threshold and the points join into a curve.

the area under it = one single number

  • The two curves differ only in which pair of metrics forms the two axes: ROC uses FPR–TPR, PR uses recall–precision.
  • AUC measures ranking ability, not decision quality: a perfect ranking still makes bad decisions if the threshold is wrong.
  • Neither one says anything about whether the probabilities can be trusted — that is axis three, in Probability calibration.
03

Reading ROC & what AUC means

AUC has an exact probabilistic interpretation, and it is worth remembering that one rather than "area under the curve".

ProsCons
Threshold-independent — measures ranking abilityIndependent of class ratio — sounds nice but is exactly the trap
Comparable across models on the same dataSays nothing about whether the probabilities are calibrated
Clear probabilistic meaning, easy to explainTreats FP and FN the same, even though their real costs differ
  • Both ROC axes are rates within a single class: TPR divides by the total positives, FPR divides by the total negatives.
  • So when negatives outnumber positives a thousand to one, FPR still looks small even though the absolute FP count is huge.
  • A model can have ROC-AUC 0.95 and be completely unusable — the next section has concrete numbers.
04

PR curve — with concrete numbers

Same model, same dataset. ROC says "excellent", PR says "only 1 in every 10 alerts is right".

10,000 transactions, of which 100 are fraud. The model catches all 100, but raises false alarms on 900 normal ones.

What ROC sees

FPR = 900 / 9,900 normal cases

= 0.09 — only 9%, sounds great

What PR sees

precision = 100 / 1,000 alerts

= 0.10 — 9 in 10 alerts are wrong

same model, same datasetthe only difference is the denominator

FPR denominator — number of normal cases9,900
precision denominator — number of alerts1,000 · exactly the pile a real person must review

Worth remembering: the PR-AUC baseline is not 0.5 but the positive class rate itself.

So a PR-AUC of 0.30 on data with 1% positives is a very good result — 30× the random level. Without knowing this, it is easy to think the model is bad.

05

Which curve to pick

There is only one deciding question: what share of the data is positive, and which class do you care about.

Use ROC-AUC when

the two classes are fairly balanced — a ratio from 1:1 up to about 1:10

you care about both classes equally, with no class being "the one to find"

you need to compare models across datasets with different class ratios — here the invariance becomes a strength

Use PR-AUC when

the positive class is rare — fraud, rare disease, equipment faults, search

you only care about the positive class; TN is so plentiful it carries no information

a real person must handle each alert — precision is exactly the share of effort not wasted

  • It is not pick-one-drop-the-other — reporting both is normal, as long as you say which number drives the decision.
  • Neither is for setting the threshold — they pick the model; to pick the threshold, compute expected cost (Metric & confusion matrix).
  • If you know the real operating region there is something better than global AUC: precision at fixed recall or recall at fixed FPR.
06

Common mistakes

Both curves can be drawn for any model, and neither warns you when it is misread.

Using ROC-AUC when positives are very rare

The number looks falsely good because FPR divides by a huge negative count. This is the most common mistake in the group.

Comparing PR-AUC against 0.5

The PR-AUC baseline is the positive class rate. 0.30 on 1% data is very good, not bad.

Comparing AUC across two datasets with different class ratios

Fine for ROC, not for PR — the PR baseline moves with the class ratio.

Concluding a model is good because AUC is high

AUC only speaks to ranking. Decisions still depend on the threshold, and probabilities still need calibrating.

Trusting AUC on a very small test set

With a few dozen positives, AUC swings wildly. Report a bootstrap confidence interval alongside it.

Setting the threshold at the point nearest the top-left corner

That point implicitly treats FP and FN as equally costly. Real costs often differ by tens of times.
