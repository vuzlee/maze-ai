HDBSCAN

It fixes exactly where DBSCAN hurts: clusters of different density, and not knowing what to set eps to. The fix is to stop choosing eps — run every value and let the data speak.

01

Mental model

The lesson is the six parts below. Every later section redraws this map and highlights the box being studied.

02

The problem it solves

DBSCAN cuts density at exactly one threshold. In real data one cluster is dense, another sparse — and a single threshold cannot fit both.

Set a small eps to fit the dense cluster

The dense cluster is split correctly.

The sparse cluster dissolves into noise — vanishing from the result entirely, with nothing to tell you it is gone.

Set a large eps to fit the sparse cluster

The sparse cluster appears.

Dense clusters that sit close together merge into one blob — all internal distinction is lost.

  • This is not an implementation bug but a limit of the definition: an absolute threshold is only right when all clusters share the same density.
  • Choosing eps is hard to begin with. With clusters of different density the k-distance plot has several elbows, and whichever you pick sacrifices something.
  • HDBSCAN's answer: don't choose. Run DBSCAN at every eps level and see which clusters survive longest across those levels.
03

Core idea — stability

Imagine lowering the density threshold step by step. A real cluster keeps its shape for a long time; a fake one breaks as soon as it appears.

high thresholdonly the densest peaks show
loweringclusters appear, grow, then split or merge
low thresholdeverything joins into one blob

DBSCAN takes one snapshot on this axisHDBSCAN watches the whole film, then choosesclusters that last = real clusters

Running DBSCAN with decreasing eps yields a hierarchy.

  • At the top are large blobs; lower the threshold and each blob gradually splits into sub-clusters, until at the bottom every point is a leaf.
  • The only remaining question is where to cut this tree — and what is new in HDBSCAN is that it does not cut straight across one level.
  • Cutting straight across one level is just DBSCAN with its old weakness. HDBSCAN cuts unevenly: this branch at a high level, that branch at a low one.
  • Which branch to pick is decided by stability: a cluster that survives across a wider range of thresholds, with more points, is more worth keeping.
  • The result: each cluster is taken at its own density level, so dense and sparse clusters appear in the same run.
04

Loss function

No loss function here either — but unlike DBSCAN, there is a score to choose by: stability.

  • Why it needs a score when DBSCAN does not. DBSCAN only has a definition and groups by it; one run and it is done. HDBSCAN builds a whole hierarchy, so it still has to choose which branches to cut — and choosing means comparing two ways of cutting. The stability of a cluster is Σ (λleave − λbirth): each point contributes exactly the threshold range during which it stays in that cluster.
  • But this is not something to minimize. No loop lowers it, there is no global optimum. It is just a ruler to compare two ways of cutting the tree and keep the one with the larger sum — closer to the pruning criterion of a decision tree than to inertia.
  • What it buys, measured in numbers. On 390 points with two dense clusters σ = 0.10 close together and a sparse one σ = 1.8: eps 0.25 separates the two dense clusters but the sparse one vanishes completely (0%); eps 1.10 sees 88% of the sparse cluster but the two dense ones have merged. HDBSCAN takes the two dense clusters at the equivalent of eps 0.58 and the sparse one at 2.68 — three different levels, one run. Stability also says the sparse cluster scores only 103.4 vs over 2,000: real, but much looser.
05

Mechanism

Four steps, and the first is the trick that makes everything after it work: change the distance so sparse regions get pushed far away.

1 · Mutual reachability distancereplace the real distance with max(core_k(a), core_k(b), d(a,b)), where core_k is the distance to the k-th neighbor — points in sparse regions are pushed away from everything, points in dense regions stay put
2 · Minimum spanning treebuild a minimum spanning tree on the transformed distance — removing longer and longer edges is exactly lowering the density threshold step by step
3 · Cluster hierarchyremove edges in order of decreasing length, recording at which level each cluster is born and at which it breaks
4 · Cut by stabilityfor each branch, compare its stability with the total stability of its child clusters; if the children win keep going down, if the parent wins stop and take the parent
corek(a) = distance from a to its k-th neighbormeasures whether the area around a is sparse or dense
dmreach(a, b) = max( corek(a), corek(b), d(a, b) )a sparse point has a large core → all its distances get stretched

Read it as: two points only count as close when the areas around both are dense enough, not merely when they sit next to each other.

  • Mutual reachability is where density gets packed into distance, so the later steps only work on a graph.
  • The main remaining parameter is min_cluster_size: anything smaller is not called a cluster — a direct business meaning, so it is easy to set.
  • Cost is O(n log n) in low dimensions thanks to spatial indexes, a few times heavier than DBSCAN. In high dimensions both fall back to O(n²).
06

Where it is used

The default to try first when you do not know how many clusters there are and do not trust the data to have uniform density.

Clustering embeddingstext, images, logs — after reducing dimensions with PCA or UMAP. This is the most common use today
Exploring unknown datano guessing k, no guessing eps; the hierarchy also shows nested structure
Anomaly detectiona low cluster-membership probability is a better signal than DBSCAN's binary noise label
Not a good fit whenthe data is very large and must be rerun constantly, or when you must explain the split to non-technical people — then k-means is much easier to defend
07

Pros and cons

Drops the hardest parameter and catches clusters of different density. You pay with speed, memory, and a mechanism that is much harder to explain.

DBSCANHDBSCAN
Main parameterseps + min_samples — eps is very hard to setmin_cluster_size — has a business meaning
Mixed-density clustersFailsHandled — each cluster at its own level
NoiseLabel −1Label −1 plus a cluster-membership probability
Intermediate outputCluster labels onlyThe whole hierarchy — see which cluster split from which

Explaining to othersTwo sentences and doneHard — you must talk about trees and stability
Assigning new pointsNot supportedHas approximate_predict
  • By default it gives quite a lot of noise: any point not sitting snugly in a stable branch is −1.
  • Not in core scikit-learn: install hdbscan separately, or use sklearn.cluster.HDBSCAN, available from version 1.3 on.
  • It does not fix the high-dimension problem: density still loses meaning in high dimensions, so reducing dimensions first is still mandatory.
08

Common mistakes

Fewer parameters does not mean fewer ways to misuse it.

Thinking it drops every parameter

min_cluster_size still shapes the result strongly. It is just easier to set than eps, not something you can skip.

Not standardizing the scales

It still relies on distance like every algorithm in the group. A column with a big unit still drowns out the rest.

Running directly on embeddings with hundreds of dimensions

Density loses meaning in high dimensions. Reduce dimensions first — UMAP is the usual partner.

Panicking at a lot of noise

Noise is a meaningful result, not an error. If you must force everything into clusters, use probabilities_.

Scoring with silhouette and concluding it is worse than k-means

A measure that favors round clusters. Comparing two families with different assumptions using it is a wrong comparison.

Using it when every cluster clearly has the same density

Then DBSCAN is simpler, faster and easier to explain.
