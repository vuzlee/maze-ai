HDBSCAN

HDBSCAN builds the whole tree of density clusters from one spanning tree, then keeps the branches that last longest — no eps to choose.

01

Mental model

Measure how crowded each point is, join all points into one tree, cut it from the longest edge down, and keep the pieces that survive.

  • It is DBSCAN without a fixed eps: clusters of different density, like A B C and G H I J here, come out together.
  • Points that never join a lasting piece are noise, label −1, as in DBSCAN.
02

Core distance

A point's core distance is the radius it needs to hold min_samples points, itself included.

corek(a)core distance of a = d(a, k-th nearest point)k = min_samples, a counts as the first
  • Small radius = dense neighbourhood; large radius = sparse. It is DBSCAN's core-point test turned into a number.
  • It is still a distance: scale the features first, or one large unit decides every radius.
03

Mutual reachability distance

Two points are never closer than either one's core distance: sparse points get pushed away.

dmreach(a, b)new distance = max( core(a), core(b)density of each end , d(a, b) )plain distance
  • Inside a crowd nothing changes; a lone point like K is far from everything, so it joins the tree late.
04

Minimum spanning tree

Join all points with the cheapest set of edges under mutual reachability: n − 1 edges, no loop.

  • Kruskal: sort the edges, take each one that joins two separate pieces (the union-find of DSA). Prim grows the same tree from one point.
  • This tree holds every DBSCAN result at once — section 09.
05

Cluster hierarchy

Remove the tree's edges longest first: each removal splits a piece, and the splits stacked by height form a dendrogram.

  • This is single-linkage hierarchical clustering on the mutual reachability distance.
  • A dendrogram with 12 leaves has 11 merges — too many pieces, mostly single points. The next step prunes it.
06

Condensed tree

A split counts only if both sides have at least min_cluster_size points; a smaller side is points falling out.

  • Each cluster now has a life: it is born at a real split and ends when its points fall out or it splits again.
  • Distance turns into λ = 1 / d: a cluster lives from a small λ (loose) to a large λ (dense).
07

Stability & selection

A cluster's stability is how long its points stay in it; keep the set of clusters with the largest total, never one inside another.

stability(C)area of the bar = Σp ∈ Cevery point of C ( λpλ when p leaves C − λbirth(C) )λ when C was born
  • Excess of mass (the default): bottom-up, keep the children if their stabilities sum to more than the parent's, else keep the parent.
  • Soft membership: probabilities_ scores each point 0–1 by how long it stayed in its cluster compared with the longest-staying point; noise gets 0.
08

Parameters

Two knobs instead of eps: the smallest group worth a name, and how much to smooth density.

8.1min_cluster_size

The smallest number of points that still counts as a cluster: raise it and small groups merge or become noise.

  • The main parameter, and it reads in business terms: "a segment needs at least 50 customers".

8.2min_samples

The k of the core distance: raise it and density is smoothed over more neighbours, so small dips vanish.

  • Defaults to min_cluster_size; larger values are more conservative and usually label more points noise.
09

DBSCAN at every eps

DBSCAN with one eps is one horizontal cut of this dendrogram; HDBSCAN chooses branches at whatever height each is most stable.

  • That is why it handles mixed density: the tight groups are cut low, the loose group high.
  • Costs more than one DBSCAN run, and density loses meaning in hundreds of dimensions — reduce embeddings first (UMAP is the usual partner).
