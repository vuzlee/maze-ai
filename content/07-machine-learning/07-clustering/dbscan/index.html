DBSCAN

Change one assumption and everything changes: a cluster is not a round shape around a centroid but a region of high density, as wide as its connections reach.

01

Mental model

The lesson is the seven parts below. Every later section redraws this map and highlights the box being studied, so wherever you are you know where you stand.

02

The problem it solves

The three places k-means fails all come from one spot: it must have centroids, and centroids imply round clusters.

K-means is helpless when

clusters are arcs, two concentric rings, S shapes — no centroid lies inside the cluster

there are real outliers — every point must belong to a cluster, and outliers drag centroids off

k is unknown in advance — and no business constraint sets it

DBSCAN changes the definition of a cluster

cluster = a connected crowded region, any shape at all

points in sparse regions are simply called noise, not forced anywhere

it does not take k; the number of clusters is an output, not an input

  • In exchange there are two other parameters: eps — the radius that counts as "near" — and min_samples — how many neighbors count as "dense".
  • It does not drop parameters, it swaps them. Choosing eps is harder than choosing k because it is a distance in standardized space.
  • Short for Density-Based Spatial Clustering of Applications with Noise — the last two words are often forgotten: noise is a first-class citizen.
03

Core idea — three kinds of point

Everything is built on one question asked of each point: within radius eps around it, are there enough min_samples neighbors.

border< m
noise—

core: dense enough, may grow the clusterborder: near a core but does not grow itnoise: belongs to no cluster

Core pointhas ≥ min_samples points within radius eps — the nucleus; a cluster spreads by linking neighboring core points
Border pointnot dense enough, but within the radius of a core point — belongs to that cluster but does not grow it further
Noise pointnot dense enough, and not near any core point — label −1, belongs to no cluster
  • A cluster's boundary is where density drops below the threshold, not where two centroids are equidistant — so clusters can be as long and curved as they like.
  • Two core points closer than eps are certainly in the same cluster. The relation chains, so a cluster stretches across many steps.
  • Border points are the only non-deterministic part: a point near two clusters belongs to whichever cluster finds it first.
04

Mechanism

There is no optimization loop at all. It is just a spread over the neighbor graph — each point is visited exactly once.

For each unvisited point p:
    N = points within radius eps of p
    if |N| < min_samples:  mark p as noise   ← may be rescued as border later
    else:
        open a new cluster, put p in
        spread: for each q in N not yet in a cluster
            put q in the cluster
            if q is also a core point:  add q's neighbors to N   ← cluster grows

This is exactly BFS on the graph where each point links to every point within eps of it — the only difference is that only core points may push the frontier outward.

A cluster is exactly one connected component of that graph.

  • The cost is set by the neighbor queries: with an index it is O(n log n), without one O(n²).
  • There is no randomness except the visiting order, so no need to run it many times, unlike k-means — only border points change.
  • It cannot predict new points because there is no centroid to compare against — you have to rerun it, or train a classifier on the cluster labels.
05

Loss function

DBSCAN has no loss function — and the full answer is being able to say why it cannot have one.

  • It has a definition, not an objective. k-means writes down inertia and loops to lower it. DBSCAN only declares what a core point, border point and noise are, then groups by exactly that definition. One pass and it is done — no optimization loop, and no "run that is better than another run".
  • And borrowing inertia breaks it. Measured on 440 points shaped as two crescents: the right split has inertia 2,013.4, while the split k-means picks has only 1,818.3. That numeric objective scores the wrong answer higher. When clusters are non-convex, any loss function based on distance to a centroid is meaningless.
  • In exchange, the result lies entirely in two knobs. No objective to optimize means nothing corrects itself for you: eps 0.3 gives 7 clusters, 0.5–0.9 gives exactly 2, 1.5 merges into 1. There is a right range rather than a single number, and the next section covers how to find it.
06

Choosing eps and min_samples

This is the whole hard part of DBSCAN. Move eps a little and you get a completely different result, with nothing to warn you.

eps too smallalmost everything becomes noise
eps at the k-distance elbowusable region
eps too largeall clusters merge into one

shattered, data lostno wide safe zone — you must searchall merged, no distinction

The standard way to choose eps — the k-distance plot.

  • For each point, compute the distance to its k = min_samples-th neighbor.
  • Sort ascending and plot: the curve is flat at the start — points inside dense regions.
  • Then it shoots up at the end, where points are sparse — take eps at that break.
min_samplesset around 2 × the number of dimensions, raise it if noisy · higher → fewer core points, more noise, firmer clusters
epsread off the k-distance plot with exactly k = min_samples · higher → clusters grow and then merge, noise disappears
metricEuclidean by default; cosine for text
  • You must standardize the scales first. eps is one single number applied to every dimension.
  • Salary in millions, age in years — without bringing them to the same scale, eps only means something for the salary column.
  • This is the mistake that ruins DBSCAN results most often.
07

Where it is used

Strongest on data with real coordinates and on problems where finding the odd points is the goal.

Geospatial datagroup GPS points into areas · detect outbreak hotspots · group trips by route — exactly the problem it was designed for
Anomaly detectionthe −1 label is exactly the output you want: lone transactions, sensors drifting out of the normal region
Cleaning before the real clusteringrun DBSCAN to filter noise, then run another algorithm on what is left
High-dimensional dataimages, text embeddings — reduce dimensions first, and consider HDBSCAN since density is usually uneven
08

Pros and cons

You get arbitrary cluster shapes and a notion of noise. You pay with a parameter that is harder to choose, and a blind spot about density.

K-means

Cluster shape round / convex only

Number of clusters set by a person

Outliers forced into a cluster

Uneven density copes so-so

High dimensions degrades gradually

New points compare to k centroids, instant

Cost O(n · k · d) per round

DBSCAN

Cluster shape any

Number of clusters found by the algorithm

Outliers labeled as noise

Uneven density fails — one eps cannot fit both

High dimensions degrades faster — density loses meaning early

New points not supported

Cost O(n log n) with an index, O(n²) without

  • The real dead spot is clusters of different density: an eps that fits the dense cluster turns the sparse one into noise, and vice versa.
  • That is what HDBSCAN was born to fix: run DBSCAN at every eps level and keep the most stable clusters.
  • DBSCAN gives non-round clusters, so do not score it with silhouette: that measure favors round clusters, and a correct split still scores low.
09

Common mistakes

DBSCAN does not raise an error when parameters are wrong — it just returns a single cluster, or all noise.

Not standardizing the scales

One eps applies to every dimension. Without a common scale it only means something for the column with the biggest unit.

Guessing eps without plotting k-distance

Hours lost trying numbers. The k-distance plot gives you the range worth trying in a minute.

Treating label −1 as a cluster

Noise is not cluster number n. Count clusters without excluding −1 and you count one too many.

Using it when clusters have clearly different densities

No eps is right for both the dense and the sparse cluster. This is when to use HDBSCAN.

Scoring with silhouette

A measure that favors round clusters, unfairly penalizing the curved clusters DBSCAN splits correctly.

Expecting it to assign clusters to new data

There is no predict. If you need online assignment, train a classifier on the cluster labels.
