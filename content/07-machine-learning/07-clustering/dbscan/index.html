DBSCAN

DBSCAN draws a circle of radius eps around every point and chains the crowded circles together, so a cluster takes any shape and lonely points are left out as noise.

01

Mental model

A cluster is a crowded region: crowded points whose circles overlap belong together, whatever the shape.

  • Two settings: the radius eps and min_samples, how many points make a circle crowded. The number of clusters comes out, it is not put in.
  • The curved run is one cluster here; K-means would cut it into round pieces and force M and N into a cluster.
  • Used where shapes are odd and outliers matter: GPS traces, hot spots on a map, anomaly flags (label -1).
02

Point types

Count the points inside each circle; the count and who is inside give every point one of three types.

Nε(p)neighbourhood of p = { q : ‖p − q‖ ≤ ε }points inside the circle, p included
p is corecrowded ⇔ |Nε(p)| ≥ min_samplesenough points inside

2.1Core point

At least min_samples points inside its circle, itself included.

  • Only core points spread a cluster; they form its dense inside.
  • scikit-learn counts the point itself, so min_samples = 4 means the point plus three others.

2.2Border point

Not crowded itself, but a core point lies inside its circle.

  • Border points sit on the edge of a cluster: they belong to it but do not extend it.

2.3Noise point

Not crowded and no core point inside its circle: it belongs to no cluster.

  • Noise gets the label -1 in labels_; DBSCAN is never forced to place every point.
03

Expansion

Start at an unvisited core point and spread neighbour by neighbour, like a BFS; only core points pass it on.

  • The chain is what lets a cluster bend: A and G are far apart but linked through B…F (BFS over the "inside my circle" graph).
  • A border point within reach of two clusters goes to the one that reaches it first, so it depends on the data order; core points never do.
  • No loss is optimised and nothing is learned: there is no predict for new points, only fit_predict.
04

Choosing the parameters

Pick min_samples from the number of dimensions, then read eps off the data.

4.1eps · k-distance plot

Sort every point's distance to its k-th nearest point (k = min_samples); put eps at the knee.

  • Flat part: points inside a cluster. Steep part: edges and outliers. The knee separates them.
  • eps is a distance, so scale the features first (StandardScaler); otherwise the column with the largest units decides.

4.2min_samples

Rule of thumb: at least dimensions + 1, often 2 × dimensions; raise it for noisy data.

  • Too small (1 or 2): every stray pair is a cluster. Too large: whole clusters drop to noise.
  • Change min_samples and redo the k-distance plot: k follows it.
05

Different densities

One eps serves the whole data set, so a tight cluster and a loose cluster cannot both be found.

  • The same wall in high dimensions: distances bunch together and no eps separates crowded from lonely.
  • HDBSCAN tries every eps at once and keeps the clusters that last longest.
