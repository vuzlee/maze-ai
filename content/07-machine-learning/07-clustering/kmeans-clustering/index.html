K-means & clustering

The algorithm fits in ten lines of code. The real questions are how to choose k and when its output is meaningless.

01

Mental model

The lesson is the five parts below. Every later section redraws this map and highlights the box being studied.

02

The problem it solves

Nobody labels anything for you. There is just a table of numbers, and the question "how many natural groups are in here".

Ten thousand customers, each with a few dozen numbers: age, purchase frequency, average order value, days since last purchase.

  • No column says this is a loyal customer or this customer is about to leave — if one did, it would already be a supervised problem.
  • The job is to find out for yourself: who is similar enough to be treated as one group.
Table of numbers, no labels

10,000 customers · a few dozen columns

assume→
Each group has a centroid

one central point representing the whole group

so→
Each customer belongs to the nearest centroid

the assignment rule, nothing more

The whole algorithm is just finding those k centroids.

  • The input is k — the number of clusters — which a person must set in advance. It is both the biggest weakness and the reason it runs fast.
  • The output is one cluster label per point plus k centroid coordinates. The centroid is the group's "average customer".
  • There is no right answer to compare against, so there is no accuracy. Every measure here is indirect — see section 03.
03

Mechanism — a two-step loop

Assign points to the nearest centroid, then move each centroid to the middle of the points it just got. Repeat until nobody changes cluster.

Inertia = Σ ‖ xₓ − μc(i) ‖²sum of squared distances to each point's own centroid

The assign step holds μ fixed and chooses c(i) to reduce inertia. The update step holds c fixed and chooses μ to reduce inertia.

Because each step can only lower inertia or keep it the same, and the number of possible partitions is finite, the algorithm is guaranteed to stop.

But where it stops is only a local minimum, not the best partition — just as the calculus lesson said about non-convex functions.

  • That is why libraries rerun it many times with different initializations and keep the run with the lowest inertia. Do not lower n_init to 1.
  • k-means++ picks initial centroids far apart instead of at random. Cheap, and less likely to land in a bad minimum — it is now the default.
  • Each round costs O(n · k · d) — the reason k-means survives even though better algorithms exist.
04

Loss function

k-means does have a loss function you can write down — inertia — and the two steps in the previous section are just a way of lowering it.

  • Both steps can only lower inertia. The assign step holds the centroids fixed and lets each point pick the nearest one, so its term shrinks. The update step holds the labels fixed and puts the centroid at the cluster mean — exactly the point that minimizes the sum of squares. The number of partitions is finite, so the algorithm is guaranteed to stop.
  • But inertia is non-convex, so no one promises where it stops. Measured on 600 points with 4 real clusters, 50 runs with k = 4: best run 982.6, worst run 3,125.3 — over three times apart on the same data. k-means++ only cuts the stuck runs from 3/50 to 2/50; it does not eliminate them. The only sure fix is a large n_init.
  • Do not use inertia itself to choose k. It always falls as k rises — with k equal to the number of points it is 0. In the table, 3,220 drops to 982 at k = 4 and then levels off (884, 801, 713): the break is the signal, not the smallest value. The next section covers a score with a real maximum.
05

Choosing k

Inertia always falls as k grows — at k = n it is 0. So you cannot choose k by looking for the smallest inertia.

Elbow — look for the break

Plot inertia against k. The point where the curve bends like an elbow is a candidate.

The problem: a lot of real data gives a smooth curve with no clear elbow. Then the elbow answers nothing.

Silhouette — score every point

For each point: b − amax(a, b), where a is the mean distance to its own cluster and b to the nearest other cluster.

From −1 to 1. Near 1 means sitting snugly in its own cluster; negative means it is assigned to the wrong cluster.

  • Silhouette has a maximum, so it can be chosen automatically, unlike inertia. This is the default measure to use.
  • But it favors round clusters: arc-shaped clusters score low even when split correctly. Do not use it to compare k-means with DBSCAN.
  • Often business constraints choose k: if marketing can run three campaigns, k = 3, even if silhouette says 7.

06

The hidden assumptions of k-means

K-means never raises an error. If the clusters have the wrong shape, it still returns a split that looks very confident.

Clusters are round, spread evenly around the centroidbreaks on long ellipses, C shapes, two concentric rings → cuts across real clusters, splitting what should be one
Clusters are of similar sizebreaks when a 9,000-point cluster sits next to a 200-point one → the big cluster is torn in two, the small one swallowed
Clusters have similar densitybreaks when a dense region sits next to a sparse one → the boundary gets pushed toward the sparse region
Every point belongs to a clusterbreaks when the data has real outliers → outliers drag the centroids off, and there is no notion of a "noise point"
  • Standardizing the scales first is mandatory. Euclidean distance adds up the differences in every column — a salary column drowns out an age column, just like KNN.
  • In high dimensions all distances draw close together and "nearest" loses its meaning. Reduce dimensions with PCA before clustering.
  • When an assumption breaks, change the algorithm family rather than tuning parameters: arbitrary shapes, noise → DBSCAN; overlapping → Gaussian Mixture.
07

Pros and cons

Every strength of k-means comes from keeping only k centroids. Every weakness comes from exactly the same place.

AspectProsCons
SpeedLinear in the number of points — runs on millions of rows—
ModelCompact: only k centroid coordinates, assigning a new point is one distance comparison—
Results—Depends on initialization, each run is different
Cluster shape—Only finds round clusters of similar size and density
Noise—No notion of a noise point — outliers drag centroids off
Preparation—Must set k in advance, and standardizing scales is mandatory
  • Choose k-means when the data is large and the clusters are fairly well separated: customer segmentation, image color quantization, grouping vectors to build an index.
  • When the assumptions above break, change the algorithm family rather than tuning parameters: arbitrary shapes, noise → DBSCAN.
  • Always run it many times with different initializations (n_init) and keep the run with the lowest inertia.
08

Common mistakes

Most mistakes do not make the program crash — they produce a result that looks reasonable but is meaningless.

Not standardizing the scales

The column with the biggest unit decides the whole split. The most common mistake, and the most silent.

Feeding one-hot categorical variables in directly

The distance between two one-hot values is always √2, carrying no information. You need k-prototypes or a different encoding.

Choosing k by the smallest inertia

Always picks the largest k tried. Inertia is only for looking at the shape of the curve.

Setting n_init=1 to save time

One bad initialization gives one bad result, and nothing tells you.

Naming a cluster and believing it

Call cluster 2 "VIP customers" and from then on everyone treats it as fact. Check it against outside data first.

Comparing clusters across two runs by their index

Cluster labels are arbitrary numbers — cluster 0 this run may be cluster 2 next run. Match them by centroid.
