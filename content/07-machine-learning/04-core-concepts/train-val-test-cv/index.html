Train/val/test & cross-validation

Split wrong once and every number after that is meaningless. This lesson settles: why three sets, which kind of split to choose, and the six sources of data leakage that make offline scores look great while production collapses.

01

Mental model

The whole lesson is the six ideas below. Each section redraws this map and highlights the box being studied.

02

Why three sets, not two

The validation set is used to choose, so it is already contaminated. You need a third set that has never influenced any decision.

train · 60%learn the model's parameters
validation · 20%choose hyperparameters, choose the model, decide when to stop — looked at again and again
test · 20%measure final performance, opened exactly once

Every time you look at the validation score and change something, you are optimizing on the validation set itself.

Try 100 configurations and keep the highest-scoring one, and the winner has been selected for luck, so it is systematically optimistic.

Even when every configuration is actually equally good:

true quality of every configuration0.70
validation score of the winning configuration0.78 — just the luckiest of 100
test score of that same configuration0.70 — the truth
  • Once you have seen the test score, you may not change the model and measure again.
  • Doing so turns test into validation, and no set is left for an unbiased evaluation.
  • How to keep the discipline: lock the test set away, and open it only when every decision is final.
03

k-fold cross-validation

A single split leaves the result at the mercy of that split's luck. k-fold rotates every part through validation and averages — every sample is used for evaluation exactly once.

  • Don't look only at the mean: the standard deviation across folds is what tells you whether the number can be trusted.
  • k = 5 or 10 is a good default. Larger k means less bias but costs k times as much and fluctuates more.
  • Use CV when data is scarce. With plenty of data, three fixed sets are reliable enough and much cheaper.
04

Choosing the right split

A random split is only correct when samples are independent and identically distributed. Real data often is not — and each kind of violation has its own split to fix it.

TypeHow it splitsUse when
K-foldSplit into k parts, rotate one part as validationIndependent, identically distributed data
Stratified K-foldKeep the same class ratio in every foldClassification — always worth using, especially with class imbalance
Group K-foldAll rows of one group stay in the same foldMany rows from the same patient, customer or device
Time series splitAlways train on the past, validate on the futureAny time-ordered data — never shuffle
Leave-one-outk = nVery little data; expensive and high variance
Shuffling time-series dataThe model learns from the future and then predicts the past. The score looks great and is completely unusable.
The same entity on both sidesPatient A has 50 rows, some go to train and some to validation — the model recognizes the patient instead of learning the disease. Use Group K-fold.
Duplicate rowsThe original in train and the duplicate in validation inflate the score. Deduplicate before splitting.
05

Data leakage

Leakage is when information that would not be available at prediction time slips into training. The common trait: great offline scores, production collapses.

SourceConcrete exampleFix
Preprocessing before splittingStandardScaler fit on the whole dataset — the mean and standard deviation already contain information from the test setPut every step in a Pipeline, fit only on train
Label leakage through featuresPredicting whether a customer will churn, with a cancel_date or cancel_reason column in the dataFor each feature, ask: is this value available at prediction time?
Temporal leakageA "total customer spend" feature computed over the full history, including after the prediction timeEvery aggregate feature must be cut off at the prediction timestamp
Group leakageThe same patient, store or device appears in both train and testGroup K-fold
Feature selection on the full datasetPick the 20 features most correlated with the label before splittingSelect features inside each fold
Resampling before splittingSMOTE or oversampling on the full data puts copies of one sample on both sidesResample only on the training set of each fold
# WRONG — the scaler sees the test set
X_scaled = StandardScaler().fit_transform(X)
X_tr, X_te = train_test_split(X_scaled, ...)

# RIGHT — the pipeline guarantees every step fits only on train
from sklearn.pipeline import make_pipeline
pipe = make_pipeline(StandardScaler(), SelectKBest(k=20), LogisticRegression())
cross_val_score(pipe, X, y, cv=5)      # each fold refits from scratch

06

Nested CV

Using one validation set both to choose hyperparameters and to report the score is optimistic. Nested CV separates the two jobs with two nested loops.

All the data

nothing touched yet

outer loop · 5 rounds→
Held-out part for measuring

takes no part in any choice

inner loop · 3 rounds→
Chosen hyperparameters

chosen without looking at the held-out part

measured exactly once→
Unbiased score

this is the number you report

5 × 3 = 15 training runs per configurationwhich is why few use it on large data

SituationUse
Large dataThree fixed sets — simple, reliable enough, cheap
Small data, need a trustworthy number to reportNested CV
Only need to choose a model to deployPlain CV is enough; no outer loop needed

In practice nested CV is rarely used because it is expensive — three fixed sets are enough when data is plentiful.

But knowing it exists and knowing what problem it fixes is worth mentioning when asked how to report performance.

08

Common mistakes

Scaling before splitting the data

The most common leak, and almost always present in rushed code. Use a Pipeline.

Shuffling time-series data

Training on the future. The score is completely meaningless.

Same entity in both train and test

The model recognizes the entity instead of learning the pattern. Use Group K-fold.

Using the test set multiple times

It becomes a validation set, and you have nothing left for an unbiased evaluation.

SMOTE before splitting

Synthetic copies of one sample end up on both sides. Resample only on train.

Looking only at the fold mean

Ignore the standard deviation and you can't tell whether the number is stable or just the luck of one split.
