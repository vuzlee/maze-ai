Bias–variance tradeoff

The thread running through the whole shelf: almost every ML technique trades bias for variance or the other way round. This lesson splits error into three parts, then shows which technique targets which part.

01

Mental model

The lesson is the five ideas below. Each later section redraws this map and highlights the cell being studied.

02

Error decomposition

A model's error isn't one lump. It splits into three sources of different nature — and each source needs a different fix.

E[(y − f̂(x))2] = ( E[f̂(x)] − f(x) )2bias² + E[( f̂(x) − E[f̂(x)] )2]variance + σ2noise
f(x)
the truth, fixed and never knowable
f̂(x)
the learned model — changes when the training set changes
E[·]
expectation over every training set that could be drawn

Reading: systematic deviation from the truth, plus fluctuation around itself, plus the noise nobody can touch.

BiasVariance
MeaningThe model deviates systematically from the truthThe model fluctuates when the training set changes
AnalogyAims off-center but shots are tightly groupedAims at the center but shots scatter everywhere
Example modelLinear regression on curved dataDeep, unpruned decision tree
Reduced byA stronger model, better featuresMore data, ensembles, regularization

A detail worth remembering: noise σ² is a floor you can't break through.

  • Two customers with identical features, one buys and one doesn't — no model can predict both correctly.
  • Once validation error has hit that floor, the fix is new features — not more model capacity.

One sentence to remember

The goal is neither the smallest bias nor the smallest variance, but the smallest total. That's why every regularization technique is the same deal: give up a little bias to win back a lot of variance.
03

What high bias looks like

High bias means the model isn't expressive enough for the real relationship. The tell-tale sign: lots of error on the training set too, not just on new data.

Fit a straight line to parabola-shaped data: however many points you add, the line stays off.

More data fixes nothing, because the error lies in the model's shape, not in the amount of data. Two error numbers give it away immediately:

error on train sethigh
error on test sethigh, about equal

both bars high and close↑ sign of high biassmall gap

  • Fixes: new features (x², interaction terms), a stronger model, longer training, or less of a regularization that is too heavy.
  • Underfitting is rarely missed because it shows right away — the numbers are bad everywhere. Overfitting is more dangerous because it gives fake good numbers.
04

What high variance looks like

High variance means the model memorizes even the random noise of the data at hand. The sign: nearly perfect on the training set, a sharp drop on new data.

A test to grasp the essence: retrain the same model on two different halves of the data.

  • A low-variance model gives two nearly identical results.
  • A high-variance model gives two very different models — because each time it chases the noise of that half.
Gap between the two curves

Train error very low, validation error much higher.

The gap between the two numbers is the measure of variance.

Level of both curves

Both high and stuck together.

That shared level is the measure of bias.

  • Read the two numbers along two dimensions: level is bias, gap is variance. Details in Overfitting & regularization.
  • Noise is exactly what the model memorizes. The less and noisier the data, the more easily a model falls into this.
05

Tradeoff curve

Push model complexity from low to high: bias falls steadily, variance rises steadily, and their sum is U-shaped. The bottom of the U is where to stop.

  • The bottom of the U is not where bias is smallest: the best model always keeps some bias, trading deviation for stability.
  • "Complexity" depends on the model: polynomial degree, max_depth, number of network layers, the inverse of the regularization strength. Same curve shape.
  • For very large neural networks there is double descent: once parameters far exceed samples, test error falls again.
06

Lab: turn up complexity

Fit a degree-d polynomial to the same dataset. Raise the degree to see the U curve from the section above appear in real numbers.

train error – validation error – diagnosis –

Degree 0: both errors very high — clear underfit. Degree 2–3: both lowest — just right, matching the degree of the true function.

Degree 5: train error drops to 0 because the polynomial passes exactly through all 6 train points, but validation error doubles — overfit.

There are only 6 train points, so the maximum degree is 5.

Untick noise to see that with perfectly clean data a high degree does less harm: noise is exactly what the model memorizes.

07

Which technique targets which part

Read this table backwards: diagnose bias or variance first, then pick the technique. Picking the wrong direction makes the model worse.

TechniqueBiasVarianceNotes
More dataunchangeddrops sharplyUseless when the problem is bias — draw a learning curve to tell
Stronger regularizationrisesdropsThe classic deal: lose a little bias, win back a lot of variance
More features, stronger modeldropsrisesThe reverse side of the same deal
Bagging — Random Forestalmost unchangeddrops sharplyAverages many trees; the less alike the trees, the better it works
Boosting — GBM, XGBoostdrops sharplyrises with roundsNeeds early stopping, or it will certainly overfit
Early stoppingrises slightlydropsCheapest in the table — adds no parameters
  • The two ensemble rows show that bagging and boosting target different parts. See Tree family overview.
  • That's why Random Forest beats a single tree on both fronts: it cuts variance while losing almost no bias.
