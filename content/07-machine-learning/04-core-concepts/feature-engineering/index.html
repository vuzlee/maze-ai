Feature engineering

On tabular data this often gains more than switching models. Three things to remember:

  • models read numbers only: encode, fill, scale without inventing meaning
  • new columns such as ratios, powers, time parts hand the model relationships it cannot add up itself
  • every step is fit on train only, or it leaks
01

Mental model

A raw row goes in; a row of meaningful numbers comes out, one transformation per column.

  • Fit every transformation on the training set only — see Train/val/test & cross-validation.
  • For images, audio and text, let a neural network learn the features instead.
02

Categorical variables

Turn text into numbers without inventing an order that is not there.

2.1One-hot encoding

Each value gets its own 0/1 column.

  • Default for few values (under ~15) and for linear models.

2.2Ordinal encoding

Map each value to a rank — correct only when the values really are ordered.

  • Trees cope with a wrong order better, but waste splits on it.

2.3Target encoding

Replace each value by the mean label of its group — compact for thousands of values.

enc(c) = nc · ȳc + m · ȳnc + mgroup mean, pulled toward the global mean
ȳc, nc
mean label and row count of value c
ȳ, m
global mean label, and how many rows of trust it gets
  • Small groups lean on the global mean, so a one-row group cannot copy its own label.

2.4Feature hashing

Hash each value into one of a fixed number of columns.

  • Use it when the set of values is unknown in advance, as in streaming data.
03

Missing values

Ask why a value is missing before choosing what to fill it with.

3.1Imputation

Fill numeric blanks with the median, categorical blanks with the most common value.

  • XGBoost and LightGBM handle blanks inside the algorithm: each split learns where to send them.
  • Dropping rows with blanks can delete a whole kind of customer.

3.2Missing with meaning

When the blank itself predicts the label, keep it as a flag column.

04

Scaling

Models that use distances or gradients need columns on the same scale; trees do not.

4.1Why scale

In a distance, the column with the largest units decides almost everything.

  • Trees only compare thresholds inside one column, so units do not matter.
  • L1/L2 penalties act on weights, and weights depend on units — see Overfitting & regularization.

4.2Standardisation and min-max

Standardise to mean 0 and spread 1, or squeeze into 0 to 1.

z = x − μσstandardisation
x′ = x − minmax − minmin-max
  • Standardisation is the default; one outlier squashes min-max.
  • Log-transform skewed columns (income, view counts) before scaling; RobustScaler uses median and quartiles.
05

New features

A linear model only adds columns. A product, a ratio or a curve must be handed to it as a column.

5.1Ratios and interactions

Divide or multiply two columns to expose a relationship neither shows alone.

  • Trees and boosting find interactions themselves; domain knowledge such as "days since last complaint" is what they cannot invent.

5.2Nonlinear terms

Add x2 or log x so a linear model can follow a curve.

  • Every added column adds variance — more features is not always better.

5.3Time features

Break a timestamp into cycles and recency.

  • Aggregates over history ("spend in the last 30 days") are the top source of leakage: cut them at the prediction time.
