Feature engineering

On tabular data, this is usually where you gain more than by switching models. Four jobs — encode, impute, scale, create new features — each with one question attached: does the model I'm using actually need this.

01

Mental model

The whole lesson is the four ideas below. Each later section redraws this map and highlights the box being covered.

02

Categorical variables

Models only take numbers. The problem is turning text into numbers without inventing an order that isn't there.

MethodMechanismUse whenCost
One-hotEach value becomes a 0/1 columnFew distinct values (under ~15), linear modelsDimensionality explodes with many values
OrdinalAssign integers in orderValues really are ordered — small/medium/largeInvents an order if used in the wrong place
Target encodingReplace each value with the mean label of its groupVery many values — postal codes, product IDsLabel leakage if you're not careful
HashingHash values into n fixed bucketsNumber of values unknown in advance, streaming dataHash collisions, loss of interpretability

The quietest bug in the table is ordinal on a variable with no inherent order:

1Paris
2Rome
3Berlin

assign integers to three citiesa linear model reads it as: Rome lies between the other two citiesa relationship that doesn't exist

  • Trees suffer less because they only split on thresholds — but they spend many splits on what should take one.

Target encoding, on the other hand, leaks like this: the row's own label goes into the number used to encode it.

product IDAlabel 1
product IDAlabel 0
product IDAlabel 1
product ID — only 1 rowZlabel 0
encoded column0.67mean of 3 rows
encoded column0.67

encoded column0.00is the label itself

for a large group, the mean is still a meanfor a one-row group, the encoded column copies the label — the model just reads it off

  • Fix it with three things: compute the mean within each fold, leave the current row out, smooth toward the global mean.
03

Missing values

The question isn't "what to fill it with" but why it is missing — the fact of being missing often carries information.

Missing at random

Broken sensor, logging error.

Handling fill with the median (numeric) or mode (categorical).

Nothing significant is lost.

Missing with meaning

Income left blank because it's low; no history because the customer is new.

Handling fill and add a was_missing flag column.

Dropping the flag column throws away a strong signal.

  • XGBoost and LightGBM handle missing values inside the algorithm: each node learns which branch to send them to.
  • Dropping rows with missing values is a dangerous choice: if the missingness isn't random, you've just deleted a specific subpopulation.
  • Every imputation step must be fit on the training set and then applied to the evaluation sets — see Train/val/test & cross-validation.
04

Scaling

Not every model needs it. Whether it does depends on whether the model uses distances or gradients.

ModelNeeds scaling?Why
Trees, Random Forest, Gradient BoostingNoOnly compares thresholds within each column; units don't matter
KNN, SVM, K-meansRequiredUses distances — a column with large units drowns out all the others
Linear regression with regularizationRequiredThe L1/L2 penalty applies to the weights, and the weights depend on units
Neural networksRequiredGradient descent converges slowly and unstably when dimensions are on different scales
Plain linear regressionNot requiredThe solution doesn't change; it only helps iterative solvers converge faster

Why distance-based models require it: when two columns differ in units, the large one swallows the other.

income gap (VND)2,000,000 — contributes nearly all of the distance
age gap (years)5 — as good as nonexistent

the same Euclidean distanceafter scaling, the two columns finally weigh the same

Standardization

Shift to mean 0, standard deviation 1.

Good default — tolerates moderate outliers.

Min-max

Squeeze into the range [0, 1].

Use it when you need clear bounds, but one big enough outlier pushes everything else close to 0.

  • Heavily skewed features — income, view counts — should be log-transformed before scaling.
  • With data full of outliers, RobustScaler uses the median and interquartile range and is far safer than the two above.
05

Creating new features

A linear model only adds columns together. If you want it to see a multiplicative or curved relationship, you have to feed it that column ready-made.

TypeExampleWhat it captures
Ratiodebt / income, price / areaA relationship that neither column shows on its own
Interactionage × incomeThe effect of one column depends on the other
Nonlinearx², log(x)Curved relationships
TimeDay of week, hour of day, days since last purchaseCycles and recency — a raw timestamp column is nearly useless
Group aggregatesCustomer's average spend over the last 30 daysHistorical context; must be cut off at the prediction time

Trees and ensembles find interactions on their own — every path from root to leaf is itself a combination of conditions.

  • On tabular data with boosting, effort spent on interaction features usually pays off little.
  • Far more worth the effort are features that carry new domain information: a column like "days since the last complaint" is something no algorithm can invent by itself.
  • The general dividing line: on tabular data, feature engineering decides the result; for images, audio and text, let the neural network learn the features.
  • More features is not better: every added column adds variance — see Overfitting & regularization.
  • Group aggregate features are the number one source of leakage: it is very easy to average over future data too.
06

Common mistakes

Target encoding computed on the whole dataset

The row's own label leaks into the encoded column. Compute it within each fold and leave the current row out.

Fitting the scaler before splitting the data

The mean and standard deviation already contain information from the evaluation set. Use a Pipeline.

Ordinal on a variable with no order

Invents a greater/less relationship between cities or categories. Use one-hot.

One-hot on a column with thousands of values

Dimensionality explodes, the matrix is sparse, the model is slow and overfits. Use target encoding or hashing.

Imputing missing values, then dropping the flag column

Throws away the "why it's missing" information, which is often a stronger signal than the imputed value itself.

Aggregate features not cut off by time

The mean is computed over future data too. Great offline score, collapse in production.
