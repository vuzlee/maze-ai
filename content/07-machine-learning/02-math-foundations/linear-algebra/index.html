Linear algebra

Data is a matrix, a model is a transformation. Three things to remember:

  • matrix multiplication is a change of coordinates, not cell-by-cell multiplication
  • rank is the true number of dimensions left after a transformation
  • an eigenvector is a direction that does not rotate — the root of PCA
01

Mental model

One row of data is one arrow. Many rows stacked are a table of numbers. A model is a transformation of that table.

  • The four things above are the whole lesson, and they share one set of numbers that runs through every section.
02

Vectors & dot product

The dot product of two vectors is one number measuring how much they point the same way.

a · b = a₁b₁ + a₂b₂ + … + anbnmultiply each pair, then add up

Divide the dot product by the lengths of the two vectors to get cosine similarity.

It ignores length and compares only direction — exactly what you need when comparing two texts of different lengths.

  • A customer aged 28 with income 15 and 7 orders is the vector [28, 15, 7]. A 28×28 image is a 784-dimensional vector. A word in a language model is a vector of a few hundred dimensions — called an embedding.
  • A linear model predicts with exactly one dot product: ŷ = w · x + b.
  • Semantic search, recommender systems and retrieval in RAG all come down to finding the vector with the highest cosine to the query vector.
  • The dot product sums over every dimension, so large-valued features dominate. You must scale features before linear models, KNN, SVM.
03

Reading matrix multiplication

Matrix multiplication is just many dot products done at once.

How to read a multiplication in a paper: look at the shapes first, the contents after.

(n×d)·(d×k) means "move n rows of data from a d-dimensional space into a k-dimensional space".

Every layer of a neural network and every projection in attention reads this way.

  • Matrix form exists to run fast: GPUs parallelize matrix multiplication extremely well, Python loops do not.
  • Matrix multiplication is not commutative: AB ≠ BA, and BA may not even exist.
  • The most common bug when writing ML code is a shape mismatch — writing the shape next to each multiplication catches it immediately.
04

Rank & subspaces

Rank is the number of truly independent columns, often far fewer than the number of columns.

A table has 100 columns, but not every column carries new information.

A "total orders" column that equals the sum of three other columns adds no dimension.

  • Real data is almost always low-rank — columns are tangled with each other. That is what makes dimensionality reduction possible.
  • LoRA rests on exactly this idea: instead of updating the whole weight matrix, it learns only a low-rank update.
  • A rank-deficient matrix cannot be inverted: two identical columns leave linear regression without a unique solution — Ridge fixes this by adding to the diagonal.
05

Eigenvalue & eigenvector

A transformation usually both rotates and stretches a vector. A few special directions are only stretched, never rotated — those are eigenvectors, and the stretch factor is the eigenvalue.

A · v = λ · vmultiplying v by the matrix changes only its length, not its direction
A
the transformation, must be a square matrix
v
eigenvector — a direction that does not rotate
λ
eigenvalue — the stretch factor along that direction
  • Only square matrices have eigenvectors. Rectangular matrices use SVD — the same spirit, and the way PCA is actually implemented.
06

PCA from eigenvectors

Take the covariance matrix of the data table: its eigenvectors are the directions in which the data spreads most, its eigenvalues are the amount of variance along each direction.

A direction in which the data barely varies cannot tell points apart, so dropping it costs little.

The share of total eigenvalue kept is exactly the share of information kept.

  • 95% of variance in 12 dimensions instead of 100 is a very common figure for tabular data.
  • You must scale features before running PCA, otherwise the column with the largest units takes over PC1.
