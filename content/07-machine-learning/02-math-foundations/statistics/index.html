Statistics

Draw conclusions about the whole population from a sample, and do it on a live system. Four things to remember:

  • a p-value is not the probability the hypothesis is true
  • power decides how many samples you need — compute it before, not after
  • looking at results repeatedly (peeking) inflates the false-alarm rate
  • statistical significance is not practical significance
01

P-value

Almost every statistics question comes down to one thing: what a p-value says and what it does not.

  • A p-value is P(data | H₀), not P(H₀ | data) — swap the two sides and you swap the conclusion.
  • Getting the second number requires the base rate, that is, going the Bayes route.
  • It also says nothing about magnitude: with a large enough sample, a 0.01% gap still gives p < 0.05.
02

Hypothesis testing framework

The reasoning runs backwards: assume both sides are equal, then ask whether this data is too rare to believe.

  • p not small means failed to reject, not "H₀ is true".
  • A type I error is a false positive (probability α); a type II error is a false negative (probability β).
  • power = 1 − β is the chance of detecting an effect when it is real — by convention α = 0.05, power = 0.80.
03

Sample size and power

Four quantities are tied together: pick three, the fourth follows. You cannot pick all four.

  • The most important detail: n ∝ 1/MDE² — halve the MDE and you need four times the sample.
  • Go the other way: ask what smallest lift is worth shipping, use that as the MDE, then look at the number of days.
  • If it comes out too long, the right conclusion is the test isn't worth running, not run it anyway and peek early.
04

Confidence interval

Same +3.2% lift, but the width of the interval is what decides what to do next.

  • Narrow interval above the threshold → ship; wide interval including negatives → know nothing yet, lacking power.
  • Correct meaning: "95% of intervals built this way contain the true value" — the interval is random, the true value is fixed.
  • Always report the effect size with its interval: a p-value only answers "is it different from 0".
05

Multiple comparisons

The more metrics you measure, the more certain you are to find "an interesting finding" — even when nothing is real.

  • 20 metrics at α = 0.05 give a 64% chance of at least one false positive.
  • Bonferroni is simple but conservative; Holm always beats it; BH fits when discovery is the priority.
  • Cheaper than any correction: fix one primary metric before running — how to fix it is in the checklist at the end.
06

Correlation and causation

One observation, four explanations — and only a randomized experiment can tell them apart.

  • Selection bias, confounders, survivorship bias — all three produce exactly the same correlation as true causation.
  • Randomization is powerful because it balances even unmeasured variables; no observational method can.
  • When you cannot randomize, use DiD, IV or RD — all require extra untestable assumptions.
07

A/B testing — statistics plus infrastructure

The six sections above are the math. What breaks in practice is who to split, when to stop, what to measure.

  • Split by user, and the hash must include experiment_id — otherwise one person is stuck in group A in every experiment.
  • Exactly one primary metric fixed upfront; the rest are guardrails, which only need to not get worse.
  • Run at least one full week even if the sample size is reached sooner — weekends are a different behavior.
08

Peeking

Stopping as soon as you see p < 0.05 sounds very reasonable, and it is the most common way to fail.

  • Looking 10 times pushes the false-positive rate up to 20–30% — one in every four "wins" is fake.
  • The cause: the gap swings wildly early on, so there is always a moment it dips below the threshold.
  • The fix is not banning looks but switching methods: sequential testing or Bayesian.
09

Practical pitfalls

Five ways a test that is entirely correct mathematically still leads to a wrong decision.

  • Sample ratio mismatch is the most dangerous: it says the data is wrong, so every other number is meaningless. Check it first.
  • Novelty effect and network effect are both broken independence assumptions, not statistical noise.
  • The last four share one shape: right numbers, wrong question — fix them in the design, not in the test.
10

Statistical vs practical significance

p = 0.001 and you should still refuse to ship — two different questions.

  • The bigger the sample, the easier a small p; it only says "different from 0", not "worth doing".
  • Three questions in order: is it different (p-value) → by how much (CI) → is it worth it (threshold).
  • The threshold must be fixed beforehand: see the number first, then ask "is it worth it", and the answer is already swayed.
11

Checklist

Three phases, and the middle phase is the easiest to break.

  • Before: one primary metric, sample size, and the ship threshold — all three fixed together.
  • During: watch only the split ratio and error rate. The primary metric stays closed.
  • After: sample ratio → effect size with CI → guardrails → compare to threshold. In exactly that order.
