Machine learning · first lesson of the shelf

Machine learning — the map

Read this first. Three things to remember:

  • a person gives examples, the machine finds the rule
  • the label decides the problem type: a number, a class, none, or a reward
  • the only score that counts is on data the model has never seen
01

Mental model

Ordinary programming: a person writes the rules. Machine learning: a person supplies examples, the machine finds the rules.

1.1Rules from examples

A hand-written rule cuts where a person guesses; a learned rule tilts until it fits the data.

  • The learned boundary gets 0.93 on these emails, the hand rule 0.75.
  • When the pattern changes, the learned rule is fixed by retraining on new data — no one rewrites it.
  • ML fits when the rules are too many or keep changing, and past outcomes are recorded.

1.2Training loop

Predict, measure how wrong, adjust the parameters a little, repeat — the loss falls step by step.

  • Feature: an input column. Label: the column to predict.
  • Parameter: a number the machine adjusts (the slope). Hyperparameter: a number a person sets first (the step size).
  • Loss: one number for how wrong the model is; learning means pushing it down.
L = 1n Σaverage over n rows (ŷi − yi)2squared gap: prediction − label
02

Problem types

One question splits them: what kind of label does the data have — a number, a class, nothing, or a reward later.

2.1Regression

The label is a number; the model draws a line and reads the answer off it.

  • Examples: house price, delivery time, demand next week.
  • Loss: squared error — see Linear regression.

2.2Classification

The label is one of a few classes; the model draws a boundary and reports which side a point falls on.

  • Examples: spam or not, churn or stay, which digit.
  • Most models also give a probability — see Logistic regression.

2.3Unsupervised learning

No labels at all; the model looks for structure, such as groups of similar rows.

  • Examples: customer segments, anomaly detection, fewer columns (PCA).
  • With no answers to grade against, judging the result is the hard part — see Clustering.

2.4Reinforcement learning

No labels, only a reward after actions; the agent learns how much each state is worth.

  • Examples: games, robot control, RLHF when tuning LLMs.
  • Rare in day-to-day ML work; supervised learning is most of it.
03

Model families

Same 70 points, four families. Each one assumes a different shape for the boundary.

3.1Linear models

One straight boundary: cheap, readable, but blind to curves.

  • Linear, Logistic, Ridge / Lasso.
  • The first baseline on any problem.

3.2Tree models

Cuts parallel to the axes, one threshold at a time, build a staircase boundary.

  • Random Forest and Gradient Boosting combine many trees.
  • The strongest default on tabular data; no feature scaling needed.

3.3Neighbours and kernels

A new point copies the vote of its closest training points.

  • KNN and SVM rely on a notion of distance, so scale the features first.

3.4Neural networks

Layers of units learn the shape themselves — a smooth curve here.

  • Win on raw images, audio and text; on tables, tree ensembles usually match them.
  • Covered on the Deep learning shelf.
04

Generalization

Being right on the training rows is easy. The goal is being right on rows the model has never seen.

4.1Underfitting

Too simple: misses the training points and the new points alike.

  • Called high bias. Fix: a richer model or better features.

4.2Overfitting

Too flexible: hits every training point, misses the new ones.

  • Called high variance. Fix: more data or regularization — see Overfitting & regularization.

4.3Good fit

Follows the pattern, ignores the noise: the lowest error on new points.

  • The balance between the two failures is the bias–variance tradeoff.
  • Only a held-out test set can tell the three apart — see Train / val / test.
