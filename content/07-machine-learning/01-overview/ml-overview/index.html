Machine learning — the map

Read this first. It answers three questions: what machine learning can do, how many problem types there are, and what order to learn them in.

01

Mental model

Ordinary programming: a person writes the rules, the machine runs them. Machine learning flips that — a person supplies examples, the machine finds the rules. On a real spam filter, hand-written rules top out at 0.743 while the learned model reaches 0.984.

  • ML is not magic: the "old model, untouched" row falls to 0.541 — close to random guessing. A model is only right as long as the world still looks like the data it learned from.
  • The gain is not in the number but in the cost of fixing: the two runs differ by exactly one variable, and not a single rule was edited.
  • In exchange, nobody can read the rules the machine found: 400 weight numbers instead of a keyword list you can read by eye — that cost has its own discussion in Model evaluation and in the linear model lessons.

The "rerun" in the last row of the table always has exactly three stages.

Labeled data → learning, i.e. pushing the loss as low as possible → a model that predicts rows it has never seen.

The seven words below appear in every later lesson; knowing exactly what they mean is enough to keep reading:

Featureone input column — age, word count in an email, order value
Labelthe column to predict, already known in the training data
Modela function that takes features and returns a prediction — the shape is chosen by a person, the parameters are learned by the machine
Parametera number inside the model that the machine adjusts while learning — regression weights, a tree's split thresholds
Hyperparametera number a person sets before learning that the machine does not adjust — a tree's max depth, the learning rate
Loss functiona measure of how wrong the model is; learning means finding the parameters that minimize it
Generalizationbeing right on unseen data — the real goal, not being right on the data it learned from
  • ML is worth using when the rules are too many or change constantly to write by hand, and there is data recording the correct outcomes.
  • ML is wrong when the rules fit in a few if statements, when every decision must be explained, or when there is no data yet.
  • A model can only learn what is in the data. Skewed data gives a skewed model, and the model does not know it.
02

Supervised, unsupervised & reinforcement

Three problem types, split by a single question: do you have correct answers to check against.

Supervised — features and correct labelslearn a mapping from features to label · predict house prices (a number), filter spam (a class)
Unsupervised — features only, no labelslearn hidden structure · segment customers, reduce dimensions, detect anomalies
Reinforcement — no answers, only a reward after each actionlearn a sequence of actions that maximizes total reward · games, robot control, RLHF when fine-tuning LLMs
  • In real work supervised is almost everything. The hard part is not choosing an algorithm but getting enough correct labels.
  • Supervised splits in two by label type: regression (a continuous number) and classification (one of a few classes) — see Linear and Logistic regression.
  • Unsupervised is much harder to evaluate: with no answers there is nothing to grade against, only indirect measures.
03

Choosing a model family

On the same data table, each model family assumes a different shape for the relationship between features and label. Choosing a family means choosing an assumption.

Linear models · Linear · Logistic · Ridge/Lassoassume the label is an additive combination of features — pick them when you need to explain every coefficient, have little data, or want a quick baseline
Tree ensembles · Random Forest · Gradient Boostingassume threshold effects and interacting features — the strongest default for tabular data, no feature scaling needed
Instance & kernel · KNN · SVMassume similar points share a label — pick them when data is low-dimensional and has a clear notion of distance
Probabilistic · Naive Bayesassume features are independent given the class — pick it for text, very high-dimensional sparse data, when it must run extremely fast
Neural networksassume no shape, learn features on their own through many layers — pick them for images, audio, text: raw data from which people cannot extract features by hand
  • On tabular data, tree ensembles still beat neural networks. So this shelf centers on classical models; neural networks are left to the Deep learning shelf.
  • Start with the simplest model that works: it gives a baseline to tell whether a complex model is really better.
  • No family wins every problem: better here means worse there, just like choosing a data structure.
04

Generalization — the central problem

Making a model right on the data it learned from is so easy it is meaningless: just let it memorize. All the difficulty lies in unseen data.

Model too simple

Not expressive enough to describe the real relationship.

Symptom: many errors on both training data and new data.

Called underfitting, caused by high bias.

Model too complex

Memorizes even the random noise of the dataset at hand.

Symptom: nearly perfect on training data, sharply worse on new data.

Called overfitting, caused by high variance.

  • These two failures pull against each other: overcorrect one and you fall into the other. Balancing them is the bias–variance tradeoff.
  • A result is only trustworthy when measured on data the model has never seen — see Overfitting & regularization.
  • Which yardstick to measure with is a separate decision: with imbalanced classes a high accuracy can still be useless — see Metric & confusion matrix.
05

Learning order

Eight stages, going from a language for talking about uncertainty to how to choose a yardstick for results.

1 · Math foundationsFour lessons: probability, linear algebra, calculus, statistics — exactly the math you will meet again, no more.
2 · StatisticsFrom sample to population: confidence intervals, hypothesis tests, p-values, then A/B testing. It comes right after the math because it shares that language, and because every later model comparison is a hypothesis test in disguise.
3 · Core conceptsThe three problem types, bias–variance, train/val/test splits, fighting overfitting, feature engineering. The stage that decides whether you can read your own results.
4 · Classical modelsLinear and logistic regression first — they are where every concept from the three stages above shows up as a concrete formula. Then Ridge/Lasso, SVM, KNN, Naive Bayes.
5 · Tree modelsDecision tree → Random Forest → Gradient Boosting → XGBoost/LightGBM. The strongest model family on tabular data.
6 · ClusteringProblems without labels: k-means, DBSCAN, HDBSCAN — and the hardest question is how to know the result is good.
7 · Dimensionality reductionPCA: fewer dimensions while keeping most of the information.
8 · Model evaluationConfusion matrix, precision/recall, ROC-AUC and PR, calibration. Pick the wrong yardstick and every conclusion above collapses.
  • Don't skip the first three stages: every model lesson assumes you know what a loss function is and why a test set is needed.
  • Statistics sits right after Math foundations because it is the same thread: probability describes known distributions, statistics goes from sample back to population.
  • Stages 4 and 5 are the "learning models" part but take only a third of the time — the real effort is in the data.
