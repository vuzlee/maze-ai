Distributed systems

One server grows into many by adding one part per limit — cache, load balancer, replicas, shards, queue — and pays for it with partial failure, lost messages and copies that must choose.

01

Growing with load

A large service is one small service that kept adding a part each time a limit was hit.

  • Every part answers one limit: speed (cache), traffic (load balancer), crashes and size (replicas, shards — and copies then face CAP), slow work (queue).
  • Add parts only when the limit is real — each one is another machine that can fail.
02

What becomes hard

Many machines bring problems one machine never had: parts fail, messages vanish, copies disagree.

  • Timeouts and retries are the only tools against silence — so every request must be safe to repeat.
  • The choice between consistent and available is made per feature; the CAP lesson shows how.
03

Start with the core trade-off, then the tools.
