Distributed systems

Many machines that look like one system to the user.

  • more machines buy scale, availability and lower latency
  • the price: partial failure and an unreliable network
  • every lesson here handles one of those trade-offs
01

Mental model

Users see one service; behind it, many machines work together.

02

Why use many machines

Three limits of a single machine.

2.1Scale

One server has a ceiling; many servers share the load.

See Load balancing & scaling.

2.2Availability

If one server dies, another keeps serving.

See Replication & sharding.

2.3Latency

Put copies close to users.

See Caching.

03

What becomes hard

Problems a single machine never had.

3.1Partial failure

Some machines fail while the rest keep running.

3.2Unreliable network

Messages can be lost or delayed, and the sender can't tell which.
