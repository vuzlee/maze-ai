Distributed systems · messaging

Message queue & Pub/Sub

Do slow work later, through a queue.

  • a queue gives each message to one worker
  • Pub/Sub sends each message to every subscriber
  • messages can repeat — make workers idempotent
01

Mental model

Reply now, do the slow work later.

  • Also smooths traffic spikes and keeps working if the worker is down for a while.
02

Queue vs Pub/Sub

Share the work, or tell everyone.

2.1Message queue

Each message goes to one worker.

Background jobs: emails, image resizing. RabbitMQ, Amazon SQS.

2.2Pub/Sub

Each message goes to every subscriber.

Events many services care about. Kafka, Google Pub/Sub, SNS.

03

Delivery guarantees

What happens when a worker crashes.

3.1At-most-once

Never repeated, but may be lost.

3.2At-least-once

Never lost, but may repeat — the usual choice.

3.3Exactly-once

No loss, no repeats — hard and costly.

04

Idempotency

Processing a message twice has the same effect as once.

  • Store processed message ids, or use a UNIQUE constraint.
05

Dead letter queue

Move a message that keeps failing out of the way.
