Distributed systems · scaling

Load balancing & scaling

Spread traffic across many servers.

  • a load balancer picks a server for each request
  • health checks skip dead servers
  • scale out with more machines, keep servers stateless
01

Mental model

One entry point, many servers behind it.

02

Balancing algorithms

How the next server is chosen.

2.1Round robin

Take turns — simple and even by count.

2.2Least connections

Send to the server with the least work.

Better when some requests take much longer.

2.3IP hash

The same user always lands on the same server.

Useful for sticky sessions; uneven if a few users are very active.

03

L4 vs L7

L4 sees IP and port; L7 reads HTTP and can route by URL.

  • Examples: AWS NLB is L4; AWS ALB, Nginx, HAProxy can do L7.
04

Health checks

Only send traffic to servers that respond.

05

Scaling

Two ways to handle more traffic.

5.1Vertical

A bigger machine — simple, but capped.

5.2Horizontal

More machines — no hard cap.

5.3Stateless servers

Keep session data outside the servers.

Then servers can be added or removed freely — the basis of autoscaling.
