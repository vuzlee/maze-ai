Caching

Keep a fast copy of data you read often.

  • a hit answers from the copy; a miss goes to the database
  • caches sit at many layers, from browser to server
  • the hard part is knowing when the copy is stale
01

Mental model

Check the fast copy first; only on a miss go to the database.

02

Cache layers

The closer to the user, the faster.

  • Redis and Memcached are the common app caches.
03

Caching patterns

Who fills the cache, and when.

3.1Cache-aside

The app fills the cache on a miss — the most common.

3.2Write-through

Write to cache and database together.

3.3Write-back

Write to cache now, database later.

04

Expiration

Stale copies must be removed.

4.1TTL

Each entry expires after a set time.

  • Or delete the key whenever the data changes.

4.2Eviction

When the cache is full, drop the least recently used.

05

Cache stampede

A popular key expires and everyone misses at once.

  • Fix: let one request rebuild the value while others wait (a lock).
  • Fix: add random jitter to TTLs so keys don't expire together.
