Database overview

Data lives in tables linked by keys, and one language, SQL, shapes it, changes it and asks it anything — the side the pendulum keeps swinging back to.

01

What SQL & relational is

Relational data is tables linked by keys; SQL is one language to ask them anything. This shelf is these eleven pictures.

  • Model first: a well-shaped table makes every later query short.
  • Every query is a pipeline of the same moves — filter, join, group, rank — and an index decides how fast it runs.
02

Data-model pendulum

Databases have swung between strict and free schema for sixty years — and keep swinging back to SQL.

  • Each swing fixed the last one’s pain: rigid trees → any question; slow joins at scale → no schema; lost guarantees → SQL at scale.
  • Today the default is a relational database; other shapes are chosen for one specific need.
03

Types of database

Four shapes for the same data — pick by how you will read it.

  • Unsure? Start relational. Move a piece out only when one access pattern clearly fits another shape.
  • The other three are taught on the NoSQL shelf.
04

SQL commands

Beyond asking, SQL defines the shape, changes the rows and controls who may.

  • DDL — CREATE · ALTER · DROP · TRUNCATE; DML — INSERT · UPDATE · DELETE; DCL — GRANT · REVOKE.
  • An UPDATE or DELETE without WHERE touches every row — run it inside a transaction.
05

Learning order

Read this shelf in order: every query lesson assumes the tables are designed well.

  • Every stop is a link. After transactions, move on to the NoSQL shelf.
