Database · SQL basics

JOIN

Combine tables on a matching key.

  • ON says which rows match
  • INNER keeps matches only; LEFT also keeps unmatched left rows
  • unmatched columns become NULL
01

Mental model

Every join uses the same ON; types differ in what they do with rows that do not match.

Syntax: SELECT c.name, o.amount FROM customers c LEFT JOIN orders o ON o.cust = c.id.

02

Join types

Same ON, different unmatched rows kept.

2.1INNER JOIN

Keep only matching rows.

FROM customers c INNER JOIN orders o ON o.cust = c.id — JOIN alone means INNER.

2.2LEFT JOIN

Keep every left row; no match gives NULL.

FROM customers c LEFT JOIN orders o ON o.cust = c.id

2.3RIGHT JOIN

Keep every right row; no match gives NULL.

Rarely used — swap the tables and use LEFT JOIN instead.

2.4FULL OUTER JOIN

Keep every row from both sides.

Not supported in MySQL — emulate with LEFT JOIN UNION RIGHT JOIN.

2.5CROSS JOIN

Pair every row with every row.

FROM sizes CROSS JOIN colors — no ON; 2 × 2 = 4 rows.

2.6Self join

Join a table to itself using two aliases.

FROM employees e LEFT JOIN employees m ON e.manager_id = m.id

2.7Joining many tables

Chain joins one at a time.

FROM orders o JOIN customers c ON … JOIN products p ON …

03

Common mistakes

Two ways joins silently give wrong numbers.

3.1Row explosion

Joining to many rows multiplies the left row.

  • Sum orders before joining, or use COUNT(DISTINCT …).

3.2ON vs WHERE

With LEFT JOIN, a condition in WHERE drops the NULL rows.

  • Filter the right table in ON; filter the left table in WHERE.
