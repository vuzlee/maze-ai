Database · relational basics

Relational model

Data as tables of rows, picked out by keys.

  • a table is a set of rows with the same columns
  • a key identifies exactly one row
  • NULL means unknown, not zero or empty
01

Mental model

A table is a set of rows — every row has the same typed columns.

  • Also called: table = relation, row = tuple, column = attribute.
  • Schema: the table's name, columns and types.
02

Data types

Each column has one type; values of another type are rejected.

TypeHolds
INT, BIGINTwhole numbers
DECIMAL(10,2)exact decimals — money
FLOATapproximate decimals
VARCHAR(n), TEXTtext
DATE, TIMESTAMPdates and times
BOOLEANtrue / false
03

Keys

A key picks out exactly one row.

3.1Candidate and primary key

Any unique column set is a candidate; you pick one as primary.

3.2Composite key

Sometimes no single column is unique — combine them.

3.3Surrogate key

An artificial id that never changes, even when real data does.

id INT GENERATED ALWAYS AS IDENTITY (or SERIAL, AUTO_INCREMENT, UUID).

04

NULL

NULL means unknown, so any comparison with it is neither true nor false.

  • NULL = NULL is not true — test with IS NULL / IS NOT NULL.
  • WHERE keeps only rows where the condition is true, so NULL rows silently drop out.
  • Use NOT NULL on columns that must always have a value.
