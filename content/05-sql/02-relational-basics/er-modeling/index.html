ER modeling

Turn requirements into tables before writing SQL.

  • entity → table, attribute → column
  • cardinality decides where the foreign key goes
  • many-to-many needs a junction table
01

Mental model

Nouns become entities, verbs become relationships.

02

ER diagram

Boxes for entities, lines for relationships.

  • Crow's foot (<) = many; bar (|) = exactly one; circle (o) = optional.
03

Cardinality

How many rows on each side can be linked.

3.1One-to-one

Each row matches at most one on the other side.

profile.user_id INT UNIQUE REFERENCES users(id)

3.2One-to-many

The foreign key always goes on the many side.

  • A customer row cannot hold a list of order ids — one cell, one value.

3.3Many-to-many

Add a junction table in the middle: one row per link.

  • Primary key of the junction table: (student_id, course_id).
  • Extra facts about the link go here too, such as enrolled_at or grade.
