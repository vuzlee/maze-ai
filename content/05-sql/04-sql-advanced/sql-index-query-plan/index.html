Index & query plan

Make lookups fast without reading every row.

  • an index is a sorted copy of a column with pointers to rows
  • it speeds up reads but slows down writes
  • EXPLAIN shows whether a query uses it
01

Mental model

Without an index the database reads every row; with one it jumps straight there.

Syntax: CREATE INDEX idx_orders_cust ON orders(cust).

02

Choosing indexes

An index helps reads and costs every write.

2.1Good candidates

Columns you filter, join or sort on, with many distinct values.

  • PRIMARY KEY and UNIQUE get an index automatically.

2.2Write cost

Every write updates every index.

2.3Composite index

Order matters: (a, b) helps a, or a and b — not b alone.

CREATE INDEX ON customers(city, name)

2.4When an index is skipped

Wrapping the column in a function hides it from the index.

03

Query plan

EXPLAIN shows how the database will run a query.

  • EXPLAIN ANALYZE also runs it and reports real times.
