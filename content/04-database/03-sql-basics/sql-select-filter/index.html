SELECT, WHERE & ORDER BY

Câu SQL không chạy theo thứ tự bạn viết. Biết thứ tự thật là hết nhầm alias, NULL, và DISTINCT.

01

Thứ tự thực thi logic

Bạn viết một câu SELECT theo thứ tự SELECT → FROM → WHERE → ORDER BY, nhưng database chạy nó theo thứ tự hoàn toàn khác:

1 · FROM

lấy bảng nguồn

→
2 · WHERE

lọc từng dòng thô

→
3 · SELECT

tính cột, đặt alias

→
4 · DISTINCT

loại dòng trùng

→
5 · ORDER BY / LIMIT

sắp xếp, cắt bớt

(Bài này bỏ qua GROUP BY/HAVING — xem GROUP BY & aggregate, chúng chạy xen giữa bước 2 và 3.)

-- bảng orders(id, customer, amount, status, created_at)
SELECT customer, amount AS so_tien
FROM orders
WHERE status = 'paid' AND amount > 100000
ORDER BY so_tien DESC
LIMIT 10;

Nhớ một câu

WHERE chạy trước SELECT. Vì vậy nó chỉ thấy các cột gốc của bảng, không thấy alias hay cột tính toán mà SELECT mới tạo ra.
02

WHERE lọc cái gì

WHERE lọc từng dòng thô, ngay sau khi FROM lấy dữ liệu — trước khi có bất kỳ gom nhóm hay tính toán nào. Các toán tử hay dùng:

WHERE status = 'paid' AND (amount > 500000 OR customer = 'VIP01');
03

Bí danh dùng được ở đâu

Vì SELECT chạy sau WHERE nhưng trước ORDER BY, một alias đặt trong SELECT chỉ tồn tại từ điểm đó trở đi:

-- SAI — lỗi "column so_tien does not exist"
SELECT amount AS so_tien FROM orders WHERE so_tien > 100000;

-- ĐÚNG — WHERE dùng tên cột gốc
SELECT amount AS so_tien FROM orders WHERE amount > 100000;

-- ĐÚNG — ORDER BY chạy sau SELECT nên thấy alias
SELECT amount AS so_tien FROM orders ORDER BY so_tien DESC;

Alias trên bảng (FROM orders o) thì khác — nó có ngay từ bước FROM nên dùng được ở mọi mệnh đề phía sau, kể cả WHERE.

04

NULL trong điều kiện

NULL nghĩa là "không biết giá trị", không phải "rỗng" hay "0". SQL dùng logic ba giá trị: TRUE, FALSE, và UNKNOWN — bất kỳ so sánh nào với NULL đều ra UNKNOWN, và WHERE chỉ giữ lại dòng có kết quả TRUE.

NULL = NULL        -- UNKNOWN, không phải TRUE
NULL != NULL       -- UNKNOWN, không phải TRUE
NULL != 5          -- UNKNOWN, không phải TRUE

-- ĐÚNG cách kiểm tra rỗng
SELECT * FROM orders WHERE shipped_at IS NULL;
SELECT * FROM orders WHERE shipped_at IS NOT NULL;

Vì sao NULL != NULL lại hợp lý

Hai ô "không biết giá trị" không thể khẳng định là bằng nhau hay khác nhau — vì cả hai đều không biết. SQL trả về UNKNOWN thay vì đoán bừa, và WHERE loại bỏ mọi dòng UNKNOWN giống như loại bỏ FALSE.
05

Lỗi hay gặp

DISTINCT che lỗi JOIN

SELECT DISTINCT làm biến mất các dòng trùng do join sai làm nhân bản — nhưng không sửa nguyên nhân, chỉ giấu triệu chứng. Con số tổng hợp phía sau vẫn sai.

ORDER BY theo số thứ tự cột

ORDER BY 2 vẫn hợp lệ nhưng đổi thứ tự cột trong SELECT là đổi luôn ý nghĩa sắp xếp mà không ai để ý — dùng tên cột hoặc alias rõ ràng.

So sánh trực tiếp với NULL

WHERE col = NULL không báo lỗi cú pháp nhưng luôn trả về rỗng, vì kết quả so sánh luôn là UNKNOWN. Phải dùng IS NULL.

06

Hỏi đáp

Thứ tự thực thi thật của một câu SELECT là gì?

FROM trước, lấy bảng nguồn. Rồi WHERE lọc từng dòng thô. Rồi mới tới SELECT, tính cột và đặt alias. Cuối cùng ORDER BY rồi LIMIT. Đây khác hẳn thứ tự viết trên màn hình, và là lý do WHERE không thấy được alias mà SELECT vừa đặt.

Vì sao WHERE col = NULL luôn trả về rỗng?

Vì SQL dùng logic ba giá trị: so sánh bất kỳ thứ gì với NULL đều ra UNKNOWN, không phải TRUE hay FALSE. WHERE chỉ giữ dòng có kết quả đúng là TRUE, nên mọi dòng UNKNOWN bị loại giống hệt FALSE. Muốn kiểm tra rỗng phải dùng IS NULL.

Vì sao ORDER BY dùng được alias mà WHERE thì không?

Vì SELECT — nơi tạo ra alias — chạy sau WHERE nhưng trước ORDER BY trong thứ tự thực thi thật. Tại thời điểm WHERE chạy, alias chưa tồn tại; tới lúc ORDER BY chạy thì nó đã có.

BETWEEN có bao gồm hai đầu mút không?

Có. amount BETWEEN 100 AND 500 tương đương amount >= 100 AND amount <= 500 — khoảng đóng cả hai đầu. Nhầm nó với khoảng mở là lỗi hay gặp khi so ranh giới ngày tháng.
