Big-O

The skill you actually need: see n ≤ 10⁵ and know at once what is allowed. The rest is just three counting rules.

01

Mental model

Big-O does not say how many seconds code runs. It says what shape the cost grows in as n gets larger — so the right statement is never “O(n log n) is faster than O(n²)”, but “from n = 80 on it is faster, forever after”.

  • Drop constants and lower-order terms: 3n² + 100n is O(n²). What gets dropped is not small — two implementations of the same O(n log n) measured 13.7× apart.
  • So Big-O answers exactly one question: up to what n does this solution survive. To know which is faster at your n, you have to measure.
  • The familiar “10⁸ ops/sec” mark belongs to C. Pure Python measures about 5 × 10⁷ — so read the table in section 02 for the language you are using.

03

Counting rules

No math needed. Count how many times the innermost line runs and you have it.

Sequential

two separate loops → add
O(n) + O(n) = O(n)

·
Nested

loop inside a loop → multiply
O(n) × O(n) = O(n²)

·
Halving

each round drops half the data → log
O(log n)

  • Recursion: branches to the power of depth. Naive Fibonacci splits into two branches, depth n → O(2n).
  • Divide and conquer halves then merges in O(n) → O(n log n) (merge sort).
  • A while loop whose pointer never moves back is still O(n) even if it looks nested.

05

Hidden costs in Python

Not every line is worth one operation. The five lines below look like O(1) but are O(n) — and they raise no error, they just drag the whole algorithm down an order.

  • Slicing inside recursion is the most dangerous trap: f(a[1:]) adds O(n) to every level, turning O(n) into O(n²) with nothing visible in the code. At n = 8,000 it is 124× slower.
  • s += "a" is only 1.8× slower because CPython optimizes in place when the string has only one reference. Keep another variable pointing at it and the optimization switches off, dropping to true O(n²) — measured 9,774 µs vs 1,452 µs at n = 32,000.
  • The common denominator: push the loop down into C. sum, sort, join, in set all keep the same order but run 4× faster.
06

Amortized — why append is O(1)

Not “every call is fast”, but total cost spread evenly over the number of operations. The figure above measured it: 0.20% of appends cost over 10× normal, the worst cost 981× — yet the average is still a constant.

worst growth981× a normal append
total copies / n8.56 — a constant
average per callO(1) amortized

2 million appends grow only 92 times — successive growths get further and further apartso the red bar is too rare to drag the average up

  • The reason is that the new space always grows proportionally, so successive growths get further and further apart: 2 million appends grow only 92 times, 8.56n copies in total. Divide by n and you get a constant.
  • The correct way to say it: amortized O(1), worst case for a single call O(n) — the two numbers do not contradict each other.
  • Real-time systems care about the worst call, not the average: a frame 78 µs late is still a late frame.
  • Same mechanism in hash map — a dict grows when 2/3 full, and there the worst growth measured 56,000× normal.
07

Space complexity

Count extra memory, not the input data. The recursion stack counts too.

Not counted

the array a given by the problem

the string s given by the problem

Counted

hash maps, result lists you create

recursion stack — costs as deep as it goes

  • Recursion depth n → O(n) memory even with no allocation. This is the most often forgotten.
  • 2D DP can usually drop from O(n²) to O(n) because it only needs the last one or two rows.
  • Yield results with a generator instead of a list: O(n) → O(1).
08

Stating complexity concisely

Three parts, one sentence: how many passes · which pass costs most · extra memory.

Say this

"Sorting is O(n log n), then one pass is O(n), so the total is O(n log n). Extra memory is O(1) if sorting in place."

Not this

"Probably O(n log n)." — if you can't say why, the interviewer will push back immediately.

  • Always mention memory, even when not asked.
  • Say the constraint out loud: "n goes up to 10⁵ so O(n²) times out, I need O(n log n)".
