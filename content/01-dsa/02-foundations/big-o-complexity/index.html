Big-O

Read the limit on n, know at once what is allowed.

01

Mental model

Big-O is the shape of the growth, not a number of seconds.

1.1Growth curves

Same n, very different work — the curve decides.

1.2Constants are dropped

A lower order is not faster at every n — only past the crossing.

02

Properties

What to memorize — the budget, the averages, the hidden costs.

2.1Which order fits n

About 10⁸ simple steps per second: pick the highest order that stays under it.

2.2Amortized cost

Rare expensive steps, averaged over all of them, can still be O(1).

2.3Space

Count extra memory — the recursion stack counts too.

2.4Lines that hide a loop

One line can be O(n) — the code does not show it.

03

Patterns

Count how often the innermost line runs — the code shape tells you.

3.1One loop

One pass over the input → O(n).

Signals: one for over the input · two pointers that only move forward · sequential loops add, still O(n)

3.2Loop inside a loop

Every pair → multiply → O(n²).

Signals: a for inside a for over the same input · "every pair"

3.3Halving loop

Cut the work in half each pass → O(log n).

Signals: n //= 2 · l/r closing on a middle · heap push/pop, balanced tree depth

3.4Recursion tree

Calls = branchesdepth.

Signals: a function calling itself twice · no memo → O(2n) · halve and merge → O(n log n)
