01

Mental model

BFS, DFS and even Dijkstra are the same loop. They differ in exactly one spot: the box holding the waiting vertices — and that box decides which question gets answered.

  • Need the fewest steps, every edge the same cost → deque, take from the front — that is BFS. Nothing simpler exists.
  • Just need to cover a whole region: counting connected components, finding cycles, topo sort → take from the back, that is DFS, shorter written recursively.
  • Edges with different costs → swap the box for a heap and you get Dijkstra (section 09). When costs are only 0 and 1, a 0-1 BFS with a two-ended deque is enough.
02

Code templates to memorize

On a grid the neighbors are the 4 adjacent cells. On a graph the neighbors are adj[u]. Everything else is identical.

# BFS — use when you need the shortest NUMBER OF STEPS
from collections import deque
q, seen = deque([start]), {start}
step = 0
while q:
    for _ in range(len(q)):        # process a whole layer
        u = q.popleft()
        for v in neighbors(u):
            if v not in seen:
                seen.add(v); q.append(v)   # mark RIGHT when pushing
    step += 1
# DFS — use when you need to COVER a whole region
def dfs(u):
    seen.add(u)
    for v in neighbors(u):
        if v not in seen: dfs(v)

Grid: neighbors = [(r+1,c), (r-1,c), (r,c+1), (r,c-1)] — remember the bounds check.

03

Common mistakes

Trap number one keeps the results correct but makes the code many times slower — very hard to notice.

Marking when popping from the queue

Mark right when pushing. Mark on pop and a vertex enters the queue many times.

Going back to the parent in an undirected graph

DFS on a tree or an undirected graph must skip the parent, otherwise it miscounts that as a cycle.

Recursion too deep

A 1000×1000 grid overflows a recursive DFS's stack. Switch to a loop with your own stack.

Pattern 3 — topo sort & cycles

Signals: "prerequisite courses" · "order of execution" · "can it be completed"

Count in-degrees, push in-degree-0 vertices into the queue, peel them off one by one. If every vertex gets placed, there is no cycle.

q = deque([u for u in vertices if indeg[u] == 0])
while q:
    u = q.popleft(); order.append(u)
    for v in adj[u]:
        indeg[v] -= 1
        if indeg[v] == 0: q.append(v)
return order if len(order) == n else []   # missing vertices = a cycle

Pattern 5 — weighted edges

Signals: each edge has a different cost — BFS is wrong right away; swap the queue for a heap

This is the third box in the section 01 figure: same loop, the box switches from deque to heap.

BFS is not broken — it still returns the path with the fewest edges; the problem is just asking for the cheapest path.

import heapq
pq = [(0, start)]                    # (cost, vertex)
while pq:
    d, u = heapq.heappop(pq)          # always take the cheapest vertex
    if d > dist[u]: continue
    for v, w in adj[u]:
        if d + w < dist[v]:
            dist[v] = d + w; heapq.heappush(pq, (dist[v], v))

weights only 0 and 1 → use 0-1 BFS with a deque, cheaper than a heapnegative edges → Bellman-Ford
