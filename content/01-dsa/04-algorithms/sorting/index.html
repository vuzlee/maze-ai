Sorting

Hiếm khi phải tự cài. Nhưng biết chọn khoá sắp xếp là thứ giải xong nửa số bài greedy và interval.

01

Ý tưởng

Sắp xếp không phải mục đích. Nó là bước chuẩn bị biến bài khó thành bài dễ.

Trước khi sắp

tìm cặp có tổng bằng target → thử mọi cặp, O(n²)

tìm hai số gần nhau nhất → mọi cặp, O(n²)

gộp các đoạn chồng nhau → không biết bắt đầu từ đâu

Sau khi sắp

hai con trỏ từ hai đầu, O(n)

chỉ cần so hai phần tử liền kề, O(n)

quét một lượt, đoạn sau chỉ chồng với đoạn ngay trước

chi phí sắp xếp O(n log n)gần như luôn đáng, vì nó hạ phần còn lại từ O(n²) xuống O(n)

02

Bubble, Selection, Insertion

Ba cách ai cũng học đầu tiên. Chậm, nhưng một trong ba vẫn đang chạy trong Python ngay lúc này.

# Bubble — đổi chỗ hai cái kề nhau cho tới khi hết sai
for i in range(n):
    for j in range(n - i - 1):
        if a[j] > a[j + 1]:
            a[j], a[j + 1] = a[j + 1], a[j]

# Selection — mỗi vòng tìm cái nhỏ nhất, đem ra đầu
for i in range(n):
    m = min(range(i, n), key=lambda k: a[k])
    a[i], a[m] = a[m], a[i]

# Insertion — lấy từng cái, lùi về cắm vào đúng chỗ
for i in range(1, n):
    x, j = a[i], i - 1
    while j >= 0 and a[j] > x:
        a[j + 1] = a[j]
        j -= 1
    a[j + 1] = x

  • Insertion sort còn sống vì hai lý do: rất nhanh trên đoạn ngắn (hằng số nhỏ, không đệ quy), và gần O(n) khi dữ liệu gần như đã sắp. Timsort của Python gọi thẳng nó cho các đoạn dưới 64 phần tử.
  • Selection sort thua Insertion ở mọi mặt — luôn O(n²) kể cả dữ liệu đã sắp sẵn, lại không stable. Nó chỉ hơn ở một chỗ: số lần đổi chỗ ít nhất, đúng n lần.
03

Merge, Quick, Heap

Không cần thuộc code. Cần biết cái nào đánh đổi thứ gì.

# Merge — chẻ đôi, sắp hai nửa, trộn lại
def merge_sort(a):
    if len(a) <= 1: return a
    m = len(a) // 2
    L, R = merge_sort(a[:m]), merge_sort(a[m:])
    out, i, j = [], 0, 0
    while i < len(L) and j < len(R):
        # <= giữ thứ tự cũ khi bằng nhau → stable
        if L[i] <= R[j]: out.append(L[i]); i += 1
        else:           out.append(R[j]); j += 1
    return out + L[i:] + R[j:]

# Quick — chọn chốt, chia ba phần quanh nó
def quick_sort(a):
    if len(a) <= 1: return a
    p = a[len(a) // 2]
    lo = [x for x in a if x < p]
    eq = [x for x in a if x == p]
    hi = [x for x in a if x > p]
    return quick_sort(lo) + eq + quick_sort(hi)

# Heap — dựng heap rồi lấy dần cái nhỏ nhất
import heapq
def heap_sort(a):
    h = a[:]; heapq.heapify(h)          # O(n)
    return [heapq.heappop(h) for _ in h]   # n × O(log n)

04

Vì sao O(n log n) là chặn dưới

Mỗi phép so sánh chỉ cho một bit thông tin. Cần đủ bit để phân biệt n! thứ tự có thể.

số thứ tự có thển! ≈ 3,6 triệu với n = 10
số câu hỏi cầnlog₂(n!) ≈ n log n

mỗi lần so sánh chia đôi số khả năng còn lạinên không thuật toán so sánh nào nhanh hơn n log n được

  • Chặn dưới này chỉ áp cho thuật toán dựa trên so sánh.
  • Biết thêm về dữ liệu thì phá được: counting sort và radix sort đạt O(n) khi miền giá trị nhỏ hoặc khoá là số nguyên ngắn.
05

Timsort — sort của Python

Sách vở dạy Merge và Quick. Nhưng a.sort() bạn gõ mỗi ngày chạy Timsort — và nó nhanh vì một nhận xét rất đời: dữ liệu thật hiếm khi ngẫu nhiên.

1 · Tìm các runQuét một lượt, cắt mảng thành các đoạn đã sắp sẵn (run). Đoạn đang giảm thì lật ngược lại. Dữ liệu thật — log, timestamp, dữ liệu vừa thêm vào cuối — đầy những đoạn như vậy.
2 · Đoạn ngắn thì insertion sortRun ngắn hơn 64 phần tử thì gọi insertion sort nối dài nó ra cho đủ. Ở cỡ đó insertion nhanh hơn đệ quy vì hằng số nhỏ và không tốn chi phí gọi hàm.
3 · Trộn các runTrộn từng cặp run như merge sort, theo quy tắc giữ kích thước các run cân nhau để không tụt về O(n²).
Kết quảDữ liệu ngẫu nhiên: O(n log n) như merge sort. Dữ liệu đã sắp sẵn hoặc gần như đã sắp: O(n) — chỉ quét đúng một lượt là xong.
mảng ngẫu nhiênO(n log n)
mảng gần như đã sắpO(n) — bắt được run sẵn

Tim Peters viết cho Python năm 2002giờ là sort mặc định của cả Java, Android, V8, Swift, Rust

  • Timsort stable — hai phần tử bằng nhau theo khoá thì giữ nguyên thứ tự cũ. Nhờ đó sắp theo tên trước rồi sắp theo điểm sau vẫn cho kết quả đúng: cùng điểm thì vẫn theo thứ tự tên.
  • Dù vậy nên sắp một lần bằng khoá ghép cho chắc: a.sort(key=lambda x: (-x.score, x.name)).
  • list.sort() sắp tại chỗ, sorted() trả về list mới — cả hai đều là Timsort.
06

Lỗi hay gặp

Bẫy đầu tiên là lỗi hay gặp nhất khi sắp xếp theo nhiều khoá.

Trộn tăng và giảm trong khoá ghép

(-score, name) đúng vì đảo dấu số. Với chuỗi thì không đảo dấu được — phải sắp hai lần, dựa vào tính ổn định.

Sắp khi không cần

Chỉ cần k phần tử lớn nhất thì heap là O(n log k), rẻ hơn sắp cả mảng. Chỉ cần min/max thì một lượt quét.

Tưởng quicksort luôn nhanh

Dữ liệu đã sắp sẵn + chốt chọn kém → O(n²). Thư viện chuẩn đã xử lý, nhưng tự cài thì phải chọn chốt ngẫu nhiên.

08

Hỏi đáp phỏng vấn

Tự trả lời thành tiếng trước, rồi mới mở ra.

Vì sao không thuật toán so sánh nào nhanh hơn O(n log n)?

Mỗi so sánh cho một bit, mà cần phân biệt n! thứ tự → cần log₂(n!) ≈ n log n lần so sánh.

Ổn định nghĩa là gì và khi nào cần?

Hai phần tử bằng khoá thì giữ nguyên thứ tự cũ. Cần khi sắp nhiều lần theo nhiều tiêu chí.

Quick sort hay merge sort?

Quick nhanh hơn trong thực tế và tốn ít bộ nhớ, nhưng ca xấu O(n²). Merge ổn định và luôn O(n log n), đổi lại O(n) bộ nhớ.

Khi nào sắp xếp nhanh hơn O(n log n)?

Khi không dùng so sánh: counting sort và radix sort đạt O(n) nếu miền giá trị nhỏ hoặc khoá là số nguyên ngắn.
