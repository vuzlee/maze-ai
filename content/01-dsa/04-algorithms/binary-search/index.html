Binary search

One code template covers every problem. Read for 2 minutes, then jump straight down to the patterns to practice.

01

Mental model

It is not "find an element". It is find the boundary between FALSE and TRUE.

  • The only requirement: once TRUE, always TRUE. A sorted array is just one instance.
  • The check function may cost O(n) — that opens up pattern 2, the most common form.
02

The one code template to memorize

Learn this one template. The next four patterns are all it with a few words changed.

def lower_bound(a, t):        # FIRST index with a[i] >= t
    lo, hi = 0, len(a)        # half-open [lo, hi)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < t: lo = mid + 1   # mid is surely wrong → drop it
        else:          hi = mid       # mid may be right → keep it
    return lo
What follows from it

first position → lower_bound(a,t)

last position → upper_bound(a,t) - 1

count of occurrences → upper - lower

exists → a[i] == t after the search

upper_bound differs by one sign

a[mid] < t → a[mid] <= t

Built into the library:

bisect_left = lower_bound
bisect_right = upper_bound

03

Common mistakes

Nearly every buggy binary search falls into one of these three mistakes.

Mixing two conventions

while lo < hi goes with hi = mid. while lo <= hi goes with hi = mid - 1. Don't mix them.

Hanging with 2 elements left

If there is a lo = mid branch, round up: mid = (lo + hi + 1) // 2.

Forgetting to check the result

lower_bound always returns an index. You must check i < len(a) and a[i] == t.

Pattern 2 — searching the answer space

Signals: "smallest / largest such that…" · nothing in the array to search for · values range up to 10⁹

Replace a[mid] < t with a check function you write yourself:

lo, hi = min_possible, max_possible
while lo < hi:
    mid = (lo + hi) // 2
    if feasible(mid): hi = mid       # feasible → try smaller
    else:             lo = mid + 1   # infeasible → must go larger
return lo                            # O(n · log range)

feasible costing O(n) is normalto find the LARGEST value, switch to lo = mid and mid = (lo+hi+1)//2

Pattern 3 — rotated arrays

Signals: "a sorted array rotated at some pivot"

if a[lo] <= a[mid]:                     # LEFT half is sorted
    if a[lo] <= t < a[mid]: hi = mid - 1
    else:                   lo = mid + 1
else:                                   # RIGHT half is sorted
    if a[mid] < t <= a[hi]: lo = mid + 1
    else:                   hi = mid - 1

To find the minimum, compare a[mid] with a[hi], not with a[lo] — that fails when the array is not rotated.

Pattern 4 — UNSORTED arrays

Signals: "an element larger than both neighbors" · you only need to know which direction is right

while lo < hi:
    mid = (lo + hi) // 2
    if a[mid] < a[mid + 1]: lo = mid + 1
    else:                    hi = mid
return lo
