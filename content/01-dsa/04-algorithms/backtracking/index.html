Backtracking

One six-line skeleton solves subsets, permutations, N-Queens. Read for 2 minutes, then go down to the patterns.

01

Mental model

Going down you choose, coming back up you unchoose — there is only one shared state, so you must restore it exactly. What remains is asking "still valid?" as early as possible: the same check, asked at the leaves or at every level, differs by nine thousand times.

  • For an unpruned tree the number of leaves is the complexity: subsets 2n, permutations n!, combinations C(n, k). For a pruned tree there is no formula — 2,057 cannot be derived from 8; you have to measure.
  • Whether you can prune depends on keeping the set of occupied states ready to answer "still valid?" in O(1) — section 09.
  • Removing duplicate results is also a form of pruning, and it too must happen inside the loop, not as a filter at the end — section 02.
02

Six-line skeleton to memorize

Three jobs: record the result · choose · unchoose. Every problem differs only in the for line.

def bt(start, path):
    res.append(path[:])                # copy it, don't push path itself
    for i in range(start, n):
        if not is_valid(a[i]): continue    # prune
        path.append(a[i])              # CHOOSE
        bt(i + 1, path)               # go down
        path.pop()                     # UNCHOOSE — mandatory
Change one spot, get another problem

bt(i + 1) → each element used once

bt(i) → may be reused (combination sum)

range(0, n) + a used array → permutations

Removing duplicate results

Sort first, then inside the for loop:

if i > start and a[i] == a[i-1]: continue

03

Common mistakes

The first trap makes every result identical — hit it once and you never forget.

Forgetting to copy path

res.append(path) pushes a reference; when path changes later, every result changes with it. You need path[:].

Forgetting to undo

Without path.pop() the next branch inherits the previous branch's state. This applies to used, grid cells, counters too.

Filtering at the end instead of pruning in the loop

set(tuple(x) for x in res) gives the right result, so it looks fixed — but the tree is still fully built and still times out. Pruning must happen before going down.

04

Lab: decision tree

The number of undo steps is nearly the number of choose steps — that is half the algorithm's work.
