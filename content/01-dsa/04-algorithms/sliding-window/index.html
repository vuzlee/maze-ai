Sliding window

One stretch-and-shrink template covers nearly every problem. Read for 2 minutes, then go down to the patterns to practice.

01

Mental model

Both edges only move forward, never back — each moves at most n steps, so the total is O(n). The price of never going back: whatever is skipped is skipped for good, so the technique is only right when widening the window is guaranteed to make the condition worse.

  • Nested loops are O(n²) because the inner index restarts from the beginning. In a window, L continues from where it stands — that is the entire saving.
  • When monotonicity is lost, change tools instead of patching: prefix sum + hash map for problems with negatives — Prefix sum.
  • A window can count "at most k" but cannot count "exactly k" directly — also a consequence of moving in only one direction — section 07.
02

Code template to memorize

Learn this one template. All three patterns that follow are it with a few words changed.

# STRETCH-AND-SHRINK WINDOW — LONGEST subarray satisfying a condition
L = 0
for R in range(len(a)):
    add a[R] to the window
    while window_violates:
        remove a[L] from the window; L += 1
    best = max(best, R - L + 1)   # AFTER the while loop
LONGEST problems

while the condition is violated → shrink L

update best after the while loop

SHORTEST problems

while the condition holds → update, then shrink L

update best inside the while loop

03

Common mistakes

A simple technique, but get these three wrong and it fails silently — the code still runs, still produces output.

Counting 1 instead of R-L+1

In a count the subarrays problem, doing just cnt += 1 each step misses every shorter subarray ending at R.

For "bcbcccc", k=1: the answer is 13, you get 7 — section 07.

Updating best in the wrong place

Longest problems: update after the while loop. Shortest problems: update inside the while loop.

Forgetting to remove an element when shrinking

Move L without subtracting from the counter and the window decays, going wrong from mid-array onward.

05

Pattern 1 — fixed window k

Signals: the problem gives a length k · "every subarray of length k" · anagrams, permutations

Drop the while loop entirely — the length is known up front, so shrinking is a single if.

for R in range(len(a)):
    add a[R]
    if R >= k: remove a[R - k]     # the window always holds exactly k elements
    if R >= k - 1: update the result

07

Pattern 3 — counting via at-most-K

Signals: "COUNT the subarrays with EXACTLY k…" — a window can't count that directly

Still the stretch-and-shrink template, but run twice and subtract.

exactly_k = at_most(k) - at_most(k - 1)

# at_most returns a NUMBER OF SUBARRAYS, not a length:
while violates: remove a[L]; L += 1
cnt += R - L + 1          # every subarray ending at R is valid
