Interval

This whole group fits in one sentence: choose the right sort key and half the problem is done.

01

Mental model

Once sorted, you only compare with the previous interval — O(n²) down to O(n log n). But which key you sort by is what decides right or wrong, and choosing the wrong one raises no alarm.

  • Sort by start point — merging intervals, inserting an interval, counting gaps.
  • Sort by end point — picking the most non-overlapping intervals, scheduling, removing the fewest intervals.
  • Sweep line needs neither key: it splits intervals into enter/leave events and keeps a running sum — section 03.
02

Code template to memorize

Merging, and picking non-overlapping intervals. They differ exactly in the sort key.

# MERGE INTERVALS — sort by START
a.sort()
res = []
for s, e in a:
    if res and s <= res[-1][1]:              # overlaps the last one
        res[-1][1] = max(res[-1][1], e)
    else:
        res.append([s, e])
# PICK THE MOST non-overlapping — sort by END
a.sort(key=lambda x: x[1])
cnt, last_end = 0, -float("inf")
for s, e in a:
    if s >= last_end: cnt += 1; last_end = e
03

Sweep line

Turn each interval into two events: enter (+1) and leave (−1). Sort all events by time, then keep a running sum.

9:00+1
9:30+1
10:00+1
10:30−1
11:00−1
12:00−1

running sum: 1 · 2 · 3 · 2 · 1 · 0peak 3 = meeting rooms needed

ev = []
for s, e in a: ev.append((s, 1)); ev.append((e, -1))
ev.sort()                       # same time: -1 before +1 (close before open)
cur = best = 0
for _, d in ev:
    cur += d; best = max(best, cur)   # best = the maximum number of overlapping intervals
  • Directly answers "how many meeting rooms are needed" — that is exactly the maximum number of overlapping intervals.
  • A second way gives the same result: a heap of end points; the heap size is the number of rooms in use.
  • The ordering on equal times decides whether boundaries are closed or open — ask the interviewer if the problem doesn't say.
04

Common mistakes

The first trap shifts the result by exactly one — the hardest kind of bug to see.

Closed or open boundaries

Do [1,2] and [2,3] overlap? For meetings no, for line segments yes. Ask before you code.

Sorting mutates the original array

a.sort() changes the array the problem gave you. If a problem still needs the original order later — matching indices, printing in input order — use sorted(a) or save the indices before sorting.

Forgetting the max when merging

res[-1][1] = max(res[-1][1], e) — without the max, an interval nested inside will cut the merged interval short.
