Prefix sum & difference array

One pass up front, then every query costs just one subtraction.

01

Mental model

The sum of range [l, r] = the sum up to r minus the sum up to l−1. In return you scan once up front — so asking one query loses 6.4×, asking 10,000 queries gains 481×.

  • What you gain is a flat cost column. A direct scan costs in proportion to range length: 0.16 µs for one cell but 324 µs for the whole array. Prefix stays at 0.06 µs however long the range — that is the real meaning of "O(1) per query".
  • Three questions before using it: how many queries are there, is the array modified midway, and does the operation have an inverse. Without an inverse the subtraction formula is meaningless — a range max, for example, has no prefix form; use a sparse table.
  • With interleaved updates, switch to a Fenwick tree: both updates and queries are O(log n), neither extremely cheap but neither extremely expensive.
02

Code template to memorize

Always keep pre[0] = 0. Padding one cell at the front removes every off-by-one error.

# 1 — one dimension
pre = [0] * (n + 1)
for i in range(n): pre[i+1] = pre[i] + a[i]
range_sum = lambda l, r: pre[r+1] - pre[l]      # [l, r] both ends inclusive
# 2 — two dimensions: rectangle sum, inclusion–exclusion on four corners
pre[i+1][j+1] = a[i][j] + pre[i][j+1] + pre[i+1][j] - pre[i][j]

# 3 — DIFFERENCE ARRAY: add v to the whole range [l, r] in O(1)
diff[l] += v; diff[r+1] -= v
# finally, the prefix sum of diff gives the resulting array

prefix sum: cheap range queriesdifference array: cheap range updates — the two are opposites

03

Prefix + hash map

The most common pattern: count subarrays whose sum equals k. With negative numbers, sliding window gives up.

seen = {0: 1}          # sum 0 seen once: the empty range
s = ans = 0
for x in a:
    s += x
    ans += seen.get(s - k, 0)   # how many ranges end here
    seen[s] = seen.get(s, 0) + 1
  • seen counts, it does not just mark. The same sum can appear many times (here sum 0 appears three times), and each time is a different range — turn seen into a set and you only count one.
  • Change what the map stores and you change the problem. Store sums → sum equals k; store remainders s % k → ranges divisible by k; turn 0s into −1 and store sums → ranges with equal numbers of 0s and 1s. The code skeleton doesn't change a single line.
  • The price: you trade O(n²) for O(n) time but spend O(n) extra memory, and lose the ability to say which range — the map only counts; to list ranges you must store whole lists of indices.
04

Common mistakes

All four are off by one cell — the code runs, no exception, the result is off by a few.

Forgetting the pre[0] = 0 padding

Without the padding cell, ranges starting at 0 need special handling, and sooner or later you forget.

Mixing up closed/open bounds

pre[r+1] − pre[l] gives range [l, r] with both ends. Writing pre[r] − pre[l] by mistake drops one element.

Difference array out of bounds

diff[r+1] needs an array of length n+1. Allocating exactly n cells is an index error for ranges touching the end.

2D version forgets to add back the corner

Subtracting two strips subtracts their overlap twice; you must + pre[r1][c1] to compensate.

The trap: every rectangle touching the top-left edge comes out right even without that term (the corner is 0).

A test like [0,0] won't catch it; on a 3×3 grid, the cell range [1..2]×[1..2] finally shows 27 instead of 28.
