Shortest path

Three algorithms, three situations. Picking the right one means reading the problem's constraints, not memorizing code.

01

Mental model

The three algorithms differ in the assumptions they make about the graph, not in speed. Pick the wrong one and the code still runs smoothly and returns a wrong number — that is why you read the constraints before typing.

  • All edges equal → BFS, not Dijkstra: simpler and faster. For why BFS and Dijkstra are the same loop, see the section 01 figure in the Graph lesson.
  • Positive edges, one source → Dijkstra (section 02) — the default for nearly every problem.
  • Negative edges, or the problem limits the number of stops → Bellman-Ford (section 03). Need every pair of vertices and V is small → Floyd-Warshall (section 04).
02

Dijkstra

Take the cheapest unprocessed vertex first. Once taken out, its distance is final.

popthe cheapest vertex in the heap
finalizeits distance is final
relaxevery outgoing edge: if cheaper, push a new entry
import heapq
dist = {start: 0}
pq = [(0, start)]
while pq:
    d, u = heapq.heappop(pq)
    if d > dist.get(u, INF): continue      # stale entry, skip it
    for v, w in adj[u]:
        if d + w < dist.get(v, INF):
            dist[v] = d + w
            heapq.heappush(pq, (dist[v], v))
  • Cost O((V + E) log V). Don't delete stale entries from the heap — skipping them on pop is enough.
  • Dies on negative edges: the "popped means final" assumption breaks, because a later negative edge can make a path cheaper.
  • Weights only 0 and 1 → use 0-1 BFS with a deque, cheaper than a heap.
03

Bellman-Ford

No heap. Relax every edge, repeated V − 1 times — slower, but it tolerates negative edges.

rounds 1…V − 1relax ALL edges each round
round Vstill improving → there is a negative cycle
for _ in range(V - 1):                  # a shortest path has at most V-1 edges
    for u, v, w in edges:
        if dist[u] + w < dist[v]: dist[v] = dist[u] + w

for u, v, w in edges:                  # round V: still improving
    if dist[u] + w < dist[v]: return "negative cycle"
  • Cost O(V · E) — much slower than Dijkstra, use it only when you must.
  • Round V is the trick for detecting a negative cycle: still improving means you can loop forever to get cheaper.
  • With a limit of at most k edges, run exactly k rounds — that is the solution to Cheapest Flights.
04

Floyd-Warshall

Three nested loops for every pair of vertices. Only worth it when the graph is small.

for k in range(V):              # k MUST be the outermost loop
    for i in range(V):
        for j in range(V):
            d[i][j] = min(d[i][j], d[i][k] + d[k][j])

O(V³) — fine for V ≤ 400k outermost: "may only pass through vertices 0..k"

  • The shortest code of the three, and it tolerates negative edges (as long as there is no negative cycle).
  • Swapping the loop order is wrong — the classic bug of this algorithm.

Choosing an algorithm
