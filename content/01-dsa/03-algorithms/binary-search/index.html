02

Mẫu code duy nhất cần thuộc

Học một mẫu này. Bốn pattern sau đều là nó đổi vài chữ.

def lower_bound(a, t):        # chỉ số ĐẦU TIÊN có a[i] >= t
    lo, hi = 0, len(a)        # nửa mở [lo, hi)
    while lo < hi:
        mid = (lo + hi) // 2
        if a[mid] < t: lo = mid + 1   # mid chắc chắn sai → bỏ
        else:          hi = mid       # mid có thể đúng → giữ
    return lo
Từ nó suy ra

vị trí đầu tiên → lower_bound(a,t)

vị trí cuối cùng → upper_bound(a,t) - 1

đếm số lần → upper - lower

có tồn tại → a[i] == t sau khi tìm

upper_bound chỉ khác một dấu

a[mid] < t → a[mid] <= t

Thư viện có sẵn:

bisect_left = lower_bound
bisect_right = upper_bound

03

Ba bẫy

Gần như mọi lần code sai binary search đều rơi vào một trong ba lỗi này.

Trộn hai quy ước

while lo < hi đi với hi = mid. while lo <= hi đi với hi = mid - 1. Không trộn.

Treo khi còn 2 phần tử

Có nhánh lo = mid thì phải làm tròn lên: mid = (lo + hi + 1) // 2.

Quên kiểm tra kết quả

lower_bound luôn trả về một chỉ số. Phải kiểm i < len(a) and a[i] == t.

Pattern 3 — mảng xoay

Dấu hiệu: "mảng sắp xếp bị xoay tại một điểm"

if a[lo] <= a[mid]:                     # nửa TRÁI đang sắp xếp
    if a[lo] <= t < a[mid]: hi = mid - 1
    else:                   lo = mid + 1
else:                                   # nửa PHẢI đang sắp xếp
    if a[mid] < t <= a[hi]: lo = mid + 1
    else:                   hi = mid - 1

Tìm phần tử nhỏ nhất thì so a[mid] với a[hi], đừng so với a[lo] — sai khi mảng chưa bị xoay.

10

Hỏi đáp phỏng vấn

Tự trả lời thành tiếng trước, rồi mới mở ra.

Vì sao dùng lo < hi thay vì lo <= hi?

lo <= hi đi với khoảng đóng và hi = mid - 1; lo < hi đi với nửa mở và hi = mid. Tôi dùng nửa mở vì nó trả thẳng ra ranh giới.

Khi nào binary search đúng mà mảng không sắp xếp?

Khi có hàm kiểm tra đơn điệu. Điều kiện là tính đơn điệu, không phải sự sắp xếp.

Giải thích binary search trên đáp án.

Tìm trên miền giá trị của đáp án, không phải trên mảng. Chặn miền → viết feasible(x) → chứng minh đơn điệu. Chi phí O(n log miền).

Làm sao chắc code không lặp vô hạn?

Chỗ chết duy nhất: còn hai phần tử thì mid == lo, gặp nhánh lo = mid là đứng yên. Chữa bằng (lo + hi + 1) // 2.
