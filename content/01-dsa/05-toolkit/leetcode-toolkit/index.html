LeetCode toolkit

The six things that shorten solutions the most. Three to remember:

  • sorted sequence? use bisect, don't scan
  • need both ends? use deque, not list
  • need only k elements? use heapq, don't sort everything
01

bisect

In a sorted sequence, find a position by halving, dropping half at every step.

  • Measured on 100,000 elements: bisect_left 143 ns, linear scan 2866 µs — 20,106× faster.
  • bisect_left returns the leftmost position, bisect_right the rightmost — they differ when there are duplicates.
  • insort inserts as well, but inserting into a list is still O(n) because of shifting — only the search part is cheap.
  • Used for: finding left/right bounds, counting elements smaller than x, "find the smallest value that satisfies a condition" problems.
02

Dicts with defaults

Both are a dict, adding only default behavior when a key is missing.

  • Counter counts for you and has most_common(k); a missing key returns 0 instead of raising KeyError.
  • Also faster than counting by hand: 1.60 ms vs 2.52 ms on 50,000 elements.
  • defaultdict(list) removes the if k not in d line entirely when grouping by key.
  • Careful: merely reading d[k] on a defaultdict creates a new key.
03

deque

Adding and removing at both ends is O(1). With a list, the left end has to shift the whole sequence.

  • Measured on 100,000 elements: deque 20 ns, list 29.6 µs — 1,446× faster.
  • The trade-off: accessing a middle element is O(n), because a deque is a doubly linked list of blocks.
  • deque(maxlen=k) pushes old elements out by itself — use it for a fixed sliding window.
  • Used for: BFS, sliding window, undo history.
04

heapq

If you only need the k smallest elements, don't sort the whole sequence — ordering the rest is wasted work.

  • Measured on 100,000 numbers: nsmallest(10) 0.87 ms, sorted()[:10] 14.67 ms — 17× faster.
  • heapq is a min-heap. For a max-heap, push negated values, or use a tuple (-priority, item).
  • Top-k over a data stream: keep a heap of size k — O(n log k) instead of O(n log n).
  • Used for: the k largest elements, merging k sorted sequences, Dijkstra, task scheduling.
05

Comprehension

Three lines become one, and slightly faster because it doesn't call append on every iteration.

  • Four variants: conditional, dict, set, and generator expression.
  • A generator expression doesn't build the whole list — use it when the data is large and iterated only once.
  • Don't nest more than two levels: at that point a loop is usually easier to read.
  • A comprehension's loop variable doesn't leak outside — see Scope & LEGB.
06

Choosing a tool

Recognize the problem type and you know which tool to use.

Signal in the problemTool
sorted sequence, finding bounds, counting elements smaller than xbisect
counting frequencies, finding the most common elementCounter
grouping by key, building an adjacency listdefaultdict
BFS, sliding window, working at both endsdeque
k largest/smallest, merging k sequences, Dijkstraheapq
transforming or filtering a sequencecomprehension
  • All six are in the standard library — nothing to install.
  • Knowing the right tool often cuts a solution from 20 lines to 5.
