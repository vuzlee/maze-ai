DSA overview

Data structures decide how data is held; algorithms decide which steps run on it. Pick the right pair and the same problem goes from minutes to milliseconds.

01

What DSA is

Data structures are shapes for holding data; algorithms are moves that run on those shapes. This shelf is these sixteen pictures.

  • Each shape makes some operations cheap and others costly — the trade-off is measured in Big-O.
  • Most interview problems are one structure plus one move: a hash map with a sliding window, a heap with a greedy choice.
02

Family tree

There are only two ways to hold data — side by side, or linked by pointers; every other structure grows from them.

  • An array gives instant access by position but costly inserts; a linked node is the opposite. Each child picks a trade-off between the two.
  • Hybrids take the best of both: a hash map is an array of buckets that chain; a heap is a tree laid flat in an array.
03

Problem to technique

The shape of the input names the technique before you write a line.

  • Each pill is a lesson with its own sign list and LeetCode problems; the LeetCode toolkit holds the full checklist.
04

Learning order

Follow this order and each lesson adds just one new idea.

1 · Big-ORead the data size, know which approach is allowed.
2 · Array & string → hash mapThe two storage choices behind most problems.
3 · Two pointers → sliding window → binary searchThe three cheapest ways to scan.
4 · Stack · heap · tree & BSTStorage for order; trees open the door to recursion.
5 · Graph → backtrackingWalk over every situation that can occur.
6 · Dynamic programmingLast, because it builds on recursion.
