Array & string

The simplest structure, and the place where hidden costs are most often overlooked.

01

Mental model

Elements sit next to each other in memory, so a position is computed with one multiplication. Reading any cell costs 10 ns, even in a 10-million-element array — but inserting at the front of a million-element array costs 42,767× as much as inserting at the end.

  • Same O(n), very different price. Scanning a 1,000,000-element array takes 5.53 ms, while one insert(0,x) takes 0.97 ms — nearly a sixth of a full scan, just to add one number.
  • Sequential reads are even faster than Big-O suggests, because the hardware prefetches whole blocks into cache. That is why sum(a) on a list and on a deque are nearly equal (5.53 and 5.85 ms) even though their insides are completely different.
  • Every operation that shifts elements is O(n): insert(0,x), pop(0), remove(x). Need to add/remove at both ends? Use deque. Need both middle inserts and index access? Then an array is not the right structure.
02

How a dynamic array grows

When it runs out of room it allocates a bigger block and copies over. Textbooks say "double" — CPython actually grows only 1.125×, so it grows 86 times over a million appends, not 20.

  • "Amortized O(1)" does not mean every call is cheap. 86 out of a million calls are expensive — the one that hits the ceiling at n = 1,000,000 has to copy a million elements. Any system sensitive to tail latency (p99) should preallocate rather than let the array grow by itself.
  • Growth is one-way. del a[500000:] deletes half of a million-element list, but getsizeof still reports 8,000,056 bytes as before; you have to list(a) to make a new copy to get down to 4,000,056. Memory is only returned when the old object dies.
  • The three ways to build a million cells differ by how often they touch the interpreter, not by bytes: [0]*n is a single C operation, append is a million Python calls.
03

Immutable strings

Python strings cannot be modified in place: in principle every concatenation copies everything. But measured, s += c is linear — and just one harmless-looking line drops it to quadratic.

  • The shortcut is an implementation detail, not a guarantee. It is not in the language spec, not in PyPy or Jython, and vanishes as soon as someone adds an intermediate variable. "".join(parts) is the fastest of all three columns and depends on no condition.
  • For the same reason, slicing s[1:] is O(n) — it builds a new string, it does not point into the old one. Recursion with slicing turns O(n log n) into O(n²) with nothing visible in the code.
  • Need to modify individual characters? Switch to a list of characters, then "".join() when done — one allocation, one copy, no reliance on the shortcut.
04

Common mistakes

All three fail silently — the code runs and still produces output.

Shallow copy

b = a only adds another name. grid = [[0]*m]*n creates n references to the same row — change one row and they all change.

Deleting while iterating

Deleting shifts indices, so the loop skips elements. Iterate backwards, or build a new list.

Negative indices raise no error

a[-1] is the last element, not an error. Compute a negative index by accident and the code quietly reads from the other end.

grid = [[0] * m for _ in range(n)]   # right: n independent rows
import copy; b = copy.deepcopy(a)          # when nested
