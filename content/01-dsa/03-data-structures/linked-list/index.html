Linked list

Rarely used in real work, but asked a lot because it immediately exposes anyone careless with pointers.

01

Mental model

Drop contiguity, link with pointers. Insert/delete become O(1) — but only counting from the moment you hold the node. Finding that node is still O(n), and that is where every "array or linked list" comparison is really decided.

  • Dummy node (a fake node in front of head) removes the special case "modify right at the head" entirely — section 02.
  • Fast–slow two pointers find the middle node or detect a cycle in a single pass — section 05.
  • Cache locality: nodes are scattered, so traversal is still slower than an array at the same O(n) — the last row in the figure.
02

Code template to memorize

Reversing a list, the dummy node, and fast–slow two pointers. Almost every problem is a combination of these three.

# 1 — REVERSE: three pointers, each loop flips one link
prev, cur = None, head
while cur:
    nxt = cur.next        # save before cutting
    cur.next = prev       # flip
    prev, cur = cur, nxt  # advance
return prev              # prev is the new head
# 2 — DUMMY NODE: removes the "delete/insert at head" case
dummy = ListNode(0, head)
p = dummy
... p.next = ...
return dummy.next

# 3 — FAST & SLOW: find the middle, detect a cycle
slow = fast = head
while fast and fast.next:
    slow, fast = slow.next, fast.next.next

The dummy node is the cheapest trick in this groupit removes half the edge cases you'd have to think about

03

Common mistakes

All three make the program loop forever or lose data.

Losing the reference

Assigning cur.next = prev before saving cur.next cuts off the rest of the list. Always save nxt first.

Off by one node

To delete the k-th node you must stand at node k−1. Use a dummy node so the head case needs no special handling.

Forgetting the empty case

head is None and a one-node list must work correctly. while fast and fast.next — leave out the first half and it fails immediately.
