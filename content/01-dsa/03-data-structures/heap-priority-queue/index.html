01

Mental model

A heap pins exactly one cell: the smallest sits at cell 0. Every other cell is loose — and that looseness is exactly what is worth paying for: with no sorting, getting the 10 smallest of a million numbers is 25× faster.

  • Peek at the smallest in O(1); pop the smallest and push are both O(log n) — the three operations a heap has.
  • Finding or modifying an arbitrary element is still O(n): the table above shows why — no cell other than cell 0 is pinned.
  • Because each element only moves up or down along one branch, the parent is (i-1)//2 and the children are 2i+1, 2i+2 — the tree needs no pointers and fits neatly in a flat array.
02

Code template to memorize

Python only has a min-heap. Need a max-heap? Push negated numbers.

import heapq
h = []
heapq.heappush(h, x)          # O(log n)
heapq.heappop(h)              # pop the SMALLEST, O(log n)
h[0]                          # peek the smallest, O(1)
heapq.heapify(a)              # turn a list into a heap in place, O(n)

heapq.heappush(h, (-val, x))  # MAX-heap: negate
heapq.heappush(h, (priority, seq, obj))   # avoid comparing obj on equal priority

Keeping the K largest: use a min-heap of size K; once full, heappushpop each time — O(n log K).

03

Common mistakes

The first trap crashes the code at runtime; the other two make it slow.

Pushing objects into a heap

Two entries with equal priority → Python compares the second item → error if the objects are not comparable. Put a sequence number in between.

Using a max-heap and forgetting to negate on the way out

Push -val, and on pop remember -heappop(h)[0].

Changing the priority of an element already in the heap

You find a shorter path and write node[0] = d_new directly: the heap does not know to sift again, and 83% of the following pops return the wrong element.

The right way is to push a new copy and skip the stale one when popping.
