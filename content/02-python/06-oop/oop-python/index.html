OOP trong Python

Bài này chỉ nói ngôn ngữ hỗ trợ gì qua cú pháp — bốn trụ encapsulation, abstraction, inheritance, polymorphism. Nên thiết kế thế nào (composition, SOLID, design pattern) là quyết định của người viết code, không phải cú pháp ép buộc — nằm ở một bài riêng.

01

Class & object

Tra thuộc tính đi từ instance lên class, rồi lên các lớp cha. Dừng ở chỗ đầu tiên tìm thấy.

class Dog:
    loài = "chó"              # class attribute — DÙNG CHUNG mọi instance
    def __init__(self, tên):
        self.tên = tên          # instance attribute — riêng từng con

d = Dog("Mực")
d.tên                           # tìm thấy ở instance
d.loài                          # không có ở instance → tìm lên class
d.loài = "cún"                 # TẠO MỚI ở instance, không sửa class
  • Gán d.loài không sửa class — nó tạo một thuộc tính riêng che mất cái của class.
  • Nhưng class attribute là mutable (list, dict) thì mọi instance dùng chung một object — đây là bẫy ở mục 08.
  • self không phải từ khoá, chỉ là tham số đầu tiên theo quy ước.
02

Encapsulation

Gộp dữ liệu và hành vi thao tác trên dữ liệu đó vào một đơn vị, rồi giấu chi tiết cài đặt — Python làm việc này bằng quy ước đặt tên, không phải từ khoá bảo mật thật.

class TàiKhoản:
    def __init__(self, số_dư):
        self._số_dư = số_dư          # _ : quy ước "đừng đụng từ ngoài", KHÔNG bị chặn
        self.__pin = "1234"          # __ : name mangling → self._TàiKhoản__pin

    @property
    def số_dư(self):
        return self._số_dư

    @số_dư.setter
    def số_dư(self, giá_trị):
        if giá_trị < 0:
            raise ValueError("số dư không được âm")
        self._số_dư = giá_trị
_x — quy ước "protected"chỉ là tín hiệu cho người đọc; Python không chặn truy cập obj._x từ bên ngoài
__x — name manglingPython đổi tên thành _TênClass__x, để chống trùng tên vô tình khi kế thừa, không phải bảo mật
@propertychặn được ở obj.x = v mà cú pháp gọi không đổi — nơi duy nhất Python cho kiểm soát truy cập có logic
  • Python tin ở người lớn: không có private thật như Java/C++, chỉ có quy ước và một mẹo đổi tên.
  • @property là encapsulation đúng nghĩa duy nhất — validate được mà code gọi vẫn viết như phép gán thường.
03

Abstraction

Định nghĩa phải có gì, không nói làm thế nào — lớp con tự quyết định cách làm.

from abc import ABC, abstractmethod

class HìnhDạng(ABC):
    @abstractmethod
    def diện_tích(self): ...    # bắt buộc lớp con phải override

class HìnhVuông(HìnhDạng):
    def __init__(self, cạnh): self.cạnh = cạnh
    def diện_tích(self): return self.cạnh ** 2

HìnhDạng()      # TypeError — không khởi tạo được lớp trừu tượng
  • Đây là abstraction tường minh: quên override diện_tích thì báo lỗi ngay lúc khởi tạo, không phải lúc gọi hàm.
  • Abstraction ngầm qua duck typing: không cần ABC, chỉ cần đúng phương thức. Muốn ghi rõ giao diện thì dùng Protocol.
  • Encapsulation giấu dữ liệu trong một object; abstraction giấu khác biệt giữa nhiều object — hai trụ dễ nhầm nhất.
04

Inheritance

super() không có nghĩa "lớp cha". Nó là lớp kế tiếp trong MRO — khác nhau khi đa kế thừa.

class Animal:
    def __init__(self, tên): self.tên = tên

class Dog(Animal):
    def __init__(self, tên, giống):
        super().__init__(tên)     # gọi lớp kế tiếp trong MRO
        self.giống = giống
  • Luôn gọi super().__init__() trong __init__ của lớp con — quên là lớp cha không được khởi tạo.
  • Kế thừa chỉ đúng với quan hệ "là một": Dog là một Animal. Quan hệ "có một" thì dùng composition.
05

Polymorphism

Python không hỏi object thuộc lớp nào. Nó chỉ hỏi có phương thức cần dùng không.

def mô_tả(x):
    print(x.kêu())      # chạy với BẤT KỲ object nào có .kêu()
                        # không cần kế thừa chung lớp cha
  • Đây là duck typing: "nhìn như vịt, kêu như vịt thì là vịt".
  • Muốn ghi rõ giao diện mà vẫn giữ duck typing → dùng Protocol, xem type hints.
  • Đè phương thức (override) chỉ cần trùng tên — không có từ khoá nào bắt buộc.
06

MRO

Đa kế thừa cần một thứ tự tra cứu xác định. Python dùng thuật toán C3.

  • Quy tắc C3: lớp con luôn đứng trước lớp cha, và giữ nguyên thứ tự khai báo class D(B, C).
  • Nhờ đó A.__init__ chỉ chạy một lần dù có hai đường đi tới — miễn là mọi lớp đều gọi super().
  • Xem thứ tự thật bằng D.__mro__. Thứ tự không dựng được thì Python báo lỗi ngay lúc định nghĩa class.
07

Tổng kết một hình

Bốn trụ OOP trong Python đều dựa trên đúng một cơ chế: tra tên đi từ instance lên class rồi lên MRO — và dừng ở chỗ đầu tiên tìm thấy.

  • Name mangling — ở ②: đổi tên để chống trùng khi kế thừa, không phải để bảo mật.
  • @property — ở ②: nơi duy nhất Python cho kiểm soát truy cập có logic mà cú pháp gọi vẫn như phép gán thường.
  • Duck typing — ở ②: lý do polymorphism trong Python không cần lớp cha chung.
  • MRO — ở ③: thứ tự tra cứu do thuật toán C3 dựng, và cũng là đích thật của super().
08

Lỗi hay gặp

Bẫy đầu tiên là câu hỏi phỏng vấn Python kinh điển nhất.

Mutable làm giá trị mặc định

def __init__(self, items=[]) — list đó tạo một lần lúc định nghĩa hàm và dùng chung cho mọi instance. Viết items=None rồi gán trong thân hàm.

Đè __eq__ mà quên __hash__

Object hết hashable, cho vào set là lỗi. Xem data model.

Tưởng _x/__x là bảo mật thật

_x chỉ là quy ước, truy cập được bình thường. __x bị đổi tên chứ không bị chặn — ai cũng gọi được qua obj._TênClass__x.

Kế thừa để dùng lại code

Quan hệ "có một" mà đi kế thừa là khoá chặt hai lớp vào nhau — đó là composition bị dùng sai chỗ, xem bài Design Patterns.

09

Hỏi đáp

Tự nghĩ ra ý trả lời trước rồi mới mở — cốt là hiểu ý, không phải thuộc chữ.

super() gọi tới đâu?

Tới lớp kế tiếp trong MRO, không phải "lớp cha". Với đa kế thừa hai thứ đó khác nhau.

Encapsulation và abstraction khác nhau ở đâu — hai khái niệm rất hay bị lẫn?

Encapsulation giấu dữ liệu bên trong một object (biến _x, @property). Abstraction giấu sự khác biệt giữa nhiều loại object đứng sau cùng một giao diện (ABC, duck typing). Encapsulation trả lời "bên trong object này có gì"; abstraction trả lời "tôi cần gọi gì, không cần biết object nào đang xử lý".

_x và __x khác nhau thế nào?

_x chỉ là quy ước — Python không chặn gì, chỉ báo hiệu cho người đọc "đừng đụng từ ngoài". __x bị name mangling đổi thành _TênClass__x, mục đích là tránh trùng tên vô tình khi kế thừa, không phải để bảo mật.

MRO giải quyết vấn đề gì?

Đa kế thừa hình kim cương: nó cho một thứ tự tra cứu xác định nên lớp gốc chỉ chạy một lần.

Vì sao không nên để list làm giá trị mặc định?

Vì nó được tạo một lần lúc định nghĩa hàm và dùng chung mọi lần gọi. Dùng None rồi gán bên trong.
