Python · typing

Type hints & dataclass

Python không kiểm tra type hint lúc chạy. Chúng viết cho người đọc và công cụ — hiểu đúng điều này là dùng đúng.

01

Vì sao có type hints

Chúng là chú thích, không phải ràng buộc. Chạy vẫn chạy dù truyền sai kiểu.

def chia(a: int, b: int) -> float:
    return a / b

chia("x", "y")      # Python KHÔNG chặn — lỗi chỉ nổ ở phép chia
                     # mypy / pyright thì báo ngay lúc kiểm tra
  • Ai đọc: static checker (mypy, pyright), IDE để gợi ý, và người bảo trì sau bạn.
  • Muốn kiểm tra thật lúc chạy thì phải dùng thư viện như pydantic — nó đọc hint rồi tự sinh code kiểm tra.
  • Lợi ích lớn nhất không phải bắt lỗi mà là hàm tự mô tả nó nhận gì trả gì, khỏi phải đọc thân hàm.
02

Cú pháp cơ bản

Bốn thứ phủ 90% nhu cầu: kiểu cơ bản · container · Optional · Union.

tên: str = "Mai"
điểm: list[float] = []                # Python 3.9+: dùng list, không phải List
bảng: dict[str, int] = {}

def tìm(id: int) -> User | None:        # 3.10+: | thay cho Optional[User]
    ...

def xử_lý(x: int | str) -> None:         # nhận một trong hai kiểu
    ...

trả về None thì ghi -> Nonebỏ trống nghĩa là "chưa chú thích", checker sẽ không kiểm tra hàm đó

03

Generic

Dùng khi kiểu trả về phụ thuộc kiểu đầu vào. Không có nó thì phải trả về Any và mất hết thông tin.

def đầu_tiên(xs: list[T]) -> T | None:      # Python 3.12+: def đầu_tiên[T](...)
    return xs[0] if xs else None

# checker biết: đầu_tiên([1,2]) là int | None
#              đầu_tiên(["a"]) là str | None
  • Trước 3.12 thì khai báo T = TypeVar("T") ở đầu file; từ 3.12 viết thẳng def f[T](...).
  • Dùng generic khi quan hệ giữa vào và ra mới là thứ đáng ghi. Không có quan hệ đó thì đừng.
04

Protocol

Ghi rõ cần object có phương thức gì, mà object đó không phải kế thừa từ đâu cả.

Interface kiểu Java

Lớp phải khai báo mình implement interface.

Không sửa được thư viện của người khác cho hợp interface của bạn.

Protocol trong Python

Chỉ cần có đúng phương thức là hợp lệ — duck typing nhưng checker hiểu được.

Áp được lên cả class có sẵn mà bạn không sửa được.

from typing import Protocol

class CóDiệnTích(Protocol):
    def diện_tích(self) -> float: ...

def tổng(xs: list[CóDiệnTích]) -> float:    # nhận mọi object có .diện_tích()
    return sum(x.diện_tích() for x in xs)
05

Dataclass

Một dòng decorator thay cho __init__, __repr__, __eq__ viết tay.

from dataclasses import dataclass, field

@dataclass(frozen=True)          # frozen → bất biến VÀ hashable
class Điểm:
    x: int
    y: int = 0
    nhãn: list[str] = field(default_factory=list)   # KHÔNG viết = []

Điểm(1, 2) == Điểm(1, 2)     # True — __eq__ được sinh sẵn
dataclass — mặc định nên dùngsửa được (trừ frozen) · truy cập p.x · làm khoá dict chỉ khi frozen=True · hợp khi có phương thức, có giá trị mặc định
NamedTuplebất biến · truy cập cả p.x lẫn p[0] · làm khoá dict được · hợp với bản ghi nhỏ, bất biến
dictsửa được · truy cập p["x"] · không làm khoá dict được · chỉ hợp khi khoá không biết trước
06

Tổng kết một hình

Type hint không chạy — nên mọi lựa chọn trong bài đều là chọn cho người đọc và công cụ đọc, không phải chọn cho máy thi hành.

  • pydantic — ở ①: cách duy nhất biến hint thành kiểm tra thật lúc chạy.
  • Generic — ở ③: chỉ dùng khi quan hệ giữa vào và ra mới là thứ đáng ghi.
  • Protocol — structural vs nominal — ở ③: duck typing nhưng checker hiểu được.
  • frozen=True — ở ④: thứ làm dataclass vừa bất biến vừa hashable, tức là dùng làm khoá dict được.
07

Lỗi hay gặp

Lỗi đầu tiên đến từ hiểu sai bản chất của type hint.

Tưởng hint là kiểm tra runtime

Python không chặn gì cả. Cần chặn thật thì dùng pydantic hoặc tự kiểm tra.

= [] trong dataclass

Python báo lỗi ngay vì mutable default. Dùng field(default_factory=list).

Generic phức tạp không ai đọc nổi

Hint tồn tại để dễ đọc hơn. Chú thích dài hơn thân hàm là đã đi quá xa — dùng alias hoặc đơn giản hoá.

08

Hỏi đáp

Tự nghĩ ra ý trả lời trước rồi mới mở — cốt là hiểu ý, không phải thuộc chữ.

Type hints có ảnh hưởng runtime không?

Không. Python bỏ qua chúng khi chạy. Chúng dành cho static checker, IDE và người đọc.

Protocol khác abstract base class ở đâu?

Protocol là structural: có đúng phương thức là hợp lệ, không cần kế thừa. ABC là nominal: phải kế thừa mới tính.

Dataclass hay NamedTuple?

NamedTuple cho bản ghi nhỏ, bất biến, cần dùng như tuple. Dataclass cho mọi trường hợp còn lại — sửa được và có phương thức.

Vì sao field(default_factory=list)?

Vì = [] tạo một list dùng chung cho mọi instance. Factory tạo list mới mỗi lần khởi tạo.
