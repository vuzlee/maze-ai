Python · typing

Type hints & dataclass

Hints are for tools and readers, not for the interpreter.

  • hints check nothing at runtime
  • Protocol is duck typing written down
  • dataclass generates __init__, __repr__, __eq__
01

Mental model

Three readers use a hint, and Python at runtime is not one of them.

  • Measured: add('x', 'y') with int hints still returns 'xy'; cost per call 25.9 ns vs 25.8 ns.
  • Hints are stored in __annotations__, so libraries can read them.
  • Real runtime checks need pydantic or typeguard.
02

Common syntax

A handful of forms cover most code. Any switches checking off — use it rarely.

2.1Container types

The checker looks inside the container.

list[int] · dict[str, int] · tuple[int, str] — built in since 3.9, no typing.List.

2.2Optional

int | None forces a None check before use.

Before Python 3.10: Optional[int].

2.3Callable

Describe a function parameter by what it takes and returns.

from collections.abc import Callable

2.4Generics

A TypeVar keeps the same type from input to output.

Python 3.12+: def first[T](xs: list[T]) -> T · classes: class Box(Generic[T]).

03

Protocol

ABC is nominal typing: declare the relationship. Protocol is structural typing: only the shape counts.

  • Use it for third-party classes you cannot change.
  • It is the duck typing of OOP in Python, made checkable.
04

Dataclass

Declare the fields, get four things a plain class writes by hand.

@dataclass(frozen=True) · tags: list[str] = field(default_factory=list)

  • Changing a field of a frozen dataclass raises FrozenInstanceError.
  • Never = [] as a default — use default_factory.
  • No runtime type checks — for input from APIs or files use pydantic.
