Python · first lesson of the shelf

Python overview

Python is names pointing at objects, run line by line by a C program — short, readable code on top, fast C libraries underneath. It is the language of ML and of most coding interviews.

01

What Python is

Python is names pointing at objects, a few built-in shapes to hold them, and a runtime that shares one interpreter. These ten pictures are the whole shelf.

  • The core band explains nearly every surprising bug: a shared list, a dict key that will not hash, an exception caught three frames up.
  • The run-time band is what interviews probe after the core: why threads do not speed up CPU work, when to reach for asyncio.
02

Life of a line

Every line is compiled to bytecode, run by a C loop, and leaves objects on the heap — that is what “interpreted, dynamically typed, garbage-collected” means.

  • Interpreted: CPython — the python3 you run — never turns your code into machine code, so a plain loop is slow; push hot loops into C libraries, see Performance & profiling.
  • Dynamically typed: the type lives on the object and is checked only when BINARY_OP runs; type hints document intent but are not enforced — see Type hints & dataclass.
  • Garbage-collected: an object no name points to is freed — see Memory management & GC.
03

Lineage

Python took readability from ABC and power from C, then won through the libraries built on top of it.

  • The 2008 break to Python 3 (text is Unicode, print is a function) took a decade to finish; all code you meet now is Python 3.
  • NumPy is why ML speaks Python: the language orchestrates, C and CUDA do the arithmetic — the road continues in the Machine learning shelf.
