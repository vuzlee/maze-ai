Memory management & GC

Python frees memory for you; you never call free().

  • reference counting does most of the work, at once
  • cyclic GC patches one gap: reference cycles
  • a leak in Python is code still holding a reference
01

Mental model

Each object counts the names pointing to it; at 0 it is freed on that line.

  • Builds on Memory model & mutability: names are tags on objects.
02

Reference counting

Every line adds or removes a name; the count follows.

  • del a removes the name, not the object; a = None does the same.
  • The price: every thread updates counts, which is one reason CPython has a GIL.
03

Reference cycle

Objects pointing at each other never reach 0 on their own.

  • Easy to create by accident: a tree whose children point back to the parent.
04

Cyclic GC

It cuts the links inside an unreachable cycle; counting then frees it.

  • Runs automatically; gc.collect() forces a run.
  • Scans only container objects, in three generations — young objects are checked most often.
05

Files, sockets and locks

GC frees memory; with closes resources on time.

Without with, use try / finally — never rely on __del__.

06

Memory leaks

A leak is a real reference the code forgot to drop.

6.1A cache that only grows

Stored objects keep refcount 1 forever.

Find it with tracemalloc; fix it with a size limit such as functools.lru_cache(maxsize=…).

6.2weakref

A weak reference does not count, so the object can still be freed.

weakref.WeakValueDictionary is a cache whose entries vanish with their objects.
