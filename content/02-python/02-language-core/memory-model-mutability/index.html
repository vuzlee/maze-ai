Memory model & mutability

Trong Python, biến không chứa giá trị — nó là một cái tên dán lên object. Hiểu đúng một câu đó xoá sạch cả một họ bug: gán tưởng là sao chép, sửa list trong hàm làm bẩn dữ liệu ngoài, đối số mặc định sống dai, và [[0]*3]*3 chỉ có một dòng thật.

Nhớ một câu

Gán không sao chép object, nó chỉ dán thêm một cái tên. Từ câu này suy ra được toàn bộ hành vi trong bài: vì sao b = a rồi sửa b lại đổi cả a, vì sao hàm sửa được list của người gọi, và vì sao x = 5 không bao giờ gây ra vấn đề đó.
02

Tên và object

a = [1, 2]
b = a              # KHÔNG sao chép — hai tên, một list
b.append(3)
a                  # [1, 2, 3]  ← a cũng đổi

id(a) == id(b)      # True — cùng một object

Có hai loại thao tác hoàn toàn khác nhau, và phân biệt được chúng là chìa khoá:

Gán lại tênSửa object
Cú phápb = [9]b.append(9), b[0] = 9, b += [9]
Ảnh hưởng tới các tên khácKhông — chỉ dán lại tên bCó — mọi tên trỏ tới object đó đều thấy
a = [1, 2]; b = a
b = [9]           # gán lại tên b → a vẫn là [1, 2]

a = [1, 2]; b = a
b[0] = 9          # sửa object   → a thành [9, 2]

Chỗ tinh vi nhất: +=

Với list, b += [9] gọi __iadd__ và sửa tại chỗ — giống extend. Với tuple hay số, b += x tạo object mới rồi gán lại tên. Cùng một toán tử, hai hành vi khác nhau tuỳ kiểu dữ liệu. Đây là nguồn bug rất khó thấy khi tái cấu trúc code.

is và ==

a = [1, 2]; b = [1, 2]
a == b             # True  — cùng giá trị

x = None

Vì sao None phải dùng is: None là một object duy nhất trong cả interpreter, nên so danh tính là chính xác và nhanh nhất. Còn == gọi __eq__, mà một class có thể định nghĩa __eq__ trả về True với mọi thứ — NumPy array thì arr == None còn trả về một mảng boolean, làm if ném lỗi.

04

Mutable hay không

Immutable — không sửa được nội dung

int float bool str bytes tuple frozenset None complex

Mutable — sửa được

list dict set bytearray, và phần lớn class tự viết

s = "abc"
s[0] = "x"         # TypeError — str là immutable
s = s.replace("a", "x")  # tạo chuỗi MỚI rồi gán lại tên

Đây chính là lý do nối chuỗi trong vòng lặp là O(n²): mỗi lần s += ch phải cấp phát một chuỗi mới và chép toàn bộ nội dung cũ sang.

Immutable không đồng nghĩa với "đóng băng hoàn toàn"

t = (1, [2, 3])       # tuple immutable...
t[1].append(4)      # ...nhưng list BÊN TRONG thì không
t                     # (1, [2, 3, 4])

hash(t)               # TypeError: unhashable — vì có list bên trong

Tuple đảm bảo danh sách các tham chiếu không đổi, không đảm bảo các object được trỏ tới cũng không đổi. Nói cách khác, immutable ở đây là nông.

Lab: theo dõi tham chiếu

Chạy từng dòng và xem tên nào trỏ tới object nào. Hai tên cùng màu là cùng một object.

Kịch bản nhân bản list là cái đáng chạy nhất: [[0]*3]*3 trông như ma trận 3×3 nhưng thực chất chỉ có một dòng, được trỏ tới ba lần. Sửa một ô là ba dòng cùng đổi.

Gán, shallow copy, deep copy

import copy
a = [[1, 2], [3, 4]]

b = a[:]                    # shallow

Khi nào deepcopy là sai lựa chọn

Nó chậm và tốn bộ nhớ, có thể lỗi với object không sao chép được (kết nối mở, khoá, socket), và nó sao chép cả những thứ bạn muốn dùng chung. Với dữ liệu lồng nhau, thường tốt hơn là thiết kế bất biến — dùng tuple, dataclass đóng băng, hoặc tạo object mới thay vì sửa tại chỗ.
07

Truyền tham số — không phải by value cũng không phải by reference

Python truyền theo cách gọi là pass by assignment: tham số trong hàm là một cái tên mới, được dán lên cùng object mà người gọi truyền vào.

def f1(lst):
    lst.append(4)       # SỬA object → người gọi thấy

def f2(lst):
    lst = [9, 9]        # GÁN LẠI tên cục bộ → người gọi KHÔNG thấy

a = [1, 2, 3]
f1(a); a              # [1, 2, 3, 4]
f2(a); a              # [1, 2, 3, 4] — không đổi thêm

Đây chính là hai loại thao tác ở mục 02, chỉ đặt trong ngữ cảnh hàm. Nếu là by value thì f1 không ảnh hưởng gì; nếu là by reference đúng nghĩa thì f2 phải đổi được biến của người gọi. Python không phải cả hai.

Quy tắc thực dụng khi viết hàm

Chọn một trong hai và ghi rõ vào tên hàm: trả về object mới (sorted(x), x.upper()) hoặc sửa tại chỗ và trả về None (x.sort(), x.append()). Thư viện chuẩn của Python tuân theo quy ước này rất nhất quán — hàm sửa tại chỗ không trả về gì, để bạn không viết được y = x.sort() rồi tưởng có bản mới.
08

Bốn cái bẫy

1. Đối số mặc định khả biến

def add(x, out=[]):       ← list này tạo MỘT LẦN, lúc định nghĩa hàm
    out.append(x)
    return out

add(1)                    # [1]
add(2)                    # [1, 2]  ← không phải [2]

def add(x, out=None):     # cách đúng
    if out is None: out = []
    out.append(x); return out

Giá trị mặc định được lượng giá một lần duy nhất khi hàm được định nghĩa, không phải mỗi lần gọi. Cùng nguyên nhân với bẫy lambda i=i ở bài decorator.

2. Nhân bản list lồng nhau

grid = [[0] * 3] * 3       # 3 tham chiếu tới CÙNG một dòng
grid[0][0] = 1
grid                      # [[1,0,0], [1,0,0], [1,0,0]]  ← cả ba đổi

grid = [[0] * 3 for _ in range(3)]   # đúng: mỗi dòng một list riêng

3. Sửa list trong lúc đang duyệt nó

a = [1, 2, 3, 4]
for x in a:
    if x % 2 == 0: a.remove(x)
a                         # [1, 3] có vẻ đúng, nhưng với [1,2,4,5] thì sai

a = [x for x in a if x % 2]     # tạo list mới — luôn an toàn

Xoá phần tử làm các chỉ số phía sau dịch lên, nên iterator nhảy qua một phần tử. Với dict và set thì Python thẳng thắn ném RuntimeError; với list thì nó âm thầm cho ra kết quả sai — nguy hiểm hơn.

4. Dùng object khả biến làm khoá

d = {}
k = [1, 2]
d[k] = "x"               # TypeError: unhashable type: 'list'
d[tuple(k)] = "x"        # được — tuple hashable

Python chặn từ đầu vì nếu khoá đổi giá trị sau khi lưu thì hash đổi theo, và dict sẽ đi tìm ở ô mới trong khi dữ liệu nằm ở ô cũ. Chi tiết đầy đủ nằm ở bài Python dict & hash table.

09

Đếm tham chiếu và bộ thu gom rác

import sys
a = [1, 2]
sys.getrefcount(a)     # 2 — một từ a, một từ đối số tạm của hàm này
b = a
sys.getrefcount(a)     # 3
del b
sys.getrefcount(a)     # 2

Cơ chế chính là đếm tham chiếu: mỗi object giữ một biến đếm, về 0 thì được giải phóng ngay lập tức. Đây là lý do Python giải phóng bộ nhớ rất kịp thời — và cũng là lý do có GIL, như đã nói ở bài trước.

Vấn đề chu trình

a = {}; b = {}
a["b"] = b
b["a"] = a          # trỏ vòng vào nhau
del a, b            # hai tên biến mất, nhưng mỗi dict vẫn còn 1 tham chiếu
                    # → đếm tham chiếu không bao giờ về 0

Vì vậy Python có thêm một bộ thu gom theo thế hệ chạy định kỳ để phát hiện những nhóm object chỉ còn trỏ lẫn nhau. Nó chỉ quét các object kiểu container, chạy theo ba thế hệ với tần suất giảm dần — object sống lâu thì bị quét ít hơn.

Khi nào chuyện này thành vấn đề thật

Với chương trình có nhiều object lồng nhau và vòng tham chiếu, lần chạy GC có thể gây ra khoảng dừng đáng chú ý. Dịch vụ độ trễ thấp đôi khi tắt GC tự động bằng gc.disable() rồi tự gọi gc.collect() vào lúc rảnh. Chỉ nên làm khi đã đo và thấy đúng nguyên nhân.
10

Interning — vì sao a is b có lúc True

a = 256; b = 256
a is b            # True  — int nhỏ được cache sẵn

a = 257; b = 257
a is b            # False trong REPL — hai object khác nhau

a = "hello"; b = "hello"
a is b            # True  — chuỗi giống định danh được intern

a = "hello world"; b = "hello world"
a is b            # thường False — có dấu cách nên không intern

CPython cache sẵn các số nguyên nhỏ từ −5 tới 256 và intern những chuỗi trông giống tên biến, để tiết kiệm bộ nhớ và tăng tốc so sánh. Đây là chi tiết cài đặt, không phải đặc tả ngôn ngữ.

Bài học duy nhất cần rút ra

Không bao giờ dùng is để so sánh giá trị. Nó có thể đúng trong lúc test rồi sai trên production, vì hành vi intern phụ thuộc phiên bản, phụ thuộc việc code nằm trong một hàm hay ở cấp module. Chỉ dùng is cho None, True, False và các sentinel do bạn tự tạo.
11

Bộ nhớ thật của object

import sys
sys.getsizeof(0)            # khoảng 28 byte — một int cũng là object đầy đủ
sys.getsizeof([])           # khoảng 56 byte cho list rỗng
sys.getsizeof([1,2,3])      # khoảng 88 — chỉ tính con trỏ, KHÔNG tính các int bên trong
sys.getsizeof({})           # khoảng 64 byte

getsizeof chỉ đo lớp ngoài. Một list một triệu số nguyên tốn khoảng 8 MB cho mảng con trỏ, cộng khoảng 28 MB cho các object int — tức khoảng 36 MB, so với 4 MB nếu dùng array hoặc NumPy. Đây là lý do NumPy tồn tại.

__slots__ — cắt bộ nhớ của object tự viết

class Point:
    def __init__(self, x, y): self.x, self.y = x, y
# mỗi instance có một __dict__ riêng: khoảng 100+ byte mỗi object

class PointSlim:
    __slots__ = ("x", "y")      # bỏ __dict__, lưu vào ô cố định
    def __init__(self, x, y): self.x, self.y = x, y
# tiết kiệm khoảng 40–50% bộ nhớ và truy cập thuộc tính nhanh hơn

Cái mất: không thêm được thuộc tính động, và kế thừa phức tạp hơn. Chỉ đáng dùng khi tạo hàng triệu instance — ví dụ node của cây, điểm dữ liệu, bản ghi trong bộ đệm.

Bốn quy tắc mang đi

  • Gán là dán tên, không phải sao chép. Cần bản độc lập thì nói rõ ra: list(a) cho một tầng, deepcopy cho mọi tầng.
  • Đừng bao giờ để giá trị mặc định là object khả biến. Dùng None rồi khởi tạo trong thân hàm.

  • is chỉ dành cho None và sentinel. Mọi so sánh giá trị dùng ==.

15

Hỏi đáp phỏng vấn

Python truyền tham số theo giá trị hay theo tham chiếu?

Cả hai đều không chính xác. Python truyền theo cách gọi là pass by assignment: tham số trong hàm là một tên mới được dán lên cùng object mà người gọi truyền vào. Nên nếu hàm sửa object khả biến thì người gọi thấy; nếu hàm gán lại tên đó thì người gọi không thấy. Đó là lý do lst.append(4) ảnh hưởng ra ngoài còn lst = [9] thì không.

Khác biệt giữa shallow copy và deep copy?

Shallow copy — a[:], list(a), copy.copy — tạo container mới nhưng các object bên trong vẫn dùng chung, nên sửa một list lồng bên trong vẫn ảnh hưởng bản gốc. Deep copy sao chép đệ quy toàn bộ nên hoàn toàn độc lập, đổi lại chậm hơn, tốn bộ nhớ hơn, và có thể lỗi với object không sao chép được như socket hay khoá. Với dữ liệu lồng nhau tôi thường ưu tiên thiết kế bất biến hơn là deepcopy.

Vì sao không nên dùng list làm giá trị mặc định của tham số?

Vì giá trị mặc định được lượng giá một lần duy nhất khi hàm được định nghĩa, không phải mỗi lần gọi. Nên mọi lần gọi đều dùng lại cùng một list và dữ liệu tích luỹ giữa các lần gọi — một bug rất khó tìm vì hàm trông hoàn toàn bình thường. Cách chuẩn là mặc định None rồi khởi tạo trong thân hàm.

is và == khác nhau thế nào, khi nào dùng is?

== so giá trị qua __eq__; is so danh tính, tức có phải cùng một object trong bộ nhớ. Chỉ dùng is cho None, True, False và sentinel do mình tạo — vì đó là những object duy nhất. Không dùng is để so số hay chuỗi: nó có thể trả về True nhờ interning của CPython nhưng đó là chi tiết cài đặt, thay đổi theo phiên bản và theo ngữ cảnh code.

Python quản lý bộ nhớ thế nào?

Cơ chế chính là đếm tham chiếu: mỗi object giữ số tham chiếu tới nó, về 0 thì giải phóng ngay. Ưu điểm là kịp thời và dự đoán được; nhược điểm là không xử lý được chu trình tham chiếu, và việc phải cập nhật bộ đếm an toàn chính là lý do có GIL. Nên Python có thêm bộ thu gom theo thế hệ chạy định kỳ để tìm các nhóm object chỉ còn trỏ lẫn nhau.

Service Python ăn RAM tăng dần — bạn tìm nguyên nhân thế nào?

Dùng tracemalloc: chụp ảnh bộ nhớ ở hai thời điểm rồi so sánh để biết dòng code nào đang cấp phát thêm. Bốn nghi phạm quen mặt là cache không giới hạn kích thước, lru_cache trên phương thức khiến instance không được giải phóng vì cache giữ self, biến toàn cục chỉ thêm mà không xoá, và callback đã đăng ký nhưng không huỷ. Với nhóm cuối thì weakref là cách chữa gọn.
