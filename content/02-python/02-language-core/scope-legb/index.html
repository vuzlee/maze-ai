Python · language core

Scope & LEGB

Where Python looks when you use a name.

  • reading searches four layers, inside out, and stops at the first hit
  • assigning always creates the name in the current layer
  • only functions, classes and modules create a scope
01

Mental model

Python looks up a name in L → E → G → B and stops at the first layer that has it.

  • L the running function · E enclosing functions · G the module · B built-ins.
  • Builds on Memory model & mutability: a name is a tag; scope says where tags are kept.
02

Reading a name

When several layers define a name, the nearest one wins.

That is why list = [1, 2] at module level breaks list(…) later: G hides B.

03

Writing a name

Assignment creates the name in the current layer; writing further out needs a declaration.

3.1Local by default

Any assignment in a function makes the name local for the whole function.

Reading before the assignment raises UnboundLocalError.

3.2global

global n sends reads and writes to the module.

Rarely a good idea: state that any function can change is hard to trace.

3.3nonlocal

nonlocal c writes to the enclosing function.

This is how closures and decorators keep state between calls.

04

What creates a scope

Functions, classes and modules do; loops and if do not.

4.1Loops and if

A loop variable lives on after the loop.

  • Unlike C or Java, a block does not end a variable's life.
  • Comprehensions do have their own scope: their loop variable does not leak.
  • A class body is not an enclosing layer for its methods.

4.2Late binding

Lambdas made in a loop all see the last value.

05

Arguments

A signature is a row of slots; each argument lands in exactly one.

Syntax: def g(a, b=2, *args, c, **kw) — when calling, * and ** unpack a list and a dict.
