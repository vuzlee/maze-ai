Iterator & generator

A for loop never reads a list directly.

  • an iterator holds a position, not data
  • so it can be walked exactly once
  • yield is the shortest way to write an iterator
01

Mental model

An iterator holds no data — only how to get the next item.

  • Has __iter__ → iterable; also has __next__ → iterator.
  • list, dict, str, range are iterables; generators and file objects are iterators.
02

The for loop

for is shorthand for iter(), then next() until StopIteration.

  • So anything with __iter__ works in a for loop.
03

Iterating twice

An iterable makes a new iterator each loop; an iterator has one pass — the second is silently empty.

  • Tests pass a list and work; production passes a generator and gets nothing.
  • Fix: items = list(items) on the first line of a function that loops twice.
04

Generator

Calling a generator function runs no code; each next() runs it to the next yield and pauses.

  • It keeps its place and local variables between calls.
  • Generator expression: (x * 2 for x in xs) — same thing, shorter.
05

The cost of laziness

Laziness saves memory but costs time when you loop more than once.

  • Generators have no len() and cannot be sliced.
06

yield from

Connect a sub-generator straight into the outer one instead of looping and re-yielding.

  • itertools holds ready-made lazy pipes: islice slices, chain joins, groupby groups.
  • groupby only groups adjacent items — sort first, unlike SQL GROUP BY.
