Decorator & context manager

Functions are values: you can reassign them, wrap them, and they remember.

  • @deco is just f = deco(f)
  • closures are the base: an inner function keeps the outer variables
  • with always runs the cleanup, even on an error
01

Mental model

No special syntax: @deco above def f means f = deco(f).

  • After wrapping, the name f points to wrapper; the original lives inside it.
  • wrapper(*args, **kwargs) accepts any arguments without knowing the original's.
02

Closure

An inner function keeps a reference to the outer variable, which survives after the outer function returns.

  • nonlocal is required to write to that cell; without it you get UnboundLocalError.
  • Reading only needs no nonlocal. More in Scope & LEGB — this is the E layer.
03

Writing decorators

Two things every real decorator needs.

3.1functools.wraps

Wrapping replaces the function — wraps copies back its name, docstring and signature.

@functools.wraps(fn) on the wrapper — treat it as mandatory.

  • The signature is what the function accepts; read it with inspect.signature(fn).

3.2Decorator with arguments

Three layers for three moments: the argument, the function, the call.

  • @repeat without parentheses is the classic bug: fn receives the function, not 3.
04

Context manager

with sets something up and always tears it down.

4.1__enter__ and __exit__

__exit__ runs even when the body raises.

  • Returning True from __exit__ swallows the error — rarely what you want.
  • Error flow in detail: Exception handling.

4.2@contextmanager

One generator function instead of a class: before yield = enter, finally = exit.

from contextlib import contextmanager
