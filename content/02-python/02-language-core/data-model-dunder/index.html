Python · language core

Data model & dunder

Python asks what methods an object has, not what type it is.

  • every piece of syntax calls a "dunder" (double-underscore) method
  • having the right method is enough — no inheritance needed
  • __eq__ without __hash__ breaks set and dict
01

Mental model

Syntax is a shortcut: unfamiliar syntax → look up its dunder.

  • That is why it is len(x), not x.len(): one syntax for every type.
  • Groups: comparison, arithmetic, containers, iteration, callables, context managers.
02

Duck typing

Has __len__ → len() works. No inheritance needed.

  • Libraries accept your object as long as it has the methods they call.
03

__repr__ and __str__

__repr__ is for developers, __str__ for readers; containers always use __repr__.

  • Give every class a __repr__ — debugging then shows values instead of addresses.
04

__eq__ and __hash__

Define __eq__ and Python sets __hash__ = None — define both or neither.

  • Equal objects must have equal hashes, or dict and set look in the wrong slot.
  • Define neither → objects compare by identity.
  • @dataclass(frozen=True) generates both — the safest option.
05

Keys must be immutable

An object changed after it went into a set cannot be found again — yet it is still there.

  • Use only immutable objects as dict keys and set items.
  • How slots and hashes work: Python dict & hash table.
