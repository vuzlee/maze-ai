Data model & dunder

Python không hỏi object thuộc kiểu gì, nó hỏi object có phương thức nào. Ba thứ cần nhớ:

  • mọi cú pháp là đường tắt gọi một dunder có tên cố định
  • có đúng phương thức là dùng được, không cần kế thừa ai
  • __eq__ mà quên __hash__ là hỏng set và dict
01

Cú pháp dịch thành lời gọi

Không cần thuộc hết. Cần nhớ đúng một điều: gặp cú pháp lạ thì đi tìm dunder tương ứng.

  • Vì sao len(x) chứ không phải x.len(): để mọi kiểu dùng chung một cú pháp.
  • Các tên này gom thành nhóm: so sánh, số học, chứa đựng, duyệt, gọi được, context manager.
  • Cài đúng vài dunder là object của bạn nhập vai được list hay dict — thư viện khác dùng nó như hàng thật.
02

Duck typing

Có __len__ thì len() chạy. Không cần kế thừa từ ai — đó là toàn bộ ý nghĩa của duck typing.

  • Đo thật: lớp có __len__ cho len() bằng 7, mà nó không phải list.
  • __repr__ dành cho lập trình viên, __str__ dành cho người đọc. Chỉ cài __repr__ thì str() dùng luôn nó.
  • Cài __repr__ cho mọi lớp của mình — lúc debug sẽ thấy giá trị thay vì địa chỉ.
03

__eq__ đi cùng __hash__

Đây là cặp duy nhất phá được mà không báo lỗi ngay. Định nghĩa __eq__ thì Python tự đặt __hash__ = None.

  • Quy tắc: hai object bằng nhau thì phải băm ra cùng một số. Nếu không, dict và set đi tìm nhầm ô.
  • Không định nghĩa gì thì so theo địa chỉ: hai object khác nhau luôn khác nhau.
  • @dataclass(frozen=True) sinh sẵn cả hai — cách an toàn nhất.
04

Khoá phải bất biến

Object đổi giá trị sau khi vào set thì tra không ra nữa — dù nó vẫn nằm trong đó.

  • Đo thật: m in S trả False, nhưng object vẫn nằm trong set (True).
  • Rác vô hình: tra không ra, xoá không được, nhưng vẫn chiếm chỗ.
  • Nên chỉ dùng object bất biến làm khoá dict hay phần tử set.
  • Cơ chế ô và hash xem ở Python dict & hash table.
