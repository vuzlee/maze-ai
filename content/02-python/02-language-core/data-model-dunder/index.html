Data model & dunder

Mọi cú pháp của Python đều là đường tắt gọi vào một phương thức có tên cố định. Biết bảng tên đó là đọc được mọi thư viện.

01

Mental model

Python không hỏi object thuộc kiểu gì. Nó hỏi object có phương thức nào.

Cả bài chỉ có ba ý, xếp theo đúng thứ tự dưới đây. Mỗi mục sau vẽ lại bản đồ này và tô sáng ô đang học.

len(x)        # → x.__len__()
x[0]         # → x.__getitem__(0)
a + b        # → a.__add__(b)
for i in x   # → iter(x) rồi __next__() tới khi StopIteration
with x       # → x.__enter__() … x.__exit__()
x()          # → x.__call__()
  • len(x) chứ không phải x.len() để có một cú pháp chung cho mọi kiểu.
  • Tự cài đúng vài dunder là object của bạn nhập vai được list, dict, hay số — thư viện khác dùng nó như hàng thật.
  • Đây chính là duck typing: có __len__ thì len() chạy, không cần kế thừa từ ai.

04

__eq__ và __hash__ đi cùng nhau

Hai object bằng nhau thì bắt buộc phải cùng hash. Phá luật này là dict và set hỏng im lặng.

Chuyện gì xảy ra

Định nghĩa __eq__ mà không định nghĩa __hash__.

Python đặt __hash__ = None → object hết hashable, cho vào set là lỗi ngay.

Tệ hơn: hash dựa trên trường sửa được → sửa xong tra không thấy nữa.

Cách viết đúng
class P:
    def __eq__(self, o):
        return (self.x, self.y) == (o.x, o.y)
    def __hash__(self):
        return hash((self.x, self.y))   # cùng bộ trường

Hoặc dùng @dataclass(frozen=True) — nó sinh cả hai cho bạn.

quy tắc: hash lấy từ đúng những trường mà eq dùngvà những trường đó không được sửa

05

Lỗi hay gặp

Bẫy thứ hai làm phần tử biến mất khỏi set mà không báo gì.

Định nghĩa __eq__ mà bỏ __hash__

Object thành không hashable. Cho vào set hoặc làm khoá dict là TypeError ngay.

Hash dựa trên trường sửa được

Chèn xong sửa trường đó → object nằm sai ô → tra mãi không thấy. Không lỗi, không cảnh báo.

Nhầm __str__ với __repr__

__str__ cho người đọc, __repr__ cho lập trình viên debug. Chỉ cài một cái thì cài __repr__ — str() sẽ tự dùng nó.

06

Hỏi đáp

Tự nghĩ ra ý trả lời trước rồi mới mở — cốt là hiểu ý, không phải thuộc chữ.

Vì sao len(x) chứ không phải x.len()?

Hàm dựng sẵn cho một cú pháp chung cho mọi kiểu, kể cả kiểu tự viết. Bên dưới nó vẫn gọi x.__len__().

Định nghĩa __eq__ thì phải làm gì nữa?

Định nghĩa __hash__ lấy từ đúng những trường mà __eq__ dùng. Bỏ qua thì object hết hashable.

__str__ khác __repr__ thế nào?

__str__ cho người dùng đọc, __repr__ cho lập trình viên — nên rõ ràng, lý tưởng là dựng lại được object. Chỉ cài một thì cài __repr__.

Làm sao để object của mình dùng được với for?

Cài __iter__ trả về một iterator, hoặc để nó là generator. Có __getitem__ nhận chỉ số từ 0 cũng chạy được.
