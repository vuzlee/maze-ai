List, tuple & set

Picking the type is about cost, not taste.

  • in scans a list but jumps straight to the slot in a set
  • adding to the front of a list shifts every cell
  • a key must be immutable so its hash stays stable
01

Mental model

Three containers, four questions: ordered, changeable, duplicates, hashable.

  • (1,) is a one-item tuple; {} is an empty dict, an empty set is set().
02

Membership test

x in list compares cell by cell; x in set hashes to the slot.

  • List is O(n), set is O(1) — the gap grows with n.
  • if x in some_list inside a loop is a sign to switch to a set.
03

Append vs insert

A list is one block of cells: append fills a free cell, insert(0) shifts them all.

  • Same reason: pop() is cheap, pop(0) is O(n).
  • Adding and removing at both ends? Use collections.deque.
04

Hashable keys

A tuple can be a key and a list cannot — hashable means unchangeable.

  • If a key changed, its hash would change while it sits in the old slot.
  • Use a tuple for a fixed record, a list for a sequence that grows.
05

Set

A set is a dict without values: same speed, same limits.

  • Items must be hashable, and a set keeps no order.
  • frozenset is an immutable set — usable as a dict key.
  • Slots and hashing: Python dict & hash table.
06

Set operations

Combine sets with one operator instead of a loop.

6.1Union

Items in either set.

a | b or a.union(b)

6.2Intersection

Items in both sets.

a & b or a.intersection(b)

6.3Difference

Items in the first set but not the second.

a - b; a ^ b gives items in exactly one set, {1, 4}.
