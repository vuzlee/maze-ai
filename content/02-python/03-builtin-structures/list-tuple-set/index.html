List, tuple & set

Chọn đúng kiểu là chuyện chi phí, không phải sở thích. Ba thứ cần nhớ:

  • in trên list là duyệt, trên set là tính thẳng ra chỗ
  • thêm vào đầu list phải dịch cả dãy
  • khoá phải bất biến thì hash mới ổn định
01

Tra thành viên

x in list so từng ô cho tới khi thấy. x in set tính hash ra số ô rồi nhảy thẳng tới.

  • Đo trên 100.000 phần tử: list 461 µs, set 15 ns — nhanh hơn 30.150 lần.
  • Khoảng cách còn giãn khi n lớn: list là O(n), set là O(1).
  • Thấy if x in danh_sach trong vòng lặp là dấu hiệu nên đổi sang set.
02

Thêm vào đầu hay cuối

List là một dãy ô liền nhau. Thêm vào cuối chỉ cần chỗ trống; thêm vào đầu thì mọi ô phải dịch một bậc.

  • Đo thật: append 12 ns, insert(0) 18.2 µs — chậm hơn 1.459 lần.
  • Cùng lý do: pop() rẻ, pop(0) đắt.
  • Cần thêm và bớt ở cả hai đầu thì dùng collections.deque.
03

Khoá phải bất biến

Tuple làm khoá được còn list thì không — vì băm được nghĩa là không đổi được.

  • Sửa được thì hash đổi, mà object vẫn nằm ô cũ — dict đi tìm nhầm ô.
  • Nhưng tuple chứa list thì lại không băm được: hash((1, [2])) ném TypeError.
  • Tuple nhẹ hơn list (120 so với 136 byte cho 10 phần tử) và tạo nhanh hơn 7 lần.
  • Quy ước: tuple cho bản ghi cố định, list cho dãy cùng loại có thể dài ra.
04

Set là hash table không giá trị

Set dùng đúng bộ máy của dict, chỉ bỏ đi cột giá trị — nên thừa hưởng cả ưu điểm lẫn ràng buộc.

  • Lọc trùng 2.000 phần tử: set 2.12 ms, còn vòng lặp với in list mất 10.9 ms.
  • Phép hợp, giao, hiệu viết thẳng bằng |, &, -.
  • Set không giữ thứ tự: set(['b','a','c','d']) ra ['d', 'a', 'c', 'b']. Từ 3.7 dict giữ thứ tự chèn, set thì không.
  • frozenset là set bất biến — dùng được làm khoá dict hay phần tử của set khác.
  • Cơ chế ô và hash xem ở Python dict & hash table.
